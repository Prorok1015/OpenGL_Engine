# EPIC-81: пространственные запросы (spatial queries)

**Issue:** #1325 · **Сторис:** #1326 (US-81-A, ядро), #1189 (пикинг в редакторе), #1327 (выбор рамкой), #1328 (shape casts) · **Связано:** #1324 (пикинг по ID-буферу)

## Зачем
Игре и редактору нужен один ответ на вопрос «что на этом луче». Раньше его не было: редактор выбирал объект по ID-буферу, у игры не было ничего. Теперь это запрос движка к миру, а редактор и игровой код пользуются им одинаково.

## Что в #1326
- `ds::bvh<T>` (core/common): обобщённое BVH по `ds::aabb3` — построение, `set_box` (refit за O(глубины)), `rebuild`, `degradation`, обход лучом, боксом, фрустумом. Не знает ни ECS, ни рендера.
- Чистая математика пересечений (`ds_intersect.hpp`): `ray_aabb`, `ray_triangle` (Мёллер–Трумбор), `frustum_from`/`test_frustum`.
- `ds::bit_flags` расширен (constexpr, `& | ^ ~`, `any_of/all_of`, `set/reset`, `raw/from_raw/all`); значения enum — номера битов.
- `scn::spatial_layer` (0..31), `scn::spatial_mask`, компонент движка `scn::spatial_layers` (нет компонента = слой 0).
- Типы-значения `ray`, `ray_filter` (`max_distance`, `mask`, `include_hidden`, `cull_back_faces`, `triangles`, `exclude`), `ray_hit` (entity, distance, point, normal, triangle, barycentric, back_face).
- `scn::spatial_backend` — закреплённый интерфейс (`spatial_backend_abi_revision`), `scn::spatial_world` в ctx реестра (backends объединяются), функции `raycast_closest/any/all`, `ray_from_screen`.
- Backend по мешам: BVH по треугольникам на каждый диапазон геометрии (позиции из элемента `position` типа VEC3_F; `geometry_desc::bounds` — это UV, не позиции) и BVH мира по боксам сущностей. Индексы относительно `vx_begin`.
- Refit ведёт система трансформаций: она сообщает `spatial_world::entities_moved` по сдвинутым сущностям и потомкам (новой системы нет: миры запускают только перечисленные системы). Структурные изменения ловятся по размеру view и проверкой устаревания при обходе. Пороги перестройки — именованные константы (доля сдвинутых 0.25, деградация 2.0).

## Что в PR 2 (сделано в той же ветке-стеке)
Асинхронный пакет запросов на job system: снимок мира принадлежит backend'у и берётся раз в кадр, результат несёт номер кадра, память кадрового аллокатора через кадр не живёт. Асинхронными бывают и `all`. Тест: снимок кадра N не видит движений кадра N+1.

## Границы
- скинированные меши проверяются в bind-позе;
- только загруженная геометрия (не готовая не попадается, пока не загрузится);
- только треугольники: коллайдеров и физики нет;
- `raycast_all` отдаёт один (ближайший) хит на сущность;
- матрица, записанная после системы трансформаций и не через `transform_updated`, видна в лучшем случае со следующего кадра.
- запрос по пирамиде видимости (#1327, `scn::overlap_frustum`) проверяет только мировые габариты сущностей (бокс меша через матрицу), не треугольники: объект, чей бокс касается пирамиды, попадает; проверка консервативная (по угловой точке бокса вдоль нормали каждой плоскости): может попасть и бокс чуть снаружи у ребра или угла пирамиды, но касающийся не пропускается; точный тест — отдельная история. `screen_rect_view_projection` углы к кадру не обрезает (редактор обрезает сам).

## Запрос по пирамиде (US-81-C, #1327)
`scn::overlap_frustum(world, view_projection, filter, out)` отдаёт сущности, чьи мировые боксы пересекают пирамиду матрицы вид-проекция (по порядку сущностей; маска слоёв, `include_hidden` и `exclude` фильтра работают как у луча). `scn::screen_rect_view_projection(view, projection, угол_a, угол_b, размер_кадра)` строит матрицу для прямоугольника на экране (пиксели, начало сверху слева, y вниз). Обход — `ds::bvh::query_frustum` по мировому дереву; новых значимых типов нет, `docs/abi/changes/1327.md`.

## Фигуры и запросы по точке (US-81-D, #1328)
Первая часть (математика, без ABI): `ds_shape.hpp` — `sphere3`, `capsule3`, `obb3`, их `bounds_of`, ближайшая точка треугольника, расстояние отрезок–отрезок и отрезок–треугольник, пересечения сферы, капсулы и ориентированного бокса с треугольником (бокс — по осям разделения), свип сферы по треугольнику (грань, рёбра-цилиндры, углы-сферы; `started_inside` при пересечении на старте); `ds::bvh::query_nearest` и `ds::distance_to_box` — обход от ближней точки с сужающимся пределом расстояния. Вторая часть (ABI, `docs/abi/changes/1328.md`, layout_revision 29): `scn::shape` (сфера, капсула, ориентированный бокс; `make_sphere/make_capsule/make_box`), `scn::point_hit`; `scn::overlap_shape` (сущности, у которых есть треугольник, пересекающий фигуру; широкая фаза по BVH мира, узкая — треугольники из BVH меша через матрицу сущности, так что растянутый меш не растягивает фигуру; меш больше миллиона треугольников отвечает боксами), `scn::overlap_point` (мировые габариты содержат точку, как пирамида — консервативно), `scn::closest_point` (ближайшая точка поверхности в радиусе `filter.max_distance`; при равных расстояниях — младшая сущность; нормаль — от точки поверхности к точке запроса, у точки на поверхности — лицевая нормаль). Фильтр как у луча: маска, `include_hidden`, `exclude`; `max_distance` — только у `closest_point`. Интерфейс бэкенда (приватный) получил те же три виртуальных метода. Третья часть (`docs/abi/changes/1328-casts.md`, layout_revision 31): `scn::shapecast(world, shape, direction, filter)` -> `scn::shape_hit` (сущность, расстояние, точка и нормаль касания, треугольник, `started_inside`): первое, чего касается сфера (точно: грань, рёбра-цилиндры, углы-сферы) или капсула (консервативное продвижение по расстоянию отрезок–треугольник: не перескакивает касание, останавливается в пределах 1e-4 радиуса от него; скользящее движение может быть пропущено) при движении вдоль направления; длина броска — `filter.max_distance` (по умолчанию не ограничена); мир, фильтры и порядок как у остальных запросов. Бокс-каст (GJK), бросок формы по большому мешу (больше миллиона треугольников) и async-пакет форм — отдельные stories. Критерий «бэкенд коллайдеров подключается через интерфейс US-81-A» закрыт расширением приватного интерфейса бэкенда (`overlap_shape`, `overlap_point`, `closest_point`, `shapecast`): коллайдеров в движке пока нет. Бокс-каст (GJK) и async-пакет форм — отдельные stories.
