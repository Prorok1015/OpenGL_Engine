# EPIC-83: Универсальная анимационная система — таймлайн для любых полей

**Theme:** runtime
**Status:** design (черновик к ревью ведущего и Fable; кода нет)
**Issue:** [#1471](https://github.com/Prorok1015/OpenGL_Engine/issues/1471) · **Истории:** #1472 (US-83-A), #1473 (US-83-B), #1474 (US-83-C), US-83-D, US-83-E
**Поглощает:** EPIC-74 (#50, UI Tweens)
**Depends on:** EPIC-82 (#1397, шаг (c) #1403 — override'ы материала у экземпляра), EPIC-67 (#42, UI Runtime) — только для tween'ов UI

> Метки: **[решение]** — решено владельцем, **[предложение]** — предложение автора, его нужно принять или заменить, **[вопрос]** — открытый вопрос.

## 1. Зачем

Сейчас в движке анимируется только одно: TRS узлов скелета из клипа модели. Tween'ов, кривых, событий на времени и анимации параметров материала нет. Карточной игре («Химера») нужны переворот и подсветка карты, растворение, движение элементов UI и звук в нужный момент анимации. EPIC-83 даёт одну систему для всего этого. Скелет переезжает на неё позже (US-83-C), без потери скорости.

## 2. Решения владельца

- **[решение]** Таймлайн → дорожки «адрес поля + ключи + интерполяция»; любое поле любого объекта (2026-11-26, #1471).
- **[решение]** Адрес — JSON pointer по схеме, как у override-записей префаба.
- **[решение]** Привязка один раз: в кадре только запись значения, без разбора строк. Скелет не медленнее текущего (замер до и после).
- **[решение]** Типы: float/vec/цвет — linear или кривая (ease, bezier); quat — slerp; bool, enum, ссылка — ступенька.
- **[решение]** Смешивание v1: «последний побеждает» + плавный переход между клипами одного объекта.
- **[решение]** Анимация пишет только рантайм-значения, сохранённые файлы не меняются; в редакторе — предпросмотр с откатом.
- **[решение]** События на таймлайне с самого начала.
- **[решение]** Типы, которые модули передают по значению, — в ключ раскладки; формат `.anim.desc` — ревью Fable.
- **[решение]** Tween — короткий таймлайн, созданный из кода; EPIC-74 поглощён.

- **Замеров анимации нет.** Ближайший — отключённый по умолчанию бенчмарк экстракции `tests/app_engine_null_backend_bench.cpp:19-36` (в nightly).
- **Tween/easing/bezier/кривых нет нигде.**
- **Адресация полей.** Override-запись префаба = `{target (путь node id), component (ключ или "transform"), path (JSON pointer), value, op}` (`scn_override_record.h:17-37`). Применяется через JSON: `json_pointer_set` поверх сериализованного desc, затем десериализация и спавнер (`scn_prefab_desc.cpp:889-1221`, `scn_ecs_assembler.cpp:58-91`). Схема описывает поля (`desc_schema.h:32-101`: виды f32, vec2-4, quat, color, bool, enumeration, res_tag…, ключ поля — pointer), для C++-типов `member_ops<T, Pointer>` держит указатель на член, но наружу даёт только JSON-операции (`desc_describe_ops.h:524-558`); `offset` заполнен лишь у рантайм-схем (`dyn_blob`). **API «pointer → типизированный setter» нет.**

- **Материал.** Параметры фиксированы: `albedo`, `emissive` (цвет), `shininess` (`/uniforms/*`, `rnd_material_desc.h:78-89,136-143`); свободной карты uniform'ов нет, `/uniforms/glow` сегодня не разрешится. Параметры упакованы в 48-байтный UBO на группу (`rnd_material_params.h:17-28`), группа создаётся один раз на набор байтов и не обновляется (`rnd_material_groups.cpp:99-130`). Пер-объектный блок — только `world` и `bone_offset` (`rnd_bindings.h:38-47`). Два объекта с одним материалом делят desc, компиляцию и bind group. **Пер-объектных значений материала нет**; #1403 (шаг (c) EPIC-82) — только дизайн: каждое изменение = свой inline-материал с `__parent`, общий по хешу содержимого, лимит 1024 разных.

## 4. Модель

- **Таймлайн** — ассет `.anim.desc` (тип `scn::timeline_desc`, §5): длительность, режим повтора, дорожки, события.
- **Дорожка** — адрес (§6) + тип значения + ключи. Ключ: время в секундах, значение, интерполяция сегмента до следующего ключа.
- **Проигрыватель** — компонент `scn::timeline_player` на объекте, который играет таймлайн(ы); дорожки адресуют сам объект или его потомков.
- **Привязка** — при старте клипа каждая дорожка превращается в `bound_track {slot, sampler}`; slot — «куда писать» без строк (§6.3). Ошибочный адрес → понятная ошибка, дорожка выключена, остальные играют.
- **Tween** — таймлайн из одной дорожки с двумя ключами, созданный кодом в памяти (§9).

## 5. Формат `.anim.desc`

**[предложение]** Тип `timeline_desc` (новый, чтобы не ломать `animation_clip_desc` до US-83-C), суффикс `.anim.desc`, вид ассета в редакторе `timeline_desc`.

```json
{
    "__type" : "timeline_desc",
    "__version" : 1,
    "duration" : 0.6,
    "wrap" : "once",
    "tracks" : [
        {
            "target" : ["9f1c2a7b3d4e5f60"],
            "component" : "transform",
            "path" : "/rotation",
            "type" : "quat",
            "times" : [0.0, 0.6],
            "values" : [[1, 0, 0, 0], [0, 0, 1, 0]],
            "interp" : ["slerp"]
        },
        {
            "target" : [],
            "component" : "material",
            "path" : "/uniforms/emissive",
            "type" : "color",
            "times" : [0.0, 0.3, 0.6],
            "values" : [[0, 0, 0, 1], [1, 0.8, 0.2, 1], [0, 0, 0, 1]],
            "interp" : [{ "bezier" : [0.42, 0, 0.58, 1] }, "ease_out"]
        }
    ],
    "events" : [
        { "time" : 0.3, "name" : "card_flip_sound" }
    ]
}
```

- **Адрес дорожки = три поля override-записи** `target` / `component` / `path` (§6), чтобы один и тот же адрес читался и проверялся одним кодом.
- `wrap`: `once` | `loop` | `ping_pong`. Время в секундах (не тиках).
- **Ключи — параллельные массивы** `times` / `values` / `interp` (SoA): компактнее в файле, сэмплер ищет по `times` без чтения значений; так же устроены дорожки glTF. `interp[i]` — сегмент `i → i+1` (длина `times - 1`); одна строка вместо массива = для всех сегментов.
- `interp`: `step`, `linear`, `slerp` (quat), `ease_in`, `ease_out`, `ease_in_out` (= именованные `bezier`), `{ "bezier": [x1, y1, x2, y2] }` (кубическая кривая времени, как CSS `cubic-bezier`: управляет темпом между двумя значениями). Касательные по значению (Hermite, `CUBICSPLINE` glTF) — **[вопрос]** нужно ли в v1; импорт glTF с ними в US-83-C можно запечь в linear с плотными ключами.
- **Проверки схемы** (ошибка с JSON pointer, как у `desc.create`): `type` из списка; длина каждого значения по типу; `times` строго возрастают, в `[0, duration]`; для `bool`, `enum`, `tag` разрешён только `step`; для `quat` — `slerp`/`step`/кривые темпа; события в `[0, duration]`.
- `type`: `float`, `vec2`, `vec3`, `vec4`, `color`, `quat`, `bool`, `int` (enum хранится как его строка в `values`, привязка переводит в число один раз), `tag` (ссылка на ассет строкой `res://`).
- Ссылки (`tag`) не держат хендлов в desc: значение — тег; при привязке все теги дорожки один раз запрашиваются через `res::resource_system::require`, в кадре пишется готовый хендл.
- **[вопрос]** имя события: строка, или строка + необязательное число/строка-параметр (`{ "time":0.3, "name":"sound", "arg":"res://sfx/flip.wav" }`)?

## 6. Адрес и привязка

### 6.1 Адрес
- `target` — путь node id от объекта с проигрывателем (пусто = сам объект), как `target` override-записи; ищется через `scn::node_index` (`scn_node_index.h:5-37`) или обходом `children_component` один раз при привязке.
- `component` — **[предложение]** имя из `component_catalog` (`scn.local_transform`…) **или** одно из псевдо-имён: `transform` (position/rotation/scale), `material` (параметры материала этого объекта, §7). Desc-имена (`camera_desc`) не годятся: живой компонент другого типа, связи «desc → компонент» нет.
- `path` — JSON pointer внутри схемы компонента (каталог уже даёт binding схемы).

### 6.2 Почему не через JSON override
Override-путь сериализует desc, правит JSON и пересоздаёт компонент спавнером — это сотни аллокаций и пересоздание GPU-состояния на каждое значение. Для кадра нужен прямой доступ.

### 6.3 Слоты
**[предложение]** Расширить `member_ops<T, Pointer>` (там уже есть указатель на член) типизированными функциями по виду поля: `write_f32(void*, float)`, `write_vec3(void*, const glm::vec3&)`, … и симметричными `read_*` (для отката предпросмотра и для старта tween'а «от текущего»). Вложенные структуры — цепочка указателей на члены, сворачивается при привязке в одну функцию через смещение внутри объекта.

```
struct field_slot {
    entt::basic_sparse_set* storage; entt::entity entity;   // компонент берётся storage->value(entity), без type_hash и строк
    value_kind kind;                                        // float, vec3, quat, ...
    void (*write)(void* component, const void* value);
    void (*read)(const void* component, void* value);
    after_write notify;                                     // none | transform | material (§6.4)
};
```

- Привязка: `component_catalog` по имени → `type_hash` → `registry.storage(id)`; схема компонента → поле по `path` (`find_field` + спуск по структуре) → его `field_ops`/typed-функции. Неизвестный компонент, нет такого компонента на объекте, нет поля, вид поля не совпал с `type` дорожки → `bind_error{track index, pointer, reason}`: лог раз и `Problems`, дорожка выключена.
- Сущность пропала (уничтожен потомок) → `storage->contains(entity)` проверяется перед записью (один поиск в sparse set, без строк); пропавшая дорожка выключается.
- Компоненты только на JSON (`dyn_blob` схемных компонентов) пишутся по `offset` рантайм-схемы — тот же `field_slot`.
- **[вопрос]** нужен ли `read` для всех видов уже в US-83-A, или только для tween «от текущего» (float/vec/color/quat).

### 6.4 Что делать после записи
- `transform` — псевдо-компонент. Живой трансформ — матрица, поэтому **[предложение]** при привязке на объект кладётся `animated_trs {position, rotation(quat), scale}` (разложение текущей `local` один раз); дорожки пишут в него, а в конце кадра системы одна сборка T*R*S на объект → `local_transform.set` + одно `transform_updated`. Так скелет не платит за сборку матрицы на каждую дорожку.
- `material` — §7.
- Остальные компоненты — без уведомления; если компоненту нужен флаг грязности, в его схеме это помечается атрибутом **[вопрос]**.

## 7. Параметры материала у одного объекта (US-83-B)

Требование: свечение одной карты не меняет другие с тем же материалом.

- **Через #1403 (instance-материалы) — не годится для анимации.** Каждое новое значение — новый inline-материал → компиляция, новый UBO и bind group, кеш до 1024 штук; 60 кадров плавного свечения = 60 разных материалов в секунду на объект. #1403 подходит для **статичного** override (переопределить цвет у экземпляра и сохранить), а не для значения, которое меняется каждый кадр.
- **[предложение] Свой путь — пер-объектный блок параметров.** Компонент `material_params_override {mask, albedo, emissive, shininess, extra}` на объекте; экстрактор кладёт его в пер-объектные данные рядом с `world` и `bone_offset` (`rnd_bindings.h:38-47`), шейдер берёт значение из блока объекта, если бит в `mask` стоит, иначе из UBO материала. Общий материал, его компиляция и bind group не трогаются; запись дорожки = запись в компонент, без GPU-аллокаций.
  - Цена: +48 байт на объект в пер-объектном буфере; правка `scene.frag`/общего include параметров; одна ветка по маске в шейдере.
  - Статичный override #1403 и анимация не конфликтуют: анимация пишет поверх итогового (instance-)материала.
- **Растворение** (`dissolve`) требует параметра, которого у `material_desc` нет. **[вопрос]** добавить в материал общий `params: vec4` (`/uniforms/params`) для шейдерных эффектов, или ждать свободных uniform'ов (#1441 — defines из слотов)? Пока US-83-B закрывает свечение через `emissive`; растворение — после решения.
- Адрес: `component: "material"`, `path: "/uniforms/albedo" | "/uniforms/emissive" | "/uniforms/shininess"` — те же pointer'ы, что у полей `material_desc`, проверяются по его схеме.

## 8. Tween'ы UI

- **Рантайм-UI нет** (только ImGui и `screen_anchor`). EPIC-67 (#42) не спроектирован.
- **[вопрос]** US-83-B: (а) отложить tween'ы UI до EPIC-67 и сделать в US-83-B только материал + общий API tween'а на любое поле (пример: `screen_anchor` offset и `transform`), или (б) ввести минимальный рантайм-компонент UI (позиция, поворот, масштаб, альфа) внутри EPIC-83. **Рекомендация: (а)** — tween уже работает для любого поля, UI-компоненты получат его бесплатно, когда появятся.
- «Отмена при смене экрана»: экрана нет; смена уровня уничтожает миры — проигрыватель и tween'ы как компоненты исчезают вместе с объектами. Явный `cancel_tweens(entity)` — в API (§9).

## 9. Проигрыватель, время, события, tween из кода

- **Компонент** `scn::timeline_player` (в ключе раскладки): до двух активных состояний клипа (текущий + уходящий при переходе), скорость, пауза. Состояние привязки — **[предложение]** за `std::shared_ptr<bound_timeline>` (непрозрачная структура движка), чтобы внутренности привязки менялись без ключа раскладки.
- **Система** `scn::timeline_system`, фаза `update` до `transform_system`; затем сборка TRS (§6.4). **[предложение] только Play** (`run_in_edit=false`): в Edit живые трансформы записываются в desc перед сохранением (`scene_editor::write_live_transforms_into`), и работающая в Edit анимация попала бы в файл уровня. Предпросмотр в редакторе — US-83-E: `read` всех слотов до старта, `write` обратно при остановке.
- **Время:** `scn::delta_time` × скорость; `once` — останов на конце и `scn::timeline_finished{entity, clip}`; `loop` переносит остаток (сейчас остаток теряется, :37); `ping_pong` — отражение.
- **Сэмплер:** в `bound_track` хранится индекс последнего сегмента; при монотонном времени следующий кадр проверяет тот же или следующий сегмент (O(1)), бинарный поиск только при прыжке.
- **События:** `scn::timeline_event{entity, name}` (тип в ключе раскладки, регистрируется в `layer.events()`), через `event_writer`; за кадр отдаются все пересечённые события по порядку, при переходе через конец цикла — и хвост, и начало. В Edit шина их сбрасывает — это ожидаемо.
- **Tween из кода** (экспортируемые функции `SNK_API`, не inline):
  ```
  scn::tween_id scn::tween(entt::registry&, entt::entity, std::string_view component, std::string_view path,
                           const tween_value& to, float duration, ease, std::optional<tween_value> from = {});
  void scn::cancel_tween(entt::registry&, entt::entity, scn::tween_id);
  void scn::cancel_tweens(entt::registry&, entt::entity);
  ```
  Создаёт таймлайн из одной дорожки в памяти (не ресурс), привязывает сразу (ошибка адреса возвращается из вызова), играет в том же проигрывателе. `from` по умолчанию — текущее значение (`read`). Второй tween на то же поле заменяет первый («последний побеждает»). Уничтожение объекта убирает проигрыватель вместе с tween'ами. `tween_value` — variant float/vec2/vec3/vec4/quat (передаётся по значению → в ключ раскладки).
- **Смешивание v1:** дорожки разных клипов одного проигрывателя на одно поле — пишет последний начатый. Переход `play(clip, blend_time)` держит уходящий клип и смешивает: float/vec/цвет — lerp, quat — slerp, ступенчатые типы переключаются в середине. Правила сверх этого — US-83-D.

## 10. Скелет (US-83-C) и скорость

Текущий узкий участок — поиски в кадре: обход родителей до корня, `try_get` на корне, поиск канала по строке, три бинарных поиска на узел; матрицы костей тоже ищут корень обходом (EPIC-48 :17-21). Новая модель убирает всё это привязкой: при старте клипа кость = `field_slot` в `animated_trs` нужной сущности, ключи без строк, курсор сегмента.

- **[предложение] Замер до любых изменений:** в PR 3 US-83-A добавить бенчмарк `anim_skeleton_bench` (выключен по умолчанию, как `app_engine_null_backend_bench`, и в nightly): модель с 60+ костями (`tests/data` или сгенерированная), N копий, время кадра систем анимации текущего пути. Тот же бенчмарк после US-83-C — критерий «не медленнее».
- Клипы импорта (`aiNodeAnim`) станут `.anim.desc` с дорожками `target`=путь к кости, `component: transform`, `path: /position|/rotation|/scale`; миграция `animation_collection_desc` → ссылки на `.anim.desc` — шаг US-83-C с миграцией EPIC-58.
- Формат дорожек должен выдерживать тысячи ключей на кость — поэтому SoA (§5) и, при росте, бинарный блок как у геометрии (`.anim.bin`, EPIC-79) — **[вопрос]** на US-83-C, не v1.

## 11. ABI и ключ раскладки

В `gs_module_layout_key.h` добавляются (каждый PR, который их вводит, поднимает `layout_revision` и пишет `docs/abi/changes/<issue>.md`):
- компоненты `scn::timeline_player`, `scn::animated_trs`, `rnd`/`scn::material_params_override` (+ `scn_engine_component_list.h`, каталог, тест `EngineComponentCatalog`);
- события `scn::timeline_event`, `scn::timeline_finished`;
- desc `scn::timeline_desc` и его элементы (дорожка, событие) — модуль может создать таймлайн сам;
- `scn::tween_value`, `scn::tween_id`, `scn::ease` (передаются по значению).
Не в ключе: `bound_timeline` и `field_slot` (за указателем, только движок). Функции tween и привязки — экспорт `SNK_API`.
Изменение пер-объектного блока рендера (§7) — внутреннее для движка, но меняет общий шейдерный include — отдельная запись в `docs/abi/changes` не нужна, если модули его не видят **[вопрос]** (модуль с собственным шейдером, включающим тот include, увидит).

## 12. Редактор и агенты

- US-83-A: вид ассета `.anim.desc` (`edt_builtin_asset_kinds.cpp`), открытие как data-документа (схемное окно уже умеет массивы); `desc.create/desc.write` агента работают по схеме без нового кода.
- Предпросмотр с откатом, окно таймлайна, выбор поля на объекте, кривые — US-83-E.
- Проблемы привязки — источник `anim` в Problems (Play).

## 13. Шаги (PR)

**US-83-A (#1472)**
1. **PR 1 — данные и сэмплер.** `timeline_desc` + схема + проверки (§5), сэмплеры (step/linear/slerp/bezier, ease-пресеты) — чистые функции, суффикс `.anim.desc` в редакторе, ключ раскладки + ABI-запись.
   Критерии: roundtrip; отказ на неверный тип/интерп/порядок времён с pointer'ом; значения кривых в контрольных точках.
2. **PR 2 — привязка.** Типизированные `write/read` в `member_ops`, `field_slot`, `bind_track` по каталогу компонентов, `animated_trs` + сборка TRS.
   Критерии: неверный компонент/поле/тип/цель → `bind_error` с понятным текстом, без падения; запись в слот меняет компонент; ни одной строки в цикле кадра (тест на счётчик вызовов `find_field` = 0 после привязки).
3. **PR 3 — проигрыватель, события, tween.** `timeline_player`, `timeline_system` (Play), wrap-режимы, `timeline_event`/`timeline_finished` до модуля (тестовая DLL), tween API, отмена при уничтожении; бенчмарк скелета (базовый замер, §10).
   Критерии: событие доходит до `subscribe` в модуле; tween отменяется при `destroy`; «анимация не меняет сохранённые файлы» — Play с анимацией, Stop, сохранение уровня = те же байты.

**US-83-B (#1473)**
4. **PR 4 — параметры материала объекта.** `material_params_override`, пер-объектный блок, шейдер, привязка `component: material`.
   Критерии: две карты с одним материалом, свечение одной — пиксели второй не меняются (headless-скриншот в CI, как `check_card.sh`); у общего материала ни одной перекомпиляции.
5. **PR 5 — пример в samples:** `card/` — подсветка и переворот как `.anim.desc`, скриншот в CI. Tween'ы UI — по ответу на §8.

**US-83-C..E** — отдельными дизайн-дополнениями к этому документу.
