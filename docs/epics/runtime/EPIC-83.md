## 1. Зачем

Сейчас в движке анимируется только одно: TRS узлов скелета из клипа модели. Tween'ов, кривых, событий на времени и анимации параметров материала нет. Карточной игре («Химера») нужны переворот и подсветка карты, растворение, движение элементов UI и звук в нужный момент анимации. EPIC-83 даёт одну систему для всего этого. Скелет переезжает на неё позже (US-83-C), без потери скорости.

## 2. Решения владельца

- **[решение]** Таймлайн → дорожки «адрес поля + ключи + интерполяция»; любое поле любого объекта (2026-11-26, #1471).
- **[решение]** Адрес — JSON pointer по схеме, как у override-записей префаба.
- **[решение]** Привязка один раз: в кадре только запись значения, без разбора строк. Скелет не медленнее текущего (замер до и после).
- **[решение]** Типы: float/vec/цвет — linear или кривая (ease, bezier); quat — slerp; bool, enum, ссылка — ступенька.
- **[решение]** Смешивание v1: «последний побеждает» + плавный переход между клипами одного объекта.
- **[решение]** Анимация пишет только рантайм-значения, сохранённые файлы не меняются; в редакторе — предпросмотр с откатом.
- **[решение]** События на таймлайне с самого начала.
- **[решение]** Типы, которые модули передают по значению, — в ключ раскладки; формат `.anim.desc` — ревью Fable.
- **[решение]** Tween — короткий таймлайн, созданный из кода; EPIC-74 поглощён.

## 4. Модель

- **Таймлайн** — ассет `.anim.desc` (тип `scn::timeline_desc`, §5): длительность, режим повтора, дорожки, события.
- **Дорожка** — адрес (§6.1) + тип значения + ключи. Ключ: время в секундах, значение, интерполяция сегмента до следующего ключа.
- **Проигрыватель** — компонент `scn::timeline_player` на объекте, который играет таймлайн(ы); дорожки адресуют сам объект или его потомков.
- **Привязка** — при старте клипа каждая дорожка превращается в `bound_track {slot, sampler}`; slot — «куда писать» без строк (§6.3). Привязка устаревает и делается заново по правилам §6.5.
- **Tween** — таймлайн из одной дорожки с двумя ключами, созданный кодом в памяти (§9.6).

## 5. Формат `.anim.desc`

**[предложение]** Тип `timeline_desc` (новый, чтобы не ломать `animation_clip_desc` до US-83-C), суффикс `.anim.desc`, вид ассета в редакторе `timeline_desc`.

```json
{
    "__type" : "timeline_desc",
    "__version" : 1,
    "duration" : 0.6,
    "wrap" : "once",
    "tracks" : [
        {
            "target" : ["9f1c2a7b3d4e5f60"],
            "component" : "transform",
            "path" : "/rotation",
            "type" : "quat",
            "times" : [0.0, 0.6],
            "values" : [1, 0, 0, 0,   0, 0, 1, 0],
            "interp" : ["slerp"]
        },
        {
            "target" : [],
            "component" : "material",
            "path" : "/uniforms/emissive",
            "type" : "color",
            "times" : [0.0, 0.3, 0.6],
            "values" : [0, 0, 0, 1,   1, 0.8, 0.2, 1,   0, 0, 0, 1],
            "interp" : [{ "bezier" : [0.42, 0, 0.58, 1] }, "ease_out"]
        },
        {
            "target" : [],
            "component" : "scn.mesh_node",
            "path" : "/material",
            "type" : "tag",
            "times" : [0.0, 0.3],
            "tags" : ["res://materials/card_front.mat.desc", "res://materials/card_back.mat.desc"]
        }
    ],
    "events" : [
        { "time" : 0.3, "name" : "card_flip", "arg" : "res://sfx/flip.desc" }
    ]
}
```

- **Адрес дорожки = три поля override-записи** `target` / `component` / `path` (§6.1), чтобы один и тот же адрес читался и проверялся одним кодом.
- `wrap`: `once` | `loop` | `ping_pong`. **Время — канонические секунды** (не тики).
- **Ключи — параллельные массивы**, у каждого массива **один тип в схеме** (правка ревью Fable): значение не зависит от соседнего поля `type`, поэтому строгая проверка тегов (#1445, #1465) и скан ссылок при rename/move (`asset.usages`, EPIC-57) работают без особого кода.
  - `times: [f32]` — строго возрастают, в `[0, duration]`.
  - `values: [f32]` — плоский массив со страйдом по `type`: `float`, `bool` (0/1) — 1; `vec2` — 2; `vec3` — 3; `vec4`, `color`, `quat` (w, x, y, z) — 4. Длина = `times × stride`.
  - `tags: [res_tag]` — для `type: tag`; длина = `times`.
  - `enums: [string]` — для `type: enum` (имя значения; в число переводится при привязке по схеме поля); длина = `times`.
  - У дорожки заполнен ровно один из `values` / `tags` / `enums`, соответствующий `type`.
- `interp[i]` — сегмент `i → i+1` (длина `times - 1`); одна строка вместо массива = для всех сегментов. Значения: `step`, `linear`, `slerp` (quat), `ease_in`, `ease_out`, `ease_in_out` (= именованные `bezier`), `{ "bezier": [x1, y1, x2, y2] }` — кубическая кривая **времени** (как CSS `cubic-bezier`), управляет темпом между двумя значениями.
- **[Fable] Hermite-касательных значений в v1 нет.** Импорт glTF `CUBICSPLINE` в US-83-C запекается в плотные linear-ключи.
- `type`: `float`, `vec2`, `vec3`, `vec4`, `color`, `quat`, `bool`, `enum`, `tag`.
- **Проверки схемы** (ошибка с JSON pointer, как у `desc.create`): длины массивов по `type`; порядок `times`; для `bool`, `enum`, `tag` разрешён только `step`; для `quat` — `slerp`/`step`/кривые темпа; события в `[0, duration]`.
- Теги не держат хендлов в desc: при привязке все теги дорожки один раз запрашиваются через `res::resource_system::require` (§6.3).
- **[Fable] Событие** = `name` + необязательный `arg: res_tag` (звук, эффект). Строковые/числовые аргументы — позже, по запросу.
- **Бинарные ключи** (`.anim.bin` рядом, как `.geom.bin` EPIC-79) — v1 только JSON; **решение по `.anim.bin` принимается до миграции US-83-C**, иначе импортированные клипы мигрируют дважды (JSON → JSON → bin).

## 6. Адрес и привязка

### 6.1 Адрес
- `target` — путь node id от объекта с проигрывателем (пусто = сам объект), как `target` override-записи; ищется через `scn::node_index` (`scn_node_index.h:5-37`) или обходом `children_component`.
- `component` — **[предложение]** имя из `component_catalog` (`scn.local_transform`, `scn.mesh_node`…) **или** псевдо-имя: `transform` (position/rotation/scale, §6.4), `material` (параметры материала этого объекта, §7). Desc-имена (`camera_desc`) не годятся: живой компонент другого типа, связи «desc → компонент» нет.
- `path` — JSON pointer внутри схемы компонента (каталог уже даёт binding схемы).
- **Ретаргетинга нет.** Адрес — путь node id, поэтому клип привязан к иерархии одной модели (одного префаба и его экземпляров). Общий клип для разных моделей (по именам узлов или костей) — вне v1; текущий скелет ищет по имени, переход на node id в US-83-C это сознательно сужает.

### 6.2 Почему не через JSON override
Override-путь сериализует desc, правит JSON и пересоздаёт компонент спавнером — это сотни аллокаций и пересоздание GPU-состояния на каждое значение. Для кадра нужен прямой доступ.

### 6.3 Слоты: запись по `kind + offset`, без кода модуля в кадре
Правка ревью Fable: никаких новых указателей на функции в `field_ops` — для компонента из модуля это был бы вызов через границу DLL каждый кадр и висячий указатель после перезагрузки кода модуля, а `desc::field_ops` в ключе раскладки (`gs_module_layout_key.h:135`).

- **[предложение]** Использовать существующее `field_ops::offset` (`desc_schema_ops.h:76`): `bind_described<T>` заполняет его для описанных C++-членов (смещение члена внутри `T`, вычисленное по указателю на член; для вложенных структур — сумма смещений по цепочке). **Раскладка `field_ops` не меняется**, меняется только то, что поле теперь заполнено и у C++-типов. Член, смещение которого нельзя получить (не standard-layout тип без экземпляра по умолчанию), помечается «не анимируется»; привязка к нему — понятная ошибка.
- **Непрерывные виды** (`f32`, `vec2-4`, `color`, `quat`, `bool` как байт) движок пишет сам: `memcpy` нужного размера по `component + offset`. Ни строки, ни кода модуля в кадре.
- **Ступенчатые виды** (`enum`, `tag`): значение меняется только на границе ключа. При привязке для каждого ключа заранее готовится значение, а запись делается существующим `field_ops::from_json`/`assign` **только в кадр, где сменился сегмент** — редко; в обычном кадре ступенчатая дорожка ничего не пишет. Для тегов хендлы запрашиваются при привязке и держатся в `bound_timeline`.
- Слот:
  ```
  struct field_slot {
      entt::basic_sparse_set* storage; entt::entity entity;   // компонент: storage->value(entity), без type_hash и строк
      value_kind kind; std::uint32_t offset;                   // запись по смещению для непрерывных видов
      const desc::field_ops* step_ops;                         // только enum/tag: на смене сегмента
      after_write notify;                                      // none | transform | material (§6.4, §7)
  };
  ```
- **Запись идёт мимо EnTT `patch`/`replace`**: прямой доступ к памяти компонента не будит `on_update`-наблюдателей (`module_context::observe(…, observed::update, …)`). Это сознательно: наблюдатели на каждый кадр анимации — та же цена, которой избегает привязка. Кому нужно знать — слушает `transform_updated` (трансформ) или события таймлайна.
- Ошибки привязки: неизвестный компонент, нет поля, вид поля не совпал с `type`, поле не анимируется → `bind_error{track, pointer, reason}`: лог раз и Problems (источник `anim`), **дорожка выключена навсегда** — это ошибка данных, повтор ничего не даст.

### 6.4 Трансформ: каналы с маской
- `transform` — псевдо-компонент: живой трансформ — матрица. При привязке на объект кладётся `scn::animated_trs {position, rotation(quat), scale, mask}`; дорожки пишут свои каналы, `mask` отмечает, какие каналы анимируются (по 3 бита: T, R, S).
- **Неанимированные каналы каждый кадр берутся из живой матрицы** (правка ревью Fable): перед сборкой система раскладывает текущий `local_transform` и подставляет из него каналы вне маски. Пример: игра двигает карту, пока анимация вращает её при перевороте — позиция остаётся игровой, вращение анимационное. Если маска полная — разложение пропускается.
- В конце фазы — одна сборка T*R*S на объект → запись в `local_transform` (мимо `patch`, §6.3) + одно `transform_updated`. Скелет не платит за сборку на каждую дорожку.
- **Ограничение разложения:** сдвиг (shear) теряется, отрицательный масштаб превращается в поворот + положительный масштаб (знак уходит в кватернион). Для узлов со сдвигом или зеркальным масштабом анимировать отдельные каналы нельзя корректно — только все три (маска полная, разложения нет). Это документируется в API.

### 6.5 Инвалидация и перепривязка
Правка ревью Fable: потерянная цель — не ошибка данных, дорожка не выключается.

- У `bound_timeline` есть **поколение привязки**; слоты считаются годными, пока оно совпадает с текущим. Поколение растёт, когда:
  - перезагружен desc таймлайна (hot reload `.anim.desc`);
  - выгружен или перезагружен слой игрового модуля (`context_manager::set_on_game_layer_change`): схемы и каталог компонентов модуля могли поменяться, смещения — тоже;
  - пересоздано поддерево цели (спавн/деспавн узлов под объектом с проигрывателем: хуки `node_index` construct/destroy помечают проигрыватели предков).
- Перед записью проверяется `storage->contains(entity)` (один поиск в sparse set). Нет сущности или компонента → дорожка в этом кадре пропускается, а адрес **разрешается заново** (не чаще раза в кадр на проигрыватель); нашлась — пишет дальше. Ошибкой (§6.3) это становится только если заново разрешённый адрес не проходит проверку схемы.
- **Копирование компонента** (дублирование узла, копия реестра для Play): копия `timeline_player` не делит `bound_timeline` с оригиналом — конструктор копирования сбрасывает указатель на привязку, копия привяжется сама на первом кадре (иначе она писала бы в сущности оригинала). Перемещение переносит привязку.
- Тесты перепривязки — в PR 2 (§13).

## 7. Параметры материала у одного объекта (US-83-B)

Требование: свечение одной карты не меняет другие с тем же материалом.

- **Через #1403 (instance-материалы) — не годится для анимации.** Каждое новое значение — новый inline-материал → компиляция, новый UBO и bind group, кеш до 1024 штук. #1403 остаётся для **статичного** override (переопределить цвет у экземпляра и сохранить).
- **[Fable] Пер-объектный блок из N общих vec4-слотов + маска** (а не именованные поля). Компонент `material_params_override {mask, vec4 slots[N]}`; экстрактор кладёт его в пер-объектные данные рядом с `world` и `bone_offset` (`rnd_bindings.h:38-47`). Слот `k` перекрывает `k`-й vec4 блока параметров материала (`rnd_material_params.h`: albedo — слот 0, emissive — 1, shininess и alpha cutoff (#1439) — 2); шейдер берёт vec4 из блока объекта, если бит `k` стоит, иначе из UBO материала.
  - Путь дорожки `/uniforms/emissive` переводится в номер слота и смещение внутри vec4 по раскладке параметров шейдера (`phong_params`) один раз при привязке.
  - **[Fable] `params: vec4`** — общий параметр эффектов (растворение, порог, фаза), добавляется в материал как ещё один слот блока (`/uniforms/params`), не отдельный механизм.
  - Общий материал, его компиляция и bind group не трогаются; запись дорожки = запись в компонент, без GPU-аллокаций.
  - Цена: `16 × N` байт на объект в пер-объектном буфере (N = 4 → 64 байта); правка общего include параметров и `scene.frag`/`mix_opaque_trans_scene.frag`; одна проверка маски на слот в шейдере.
  - Статичный override #1403 и анимация не конфликтуют: анимация пишет поверх итогового (instance-)материала.
- Адрес: `component: "material"`, `path: "/uniforms/albedo" | "/uniforms/emissive" | "/uniforms/shininess" | "/uniforms/params"`.

## 8. Tween'ы UI

- **Рантайм-UI нет** (только ImGui и `screen_anchor`). EPIC-67 (#42) не спроектирован.
- **[Fable] Отложить tween'ы UI до EPIC-67.** В US-83-B — только материал и общий API tween'а на любое поле (примеры: `screen_anchor` offset, `transform`). UI-компоненты получат tween без нового кода, когда появятся.
- «Отмена при смене экрана»: экрана нет; смена уровня уничтожает миры — проигрыватель и tween'ы как компоненты исчезают вместе с объектами. Явный `cancel_tweens(entity)` — в API (§9.6).

## 9. Проигрыватель, время, события

### 9.1 Компонент и система
- `scn::timeline_player` (в ключе раскладки): до двух активных состояний клипа (текущий + уходящий при переходе), скорость, пауза, флаги `unscaled` и `preview`. Привязка — за `std::shared_ptr<bound_timeline>` (непрозрачная структура движка, не в ключе); семантика копирования — §6.5.
- `scn::timeline_system`, фаза `update` до `transform_system`, затем сборка TRS (§6.4).
- **Edit и Play** (правка ревью Fable, вместо «только Play»): система регистрируется с `run_in_edit = true`, как сегодняшний скелет (`scn_animation_job.cpp:171-178`, ради превью). В Edit продвигаются **только проигрыватели с флагом `preview`** (их ставит предпросмотр редактора, US-83-E); остальные стоят.
- `scene_editor::write_live_transforms_into` **пропускает сущности с `animated_trs`**: анимированный трансформ никогда не попадает в сохранённый уровень (решение владельца «анимация не меняет файлы»). Предпросмотр перед стартом читает значения слотов и возвращает их при остановке.
- **Порядок проигрывателей стабилен** — по пути node id объекта, не по порядку пула EnTT: от него зависят «последний побеждает» между проигрывателями и порядок событий в кадре.

### 9.2 Время
- Источник — `scn::delta_time` (уже масштабирован и равен 0 в паузе). **Флаг `unscaled`**: проигрыватель берёт немасштабированное время кадра (UI-анимации в паузе игры). Для этого движок выдаёт в ctx `scn::unscaled_delta_time` (новый ctx-тип → в ключ раскладки) — **[вопрос]** имя и место (рядом с `delta_time` в `world_context::begin_frame`).
- Время клипа копится как `double`; **сэмпл зависит только от накопленного времени** (чистая функция `sample(track, t)`): при `deterministic_time` одинаковая история dt даёт одинаковые значения, без дрейфа от шага кадра.
- `once` — останов на конце + `scn::timeline_finished{entity, clip}`; `loop` переносит остаток (сегодняшний скелет его теряет, :37); `ping_pong` — отражение; отрицательная скорость — время идёт назад, `once` заканчивается на 0.
- **Сэмплер:** в `bound_track` хранится индекс последнего сегмента; при монотонном времени проверяется тот же или соседний сегмент (O(1)), бинарный поиск — только при прыжке.

### 9.3 События
- `scn::timeline_event{entity, clip, name, arg}` (тип в ключе раскладки, регистрируется в `layer.events()`), через `event_writer`; доставка — раз в кадр после фазы update.
- **Правила срабатывания** (правка ревью Fable):
  - событие срабатывает, когда время **пересекает** его метку в направлении проигрывания (вперёд при скорости > 0, назад при < 0 и на обратном ходе `ping_pong`);
  - `seek`/`set_time` событий **не** вызывают;
  - большой `dt`, пересекающий несколько циклов, отдаёт события **каждого прохода по порядку**, но не больше 4 проходов за кадр; остальные отбрасываются с предупреждением раз на проигрыватель;
  - событие на `t = 0` срабатывает ровно один раз при старте прохода, на `t = duration` — ровно один раз в конце прохода; на стыке циклов `loop` они не дублируют друг друга (стык — конец одного прохода и начало следующего, по одному разу);
  - в Edit шина события сбрасывает, превью тоже их не шлёт — звук и логика игры в редакторе не запускаются.

### 9.4 Смешивание v1
- Дорожки разных клипов одного проигрывателя на одно поле — пишет последний начатый. Между проигрывателями — последний по стабильному порядку (§9.1).
- Переход `play(clip, blend_time)` держит уходящий клип и смешивает: float/vec/цвет — lerp, quat — slerp, ступенчатые типы переключаются в середине перехода. Правила сверх этого — US-83-D.

### 9.5 Потоки
- `tween`, `cancel_*`, `play`, `seek` — **только из главного потока**: проверка `ASSERT_MSG` на id главного потока в каждой функции.

### 9.6 Tween из кода
Экспортируемые функции `SNK_API` (не inline):
```
scn::tween_id scn::tween(entt::registry&, entt::entity, std::string_view component, std::string_view path,
                         const tween_value& to, float duration, ease, std::optional<tween_value> from = {});
void scn::cancel_tween(entt::registry&, entt::entity, scn::tween_id);
void scn::cancel_tweens(entt::registry&, entt::entity);
```
Создаёт таймлайн из одной дорожки в памяти (не ресурс), привязывает сразу (ошибка адреса возвращается из вызова), играет в том же проигрывателе. `from` по умолчанию — текущее значение (чтение по слоту). Второй tween на то же поле заменяет первый. Уничтожение объекта убирает проигрыватель вместе с tween'ами. `tween_value` — variant float/vec2/vec3/vec4/quat (по значению → в ключ раскладки).

## 10. Скелет (US-83-C) и скорость

Текущий узкий участок — поиски в кадре: обход родителей до корня, `try_get` на корне, поиск канала по строке, три бинарных поиска на узел; матрицы костей тоже ищут корень обходом (EPIC-48 :17-21). Новая модель убирает это привязкой: кость = слот в `animated_trs` нужной сущности (маска полная — без разложения), ключи без строк, курсор сегмента.

- **[предложение] Замер до любых изменений:** в PR 3 US-83-A — бенчмарк `anim_skeleton_bench` (выключен по умолчанию, как `app_engine_null_backend_bench`, и в nightly): модель с 60+ костями, N копий, время кадра систем анимации текущего пути. Тот же бенчмарк после US-83-C — критерий «не медленнее».
- **Импорт:** время ключа = `ticks / ticks_per_second`, считается в `double` и записывается в `f32` секунд; соседние ключи с одинаковым временем после округления сливаются (последний побеждает) — так, чтобы `times` строго возрастали.
- Клипы импорта (`aiNodeAnim`) станут `.anim.desc` с дорожками `target` = путь node id кости, `component: transform`, `path: /position | /rotation | /scale`; миграция `animation_collection_desc` → ссылки на `.anim.desc` — шаг US-83-C (EPIC-58). Решение по `.anim.bin` — до неё (§5).

## 11. ABI и ключ раскладки

Каждый PR, который меняет ключ, берёт следующий `layout_revision` относительно main на момент push и пишет `docs/abi/changes/<issue>.md`.
- **Новые компоненты:** `scn::timeline_player`, `scn::animated_trs`, `scn::material_params_override` (+ `scn_engine_component_list.h`, каталог, тест `EngineComponentCatalog`).
- **События и ctx:** `scn::timeline_event`, `scn::timeline_finished`, `scn::unscaled_delta_time`.
- **Desc и элементы:** `scn::timeline_desc`, дорожка, событие.
- **По значению:** `scn::tween_value`, `scn::tween_id`, `scn::ease`.
- **`desc::field_ops`** (уже в ключе, :135): **раскладка не меняется** — меняется только то, что `offset` заполнен у C++-членов (§6.3). Новых указателей на функции нет; запись ABI в PR 2 это фиксирует («no type changes to field_ops: the layout key stays; offset now filled for described members»).
- **Не в ключе:** `bound_timeline`, `field_slot` — за указателем, только движок. Функции tween и привязки — экспорт `SNK_API`.
- Пер-объектный блок рендера (§7) и общий include параметров меняют контракт шейдеров: модуль со своим шейдером, включающим этот include, увидит новые слоты. **[вопрос]** нужна ли запись в `docs/abi/changes` для шейдерного контракта, или он вне ABI модуля.

## 13. Шаги (PR)

**US-83-A (#1472)**
1. **PR 1 — данные и сэмплер.** `timeline_desc` + схема + проверки (§5), сэмплеры (step/linear/slerp/bezier, ease-пресеты) — чистые функции, суффикс `.anim.desc` в редакторе, ключ раскладки + ABI-запись.
   Критерии: roundtrip; отказ на неверный тип/интерп/порядок/длину массивов с pointer'ом; теги дорожки проходят строгую проверку тегов и находятся `asset.usages`; значения кривых в контрольных точках.
2. **PR 2 — привязка.** `field_ops::offset` для C++-членов, `field_slot`, `bind_track` по каталогу компонентов, `animated_trs` с маской и сборкой TRS, поколение привязки и перепривязка (§6.5).
   Критерии: неверный компонент/поле/тип/цель → `bind_error` с понятным текстом, без падения; запись по слоту меняет компонент и не будит `on_update`; в цикле кадра ноль поисков по строке (счётчик вызовов `find_field` = 0 после привязки); **перепривязка:** удалённый и заново заспавненный узел снова анимируется; перезагрузка `.anim.desc` и смена слоя модуля перепривязывают; копия проигрывателя не пишет в сущности оригинала; анимация вращения не трогает позицию, которую двигает игра.
3. **PR 3 — проигрыватель, события, tween.** `timeline_player`, `timeline_system` (Edit — только `preview`), wrap-режимы, `unscaled`, события по правилам §9.3, `timeline_finished` до модуля (тестовая DLL), tween API с проверкой главного потока, отмена при уничтожении, пропуск `animated_trs` в `write_live_transforms_into`; бенчмарк скелета (базовый замер, §10).
   Критерии: событие доходит до `subscribe` в модуле; события на 0 и `duration` ровно раз за проход; `seek` событий не шлёт; большой dt — до 4 проходов; одинаковая история dt → одинаковые значения; tween отменяется при `destroy`; Play с анимацией, Stop, сохранение уровня = те же байты; сохранение в Edit при работающем превью = те же байты.

**US-83-B (#1473)**
4. **PR 4 — параметры материала объекта.** `material_params_override` (N vec4 + маска), пер-объектный блок, шейдеры, `params: vec4` в материале, привязка `component: material`.
   Критерии: две карты с одним материалом, свечение одной — пиксели второй не меняются (headless-скриншот в CI, как `check_card.sh`); у общего материала ни одной перекомпиляции.
5. **PR 5 — пример в samples:** `card/` — подсветка и переворот как `.anim.desc`, скриншот в CI.

**US-83-C..E** — отдельными дизайн-дополнениями к этому документу.
