# EPIC-60: Автосохранение и восстановление несохранённых документов

**Theme:** editor
**Status:** in_progress (#1186 — автосохранение; #1187 — восстановление после сбоя; #1188 — дальше)
**Issue:** #32
**Stories:** #1186 (автосохранение в `cache://autosave/`), #1187 (восстановление после сбоя), #1188 (следующий шаг после восстановления)

---

## 1. Зачем

Редактор держит правки в памяти до Save. Падение процесса, зависшая видеокарта или убитый процесс теряют всё, что не было сохранено. Автосохранение раз в несколько секунд-минут пишет копию несохранённого документа рядом с проектом — не поверх исходного файла — чтобы после сбоя её можно было предложить восстановить (#1187).

## 2. Что делает автосохранение (#1186)

- **Какие документы:** все открытые документы с несохранёнными правками (`is_dirty()`), обход через `document_manager::for_each`: уровень (`scene`), префаб (`prefab`), документ данных (`data`), меш (`mesh`). Документ, который сейчас нельзя менять (`edits_locked()`, Play), пропускается.
- **Что пишется:** ровно те байты, которые записал бы Save для текущего состояния (интерфейс `edt::autosave_source`, внутренний для редактора, не часть `edt::document`):
  - уровень — `level_controller::level_file_json` (та же функция, что у Save) над **копией** миров, в которую перенесены трансформы из ECS; документ, его история и `rebase_history` не трогаются. Безымянный уровень пишется как `untitled`;
  - префаб — `prefab_file_bytes` рабочей копии (форма Apply);
  - документ данных — `data_document::save_bytes()` (проверка, `stamp_tree`, ссылки как в файле, без записи);
  - меш — текст `x.poly.desc` (`mesh::poly_file_text`); пара геометрии выводится из него и не пишется.
- **Когда:** отсчёт документа начинается с его первой несохранённой правки; через `interval` секунд (по умолчанию 60) пишется копия. Если в этот момент идёт жест человека (активный элемент ImGui, перетаскивание гизмо, незакоммиченное поле инспектора — `editor_system::person_is_editing`), запись ждёт и делается сразу после конца жеста. Отдельного таймера простоя нет. После записи следующая — через `interval` после следующей правки (смены `generation()`); без правок повторной записи нет.
- **Документ, который сейчас нельзя записать** (недопустимое значение в документе данных, вариант префаба без разрешимой базы) пропускается строкой `egLOG_DEBUG` с именем документа и причиной; снова — только после следующей правки. Такой пропуск и неудачная запись — предупреждение в Problems (источник `autosave`, «<документ> is not autosaved: <причина>»); строка уходит, когда документ записан, чист или закрыт.
- **Как пишется:** снимок берётся на главном потоке; печать JSON уровня, хеш исходного файла и запись идут задачей `job_service` на линии io. Каждый файл — во временный файл рядом и переименованием поверх, все папки открываются без следования по ссылкам (`platform::beneath`, как запись `resource_system` в #414/#1294). Исходный файл и `is_dirty()` документа не меняются.
- **Когда файлы удаляются:** документ стал чистым (Save, Discard = `mark_clean`, Revert); документ закрыт (`document_closed`); у документа сменился источник (загружен другой уровень, Save As); сменилась папка кеша проекта (файлы удаляются из той папки, куда были записаны, даже если запись ещё шла, вместе с папкой сессии); автосохранение выключено (настройка или cfg); чистый выход из редактора (`~editor_system`: дожидается идущей записи, не начатые отменяет, затем удаляет всю папку своей сессии). После сбоя файлы остаются — это материал для восстановления (раздел 6).
- **Без проекта** (нет монтирования `cache://`) автосохранение выключено, одна строка в лог (INFO, `editor/autosave`).

## 3. Настройки

Личные настройки человека, не проекта: `edt://settings/autosave.json`

```json
{ "enabled": true, "interval_seconds": 60 }
```

- `interval_seconds` — от 5 до 86400 (вне диапазона прижимается к границе); неизвестный ключ или неверный тип — предупреждение и значения по умолчанию.
- cfg `editor/autosave` (по умолчанию `true`): `false` выключает автосохранение на этот запуск, что бы ни было в файле (CI, тесты).
- Edit > Editor Settings..., раздел **Autosave**: флажок и интервал, сохраняются в тот же JSON.

## 4. Файлы на диске (формат 2)

Папка: `<проект>/.cache/autosave/` (корень монтирования `cache://`). У каждого запуска редактора — своя папка сессии (#1187):

| Файл | Содержимое |
|---|---|
| `autosave/<session>/session.lock` | файл блокировки сессии: запущенный редактор держит на нём исключительную блокировку ОС (`platform::file_lock`: POSIX `flock`, Windows `LockFileEx`), которую система снимает при смерти процесса |
| `autosave/<session>/session.json` | кто владелец сессии (ниже) |
| `autosave/<session>/<kind>/<name>` | байты документа, как их записал бы Save |
| `autosave/<session>/<kind>/<name>.autosave.json` | мета-файл (ниже) |

`<session>` — 32 строчные шестнадцатеричные цифры (случайный идентификатор запуска, 128 бит). `<kind>` — `document::kind()` (`scene`, `prefab`, `data`, `mesh`). `<name>` — путь источника внутри `res://` (для другого протокола — весь тег), сведённый в одно имя файла: `/` → `%2F`, `%` → `%25`, а также `\ : < > | ? * "` и управляющие символы — `%XX`; ведущая точка — `%2E`; имя длиннее 160 байт — хвост пути (обрезанный по границе символа UTF-8 и `%XX`) + `~` + FNV-1a 64 полного пути, так что два длинных имени не совпадают. Безымянный документ — `untitled`. Пример: `res://levels/arena.level.desc` → `autosave/<session>/scene/levels%2Farena.level.desc`.

**Начало сессии** (до первой записи, как только известна папка кеша и автосохранение включено): папки формата 1 прямо под `autosave/` с именем вида (`scene`, `prefab`, `data`, `mesh`) удаляются (формат не выпускался, это наши файлы); другие имена не трогаются. Затем `autosave/<id>` создаётся как новая папка (`make_folders_beneath(..., must_be_new)`); если она уже есть — берётся новый случайный id (до 8 попыток). Затем берётся блокировка `session.lock` и пишется `session.json`. Если блокировку держит другой (`held`) или файл блокировки исчез (`missing`), папку занял другой редактор: в ней ничего не трогается, берётся новый id и всё повторяется (те же 8 попыток). Если блокировку взять нельзя (`unsupported`/`failed`: файловая система без блокировок, ошибка) — одно предупреждение, автосохранение работает, а `session.json` говорит `"locked": false`, чтобы другие редакторы не судили о сессии по её блокировке.

**Чистый выход:** свои записи удаляются, затем `session.json`, затем вся папка сессии (`remove_tree_beneath`) — пока блокировка ещё держится; только если удалить не удалось, блокировка отпускается и удаление повторяется один раз. Ничего не остаётся.

```json
{
  "format": 2,
  "session": "<32 hex>",
  "host": "workstation-12",
  "pid": 4242,
  "started_at": "2026-11-24T09:00:00Z",
  "locked": true
}
```

Порядок записи: сначала файл данных (временный файл, fsync, переименование), потом мета-файл (так же). Удаление — в обратном порядке: сначала мета, потом данные. Мета никогда не указывает на отсутствующий файл данных; файл данных без меты — мусор, который читатель игнорирует. Запись, начатая до смены папки кеша, удаляется из той папки, куда она легла.

```json
{
  "format": 2,
  "source": "levels/arena.level.desc",
  "kind": "scene",
  "generation": 42,
  "saved_at": "2026-11-24T10:15:00Z",
  "session": "<32 hex>",
  "host": "workstation-12",
  "payload_size": 20511,
  "payload_sha256": "<64 hex>",
  "source_size": 18342,
  "source_sha256": "<64 hex>"
}
```

| Поле | Смысл |
|---|---|
| `format` | версия формата, сейчас `2` (формат 1 = без `host` и без папки сессии); читатель другой версии запись отвергает |
| `source` | путь источника внутри `res://` (весь тег для другого протокола); пусто для безымянного документа |
| `kind` | вид документа (`scene`, `prefab`, `data`, `mesh`) |
| `generation` | `document::generation()` записанного состояния |
| `saved_at` | время записи, UTC, ISO-8601 |
| `session` | идентификатор запуска редактора = имя папки сессии |
| `host` | имя машины, на которой работал редактор (UTF-8, не длиннее 255 байт) |
| `payload_size`, `payload_sha256` | размер и SHA-256 байтов, записанных в файл данных вместе с этой метой |
| `source_size`, `source_sha256` | исходный файл на диске в момент записи (необязательны: нет у безымянного, у недоступного и у файла больше 256 МиБ). По ним восстановление видит, что источник изменился после автосохранения |

## 6. Восстановление после сбоя (#1187)

**Issue:** #1187 (US-60-B).

### Когда и где

После того как стартовый уровень загрузился и устоялся (то же условие, что у вопроса об откате миграции: `migration_component::start_level_settled`), `autosave_recovery` (создаётся в `editor_system::init` после автосохранения) запускает сканирование задачей `job_service` на линии io — никогда на главном потоке. Результат применяется на главном потоке. Без проекта (нет `cache://`) ничего не делается.

### Живость сессии

Сканер перечисляет `autosave/` (`list_beneath`) и берёт только папки (не ссылки) с именем ровно из 32 строчных hex-цифр, кроме своей. Для каждой:

1. Читается `session.json` (`read_beneath`, не больше 64 КиБ).
2. Проба `file_lock::acquire(..., "autosave/<s>/session.lock", existing_only)`:
   - `held` — **LIVE**: тот редактор работает; сессия пропускается целиком, ничего не трогается;
   - `acquired` — **DEAD**: тот редактор мёртв (но если `session.json` нет, а папка моложе 5 минут — это редактор между блокировкой и записью `session.json`: **STARTING**, блокировка отпускается, пропуск); сканер **держит** эту блокировку, пока на вопрос не ответили и Restore/Discard не закончились, и удаляет папку только держа её;
   - `unsupported` / `failed` — **UNVERIFIABLE**;
   - `missing` — если папка сессии моложе 5 минут, это редактор, который только стартует (**STARTING**, пропуск; время записи папки в будущем — не «молодая»; время, которое не удалось прочитать, — «молодая», то есть пропуск); иначе `acquire(..., create)`: `acquired` — DEAD (держится), `held` — LIVE (её держит другой сканер), иначе UNVERIFIABLE.
3. `session.json` с `"locked": false` или с `host`, не равным имени этой машины, — **UNVERIFIABLE** при любом исходе пробы, кроме `held` (по блокировке такую сессию не судят).

Два сканера на одной мёртвой сессии: второй видит её LIVE (блокировку держит первый) и ничего не предлагает.

### Проверка записей

Только у DEAD и UNVERIFIABLE сессий: папки известных видов (только папки) и их файлы; мета — `<имя файла данных>.autosave.json`. Для каждой меты (не больше 256 на сессию, остальные считаются «не проверены»):

- мета — обычный файл (не ссылка), не больше 64 КиБ, формат 2;
- `meta.session` = имя папки сессии; `meta.kind` = имя папки вида и известный вид;
- `source` пуст только у безымянного уровня, иначе — путь внутри `res://` в той форме, что пишет `autosave_source_text` (без протокола, без `.`/`..`, `\`, `:` и управляющих символов);
- имя файла данных = последнее имя `autosave_file_of(session, kind, source)` (точно);
- файл данных читается с `max_bytes = min(payload_size, 256 МиБ)`, размер и SHA-256 совпадают с метой.

На одно сканирование читается не больше 512 МиБ файлов данных; сверх — записи не читаются и считаются «не проверены (лимит)». Принятые записи держат проверенные байты в памяти: восстановление использует ровно их, без повторного чтения. Судятся (проба блокировки) все папки сессий; записи читаются не больше чем у 64 сессий DEAD и UNVERIFIABLE, остальные такие сессии называются числом в тексте вопроса (LIVE и STARTING в лимит не входят).

Отвергнутая запись — предупреждение в лог (строки из файлов экранированы), в вопросе — счётчик; восстановить её нельзя, удаляет её только Discard all своей сессии.

Папка сессии, которую не удалось перечислить целиком (ошибка листинга самой папки или папки вида, больше записей, чем читается), считается **прочитанной не полностью**: это пишется в вопросе, такая папка никогда не удаляется — ни как пустая, ни после Restore all, ни по Discard all (он удаляет только прочитанные записи; папка, `session.json` и `session.lock` остаются).

Файлы в папках видов, которые не мета и не файл данных какой-либо прочитанной меты (файл данных без меты, временный файл оборванной записи), считаются **непрочитанными**: сессия с ними не считается пустой и не удаляется сама; Discard all мёртвой сессии, перечисленной целиком, по-прежнему удаляет всю папку (так выбрал человек).

Пустая мёртвая сессия (и мёртвая сессия, все записи которой восстановлены) удаляется только после повторного листинга под её блокировкой: в папке должны остаться лишь `session.json`, `session.lock` и пустые папки видов; иначе (например, запись появилась после сканирования) папка остаётся.

Сканирование также смотрит, есть ли источник сейчас (слои `res://` сверху вниз) и изменился ли он: сначала размер против `source_size` меты (другой размер — изменился, без чтения), иначе SHA-256 файла, читаемого по частям (`read_beneath_stream`); эти байты считаются в тот же бюджет 512 МиБ, сверх него пометка «изменён на диске» не проверяется (запись остаётся восстанавливаемой).

### Вопрос

Один вопрос на все DEAD-сессии, не по вопросу на запись: `dialogs().choose("Recover unsaved changes", text, {"Restore all", "Discard all", "Later"})`. Текст — по строке на запись: вид (Level / Prefab / Data / Mesh), источник (или «untitled level»), `saved_at`; пометка «file changed on disk since the autosave», если SHA-256 источника изменился; пометка, почему запись нельзя восстановить; строки со счётчиками отвергнутых и непроверенных записей и непроверенных сессий. Всё, что пришло из файлов, показывается как данные: управляющие и непечатаемые символы — `\xNN`, не длиннее 200 символов, затем «...». Не больше 50 строк, затем «and N more».

UNVERIFIABLE-сессии — отдельный вопрос после первого (текст добавляет, что Restore all переносит файлы из папки того, возможно ещё работающего, редактора), «Recover unsaved changes of another editor», кнопки `{"Later", "Restore all", "Discard all"}` (Later первой, по умолчанию); текст говорит «An editor may still be running on <host>» (экранировано, обрезано) или «This file system cannot tell whether that editor still runs».

Без человека (headless, агентский режим — те же условия, что у вопроса миграции): предупреждение в лог со списком сессий и записей, ничего не спрашивается и не удаляется, блокировки отпускаются.

### Ответы

- **Later** или закрытие вопроса — ничего не удаляется, блокировки отпускаются.
- **Discard all** (DEAD, прочитанная целиком) — вся папка сессии удаляется, пока блокировка держится, затем блокировка отпускается. **Discard all** (UNVERIFIABLE или прочитанная не полностью) — удаляются только проверенные и отвергнутые файлы записей, которые сканирование прочитало; `session.json`, `session.lock` и папка остаются.
- **Restore all** — каждая восстанавливаемая запись по очереди (ниже). После того как все записи DEAD-сессии обработаны и ни одной не осталось — её папка удаляется (под её блокировкой), блокировка отпускается.

### Restore

- **Вид и источник:** расширение источника должно соответствовать виду (scene — `.desc`, но не `.prefab.desc`/`.poly.desc`/`.geom.desc`, и корневой `__type` и байтов автосохранения, и существующего файла источника (прочитанного тем же безопасным чтением, в счёт бюджета 512 МиБ) — тип уровня `level_desc`, иначе запись не восстанавливается, её можно только отбросить; prefab — `.prefab.desc`; mesh — `.poly.desc`; data — `.desc`, в байтах которого `__type` — тип документа). Источник должен существовать сейчас и открываться обычным путём своего вида (который отказывает другому виду). Запись с источником, которого нет, **не** восстанавливается: «source missing: can only be discarded». Безымянный уровень (пустой `source`) восстанавливается как безымянный уровень из байтов.
- **Содержимое — обычным путём загрузки из проверенных байтов**, документ после этого грязный, исходный файл не пишется:
  - уровень — пока грузится другой уровень, восстановление отказывает; `level_load_component::begin` получает байты вместо байтов файла и кладёт их в свою рабочую копию `memory://editor/loading/<n>/<stem>.desc`; источник документа — настоящий тег; затем `commit("Recovered autosave", state_only)` — только если закончилась именно эта загрузка (та же рабочая копия и тот же источник), иначе отказ и пара остаётся. Открыт может быть один уровень: из нескольких записей уровня восстанавливается самая новая по `saved_at`, остальные остаются («only one level can be open: not restored, kept»). Уровень с несохранёнными правками не заменяется;
  - префаб — `prefab_editor_component::open(source)`, по окончании открытия байты кладутся в `memory://editor/recovery/<n>/<имя файла данных>`, читаются как `scn::prefab_desc` через систему ресурсов и вносятся `prefab_document::edit`;
  - меш — `modeller_component::open`, затем `mesh_document::edit` с `poly_mesh`, прочитанным `poly_mesh_from_json`;
  - данные — открытие через `data_document_host`, затем `data_document::restore_own` с объектом из байтов (другой `__type`/`__parent` — отказ).
- После успешного восстановления те же проверенные байты с новой метой (своя сессия, своё имя машины, формат 2) пишутся в **свою** папку сессии (`write_autosave_files`; автосохранение считает их своими, `autosave_component::adopt`), и только потом удаляется пара мёртвой сессии: второй сбой найдёт её снова. Если восстановление не удалось — сообщение человеку (`dialogs().message`), пара мёртвой сессии остаётся.

### Чего восстановление никогда не делает

- не трогает LIVE и STARTING сессии;
- ничего не создаёт по имени из меты: ни папку, ни файл, кроме своих файлов автосохранения;
- не пишет исходный файл документа;
- не удаляет файлы UNVERIFIABLE-сессии без выбора человека, не удаляет ничего в headless;
- не даёт команды агенту: Restore — только действие человека.
