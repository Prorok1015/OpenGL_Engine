**Status:** in_progress (#1186 — автосохранение; #1187, #1188 — дальше)

**Stories:** #1186 (автосохранение в `cache://autosave/`), #1187 (восстановление после сбоя), #1188 (следующий шаг после восстановления)

## 1. Зачем

Редактор держит правки в памяти до Save. Падение процесса, зависшая видеокарта или убитый процесс теряют всё, что не было сохранено. Автосохранение раз в несколько секунд-минут пишет копию несохранённого документа рядом с проектом — не поверх исходного файла — чтобы после сбоя её можно было предложить восстановить (#1187).

## 2. Что делает автосохранение (#1186)

- **Какие документы:** все открытые документы с несохранёнными правками (`is_dirty()`), обход через `document_manager::for_each`: уровень (`scene`), префаб (`prefab`), документ данных (`data`), меш (`mesh`). Документ, который сейчас нельзя менять (`edits_locked()`, Play), пропускается.
- **Что пишется:** ровно те байты, которые записал бы Save для текущего состояния (интерфейс `edt::autosave_source`, внутренний для редактора, не часть `edt::document`):
  - уровень — `level_controller::level_file_json` (та же функция, что у Save) над **копией** миров, в которую перенесены трансформы из ECS; документ, его история и `rebase_history` не трогаются. Безымянный уровень пишется как `untitled`;
  - префаб — `prefab_file_bytes` рабочей копии (форма Apply);
  - документ данных — `data_document::save_bytes()` (проверка, `stamp_tree`, ссылки как в файле, без записи);
  - меш — текст `x.poly.desc` (`mesh::poly_file_text`); пара геометрии выводится из него и не пишется.
- **Когда:** отсчёт документа начинается с его первой несохранённой правки; через `interval` секунд (по умолчанию 60) пишется копия. Если в этот момент идёт жест человека (активный элемент ImGui, перетаскивание гизмо, незакоммиченное поле инспектора — `editor_system::person_is_editing`), запись ждёт и делается сразу после конца жеста. Отдельного таймера простоя нет. После записи следующая — через `interval` после следующей правки (смены `generation()`); без правок повторной записи нет.
- **Как пишется:** снимок берётся на главном потоке; печать JSON уровня, хеш исходного файла и запись идут задачей `job_service` на линии io. Каждый файл — во временный файл рядом и переименованием поверх, все папки открываются без следования по ссылкам (`platform::beneath`, как запись `resource_system` в #414/#1294). Исходный файл и `is_dirty()` документа не меняются.
- **Когда файлы удаляются:** документ стал чистым (Save, Discard = `mark_clean`, Revert); документ закрыт (`document_closed`); у документа сменился источник (загружен другой уровень, Save As); сменилась папка кеша проекта; чистый выход из редактора (`~editor_system`). После сбоя файлы остаются — это и есть материал для #1187.
- **Без проекта** (нет монтирования `cache://`) автосохранение выключено, одна строка в лог (INFO, `editor/autosave`).

## 3. Настройки

Личные настройки человека, не проекта: `edt://settings/autosave.json`

```json
{ "enabled": true, "interval_seconds": 60 }
```

- `interval_seconds` — от 5 до 86400 (вне диапазона прижимается к границе); неизвестный ключ или неверный тип — предупреждение и значения по умолчанию.
- cfg `editor/autosave` (по умолчанию `true`): `false` выключает автосохранение на этот запуск, что бы ни было в файле (CI, тесты).
- Edit > Editor Settings..., раздел **Autosave**: флажок и интервал, сохраняются в тот же JSON.

## 4. Файлы на диске (формат 1)

Папка: `<проект>/.cache/autosave/` (корень монтирования `cache://`).

| Файл | Содержимое |
|---|---|
| `autosave/<kind>/<name>` | байты документа, как их записал бы Save |
| `autosave/<kind>/<name>.autosave.json` | мета-файл (ниже) |

`<kind>` — `document::kind()` (`scene`, `prefab`, `data`, `mesh`). `<name>` — путь источника внутри `res://` (для другого протокола — весь тег), сведённый в одно имя файла: `/` → `%2F`, `%` → `%25`, а также `\ : < > | ? * "` и управляющие символы — `%XX`; ведущая точка — `%2E`; имя длиннее 160 байт — хвост пути + `~` + FNV-1a 64 полного пути. Безымянный документ — `untitled`. Пример: `res://levels/arena.level.desc` → `autosave/scene/levels%2Farena.level.desc`.

Мета-файл пишется после файла данных и удаляется раньше него: есть мета — есть и данные.

```json
{
  "format": 1,
  "source": "levels/arena.level.desc",
  "kind": "scene",
  "generation": 42,
  "saved_at": "2026-11-24T10:15:00Z",
  "source_size": 18342,
  "source_sha256": "<64 hex>"
}
```

| Поле | Смысл |
|---|---|
| `format` | версия формата, сейчас `1`; читатель другой версии файл пропускает |
| `source` | путь источника внутри `res://` (весь тег для другого протокола); пусто для безымянного документа |
| `kind` | вид документа (`scene`, `prefab`, `data`, `mesh`) |
| `generation` | `document::generation()` записанного состояния |
| `saved_at` | время записи, UTC, ISO-8601 |
| `source_size`, `source_sha256` | исходный файл на диске в момент записи (необязательны: нет у безымянного, у недоступного и у файла больше 256 МиБ). По ним #1187 видит, что источник изменился после автосохранения |
