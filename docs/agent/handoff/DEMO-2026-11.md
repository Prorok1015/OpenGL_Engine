# Демо: редактор + ИИ-агент (MCP), Play/Game mode, Git, GitHub

Ветка `aibranch` (проверено на `0cf3ee2`, #539). Сценарий для ручного прогона на своей машине (Windows или Linux).
Всё, что ниже, взято из кода и документации ветки; места, которые по исходникам подтвердить не удалось, помечены **(проверить)**.

Отмечайте по ходу: ✅ / ❌ (что увидели) / ⚠️ (работает, но странно). Лог — консоль редактора и `logs/engine.log` в рабочей папке.

Два проекта:
- **sandbox** (`projects/sandbox`, есть в репозитории) — шаги 1, 2, 4, 5, 6: там есть уровни с камерой (`res://levels/smoke_level.desc`).
- **DemoProject** — новый проект из шаблона `Editor/data/templates/projects/empty` (там есть `code/` с CMake) — шаги 3, 7, 8. Код (`code.*`) без папки `code/` отвечает `no_project`, поэтому на sandbox шаг 3 не пройдёт. Для Git/GitHub нужен отдельный репозиторий: sandbox лежит внутри репозитория движка, и Git-панель покажет сам `OpenGL_Engine`. Черновой PR туда создавать не надо.

## 0. Сборка и запуск

```bash
git clone --recursive -b aibranch https://github.com/Prorok1015/OpenGL_Engine.git
cd OpenGL_Engine
cmake --preset dev-debug                 # Ninja, build/dev-debug
cmake --build build/dev-debug --target editor
```
- Windows: команды выполнять в Developer PowerShell VS 2022 (нужны MSVC, CMake ≥ 3.26, Ninja). Исполняемый файл — `build\dev-debug\Editor\editor.exe`.
- Пресеты: `dev-debug`, `dev-release` (RelWithDebInfo), `release`, `no-assimp`. Для демо быстрее работает `dev-release`: тогда везде `build/dev-release`.

Запуск из корня репозитория с тестовым проектом:
```bash
build/dev-debug/Editor/editor --config Editor/config/editor.cfg --project projects/sandbox
```
**Должно быть:** откроется окно с меню File / Edit / View / Build / Play / Help и загрузится стартовый уровень проекта (`start_scene` = `res://levels/editor_level.desc`). Лог пишется в `logs/engine.log`.
- Если спросит про версию движка (в `project.snkproj` записано `0.2.0`), добавьте `--allow-engine-version-mismatch` **(проверить, спросит ли вообще)**.
- Полезные опции: `--help` (все опции и `--set`-переменные), `--set <имя> <значение>` (можно повторять), `--game[=res://...]`, `--headless`, `--mcp-stdio`, `--agent-policy <файл>`.

**DemoProject (понадобится в шагах 3, 7, 8).** File > **New Project...** → путь, например `~/snk-demo/DemoProject` (папка создаётся; имя проекта = имя папки). Редактор перезапустится на новом проекте. Затем **закройте редактор** и в терминале:
```bash
cd ~/snk-demo/DemoProject
git init -b main && git add -A && git commit -m "init"
git remote add origin https://github.com/<you>/<throwaway-repo>.git   # пустой одноразовый репозиторий
git push -u origin main
```
Редактор запоминает состояние git для корня проекта, поэтому `git init` при открытом редакторе он увидит только после перезапуска. Запуск на DemoProject:
```bash
build/dev-debug/Editor/editor --config Editor/config/editor.cfg --project ~/snk-demo/DemoProject
```
В шаблоне есть `.gitignore` с `.snk/*` и `!.snk/agent_policy.json`: файл подключения `mcp.json` в git не попадёт, а политика попадёт.

## 1. Подключение агента (MCP)

**Включить сервер на лету.** View > **MCP / Agents** (плавающее окно, по умолчанию закрыто):
- секция **Server**: галка **"Accept agent connections (HTTP, 127.0.0.1)"**, поле **"Port (0 = any free port)"**, кнопка **"Restart on this port"**;
- после включения показываются **Address:** `http://127.0.0.1:<port>/mcp` и подсказка "The token for the client is in .snk/mcp.json of the project folder.";
- выбор сохраняется в `edt://settings/agent_server.json` (`{"enabled": true, "port": N}`) и действует при следующем запуске.

Вместо окна можно включить из командной строки (явное значение сильнее личного переключателя):
```bash
... --set editor/agent_server true --set editor/agent_server_port 8765
```
`editor/agent_server_port 0` (по умолчанию) — порт выбирает ОС. В логе будет строка `the MCP server listens on http://127.0.0.1:<port>/mcp`.

**Файл подключения** `<проект>/.snk/mcp.json`: поля `url`, `port`, `token`, `pid`. Права есть только у пользователя (0600 / DACL). **Токен новый при каждом старте сервера**, поэтому после перезапуска редактора клиента нужно переподключить. Транспорт — Streamable HTTP, токен передаётся заголовком `Authorization: Bearer <token>`, слушается только 127.0.0.1. Без токена сервер отвечает 401.

**Claude Code** (в отдельном терминале, порт и токен берите из `mcp.json`):
```bash
claude mcp add --transport http snk-editor http://127.0.0.1:8765/mcp --header "Authorization: Bearer <token>"
```
То же в `.mcp.json` клиента **(формат Claude Code, проверить)**:
```json
{ "mcpServers": { "snk-editor": { "type": "http", "url": "http://127.0.0.1:8765/mcp",
  "headers": { "Authorization": "Bearer <token>" } } } }
```
Вариант без сети: `editor --headless --mcp-stdio --project <путь>`. В этом режиме вопросы задать некому, и `ask` превращается в `denied`, если его заранее не разрешил `--agent-policy <файл вне проекта>`.

Имена инструментов — id команд с заменой `.` на `_`: `scene_query`, `component_set`, `play_start`, `vcs_status`, `forge_create_pr` и т.д.

**Спросить агента:** «Перечисли инструменты редактора snk-editor и прочитай последние 20 строк лога».

**Должно быть:** в строке меню появится слот **"Agent: 1"**. Он кликабелен: в popup последние 8 действий агента, сессии с **Disconnect** и **Settings...**. Пока агент ждёт ответа, слот показывает **"Agent: N waiting"**, а после каждого действия агента 2 с подсвечивается зелёным. В окне MCP / Agents в секции **Connected agents** — клиент, сессия, Connected, Idle и кнопка **Disconnect**. Сессия закрывается после 30 мин простоя (`editor/agent_session_idle_minutes`).

**Политика allow / ask / deny.** Действуют два слоя: `<проект>/.snk/agent_policy.json` (коммитится) и личный `edt://settings/agent_policy.json`. Побеждает более строгий, а личный слой может только ужесточать. Значения по умолчанию:
- `read`, `scene_edit`, `live`, `play`, `editor_control` и `vcs_read/commit/branch/sync/push` — allow;
- `code_edit`, `code_files`, `cmake_presets` и `vcs_forge` — ask;
- `build` — deny.

В окне секция **Policy**: радиокнопки **Project / Mine**, таблица Category / Mode / Agents get / Because, узлы **Single commands** и **Git**, кнопки **Apply** / **Revert**.

**Баннер утверждения ослабленной политики.** Закройте редактор и руками ослабьте проектный файл:
```json
{ "version": 1, "categories": { "code_edit": "allow" } }
```
Затем запустите редактор снова.

**Должно быть:**
- в правом нижнем углу появится уведомление "The project's agent policy waits for your approval." с кнопками **Open / Later**;
- слот в меню покажет **"Agent policy: approve"**;
- в окне MCP / Agents будет баннер "The project's agent policy lets agents do more than you approved." с кнопкой **Review...**;
- **"Approve this version"** становится активной только через ~1 с, если popup Review открыт и курсор был над ним;
- пока изменение не утверждено, действует более строгий вариант: `code.write` по-прежнему спрашивает.

После проверки верните файл как было (или утвердите изменение).

## 2. Агент правит сцену (sandbox, `res://levels/smoke_level.desc`)

Откройте уровень через File > **Open Level...**. Подсказки для агента:
1. «Вызови `agent_session_begin` с label "демо"».
2. «Через `scene_query` найди узлы активного мира и покажи их имена и ref».
3. «Создай под корнем мира узел "AgentCube" (`scene_node_create`)».
4. «Измени у какого-нибудь источника света поле компонента через `component_set` (patch — JSON Merge Patch). Перед этим посмотри схему через `component_schema`».

**Должно быть:**
- после каждой правки в **Scene Hierarchy** у узла появится суффикс **" (agent)"** с подсказкой "Changed by an agent (not saved or accepted yet)";
- в **Inspector** будет строка "Changed by an agent (not saved or accepted yet)";
- меню Edit покажет «Undo …» с пометкой " (agent)", Ctrl+Z отменяет правку агента;
- в слоте "Agent: …" будет зелёная вспышка.

**Принять правки:** Edit > **Accept Agent Changes**. Пометки исчезнут; это может сделать только человек. Сохранение уровня (Ctrl+S) тоже снимает пометки.

**Откат через сессию:** сделайте ещё 2–3 правки, потом попросите «Сделай `agent_session_rollback`». Шаги откатываются от новых к старым и останавливаются перед узлом, который вы потом правили руками; тогда в ответе будет `stopped_at`. В конце: «Заверши сессию `agent_session_end`».

## 3. Агент правит код (DemoProject, `code.write` под "ask")

**Спросить агента:** «Прочитай `code_read` файл `src/game_module.cpp` и через `code_write` (replace) добавь в начало комментарий `// demo`».

**Должно быть:** в правом верхнем углу окно **"Agent request"** с текстом "An agent wants to run code.write", описанием, сессией и категорией. Аргументы показаны целиком, ответ ждёт 60 с. Кнопки:
- **"Разрешить один раз"**: выполняется только этот вызов;
- **"Разрешить до конца сессии этого агента"**: больше не спрашивает про эту категорию до конца MCP-сессии. Сессия кончается при Disconnect, через 30 мин простоя или при выключении сервера;
- **"Отклонить"**: агент получит `denied`.

Проверьте:
- после «до конца сессии» вторая просьба `code_write` проходит без вопроса;
- `code_create`, `code_rename` и `code_delete` — другая категория (`code_files`), про неё спросит отдельно;
- у **рискованных** команд (`code.delete`, `forge.create_pr`) есть только "Разрешить один раз" / "Отклонить": сессионное разрешение на них не выдаётся никогда.

Попросите «удали файл через `code_delete`» и убедитесь, что средней кнопки нет. Каждая правка пишется в лог: `agent` "code.write <path> (<n> bytes) by <who>".

## 4. Play Mode (sandbox, `smoke_level`)

**Вручную:** меню **Play**: **Play** (Ctrl+P; на паузе пункт работает как Resume), **Pause**, **Step** (активен только на паузе), **Stop**.

**Должно быть:**
- в строке меню "Play: playing" / "Play: paused";
- в Hierarchy, Inspector и Viewport надпись **"Stop Play to edit"**, гизмо и drag-n-drop не работают;
- Edit > Undo/Redo неактивны;
- после Stop уровень, камера, выделение и активный мир возвращаются, документ не меняется. Сохранять во время Play можно.

**Через агента** (категория `play` — allow):
- «`play_start`, потом `play_pause`, `play_step` с n=10, `play_status`, `play_stop`». Каждый ответ: `{state, frame, worlds}`, у `frame` после step прибавилось 10.
- «Во время Play попробуй `scene_node_create`»: ответ `busy` "stop play first".
- «`play_step` во время playing»: `failed` "pause first".
- «`app_advance` с frames=5, затем `app_resume`»: работает только при активном Play, вне Play — `disabled`. Каждый Stop снимает удержание времени.

## 5. Game mode

**F11** или View > **Game Mode**: Game view на всё окно, без меню и панелей. Срабатывают только F11 и хоткеи меню Play, остальной ввод уходит в игру. Переход в редактор ставит Play на паузу, возврат в игру её снимает.

Старт сразу в игре:
```bash
build/dev-debug/Editor/editor --config Editor/config/editor.cfg --project projects/sandbox --game=res://levels/smoke_level.desc
```
**Должно быть:**
- пока уровень грузится — чёрный экран "Loading res://levels/smoke_level.desc..." без меню и хоткеев (Esc в окне "Loading Level" отменяет загрузку → режим редактора);
- после загрузки в логе `level loaded: ...smoke_level.desc` и `[editor] game mode`, Play запущен;
- уровень принимается только как `res://`-тег; путь к файлу даст ERROR, и уровень не загрузится.

**Stop возвращает в редактор:** попросите агента «`play_stop`» (или F11 → Play > Stop). Любой Stop в game mode переключает раскладку редактора. Агент может переключать режим сам: `editor_mode_toggle{mode:"game"|"editor"}`.

## 6. `capture.compare` с эталоном `res://`

Эталон — PNG/JPEG внутри `res://`, **ровно того же размера**, что и вид. Размер Game view между съёмкой эталона и сравнением не меняйте, иначе получите `size_mismatch`. Как сделать эталон:
- (а) запустить с `--set capture/on_settled projects/sandbox/res/demo_ref.png --set capture/viewport game --set editor/show_game_view true` и дождаться в логе `captured viewport 'game' (WxH) to ...` **(проверить, что `settled` наступает в обычном оконном запуске)**;
- (б) попросить агента: «сними `viewport_capture` вида game и сохрани `png_base64` в `projects/sandbox/res/demo_ref.png`».

**Спросить агента:** «Сравни Game view с эталоном: `capture_compare` с reference `res://demo_ref.png`, viewport `game`».

**Должно быть:** `{match, diff_pixels, total_pixels, diff_pct, width, height, viewport, reference}`. На неизменной сцене `match: true` (по умолчанию `fuzz` 4 %, `max_diff_pct` 2 %). Сдвиньте объект и повторите: `match: false`. Неверные ссылки отвергаются как `invalid_args`: абсолютный путь, `..`, `\`, `:`, не-`res://` или `.pct`. В `--headless` ответ `unavailable_headless`.

## 7. Git-панель (DemoProject)

View > **Git** (по умолчанию закрыта).

**Должно быть:**
- ветка, upstream "ahead N, behind M";
- кнопки **Refresh / Fetch / Pull / Push / Create PR / Account...**;
- вкладки **Changes** и **History**.

Пройдите по шагам:
1. Измените `code/src/game_module.cpp` в другом редакторе: через ~1 с файл появится в изменениях. Клик по файлу показывает diff.
2. Отметьте галку stage, введите сообщение и нажмите **Commit**.
3. Ветка: комбобокс веток (при незакоммиченных изменениях переключение сначала спросит), поле новой ветки + **Create**.
4. **History**: граф коммитов, метки веток и тегов, фильтры автора и текста. У коммита видны файлы и diff, в контекстном меню **Copy hash**.
5. В терминале `git commit --allow-empty -m "from terminal"`: панель и History обновятся сами (~250 мс после изменения). Изменённый ассет в `res/` тоже обновляет панель (~1 с).
6. **Push**: "running..." + прогресс-бар + **Cancel**.

**Агент (`vcs.*`), правила по умолчанию:** push только в ветки `agent/*`, только в remote `origin`; `main`/`master` защищены. Hooks, фильтры (LFS) и credential helper из конфига репозитория не запускаются.

**Спросить агента:**
- «`vcs_status`, потом создай ветку `agent/demo` (`vcs_branch_create`), переключись (`vcs_checkout`), закоммить изменения (`vcs_stage` + `vcs_commit`) и запушь (`vcs_push` в origin, `set_upstream`)». Каждая команда отвечает `{job}`, результат — через `job_get`, а с progressToken приходит прогресс. В сообщении коммита агента последним абзацем стоит `Agent-Session: <session>`.
- «Запушь в `main`»: результат `denied` до запуска git.

Разрешённые ветки и remotes меняются в MCP / Agents > Policy > **Git** ("Push to branches", "Remotes", "Also protected branches") или в секции `"vcs"` политики.

## 8. GitHub (DemoProject, remote `origin` на github.com)

Нужен `curl` в PATH (`forge/curl` в конфиге). Токен хранится в ОС: Windows Credential Manager / libsecret на Linux. Без хранилища он живёт только в RAM до конца сессии и никогда не пишется в файл.

1. Git-панель > **Account...** → окно **Git Account**: строка `github.com` и её состояние "not set". Вставьте токен в маскированное поле и нажмите **Save**. Состояние станет "set (OS keychain)" или "set (this session only)". Есть кнопки **Clear / Remove / Refresh**. Нужные права токена (pull requests на запись) в исходниках не указаны **(проверить)**.
2. **Create PR** (после push ветки; неактивна без ветки и во время записи). В форме:
   - Base `main`, Head = текущая ветка, Title, тело, галка **Draft** (включена);
   - сверху "The pull request goes to: github.com/<owner>/<repo> (remote origin)". **Create** неактивна, пока адрес не показан;
   - если адрес переписан `insteadOf`/`pushurl`, показываются оба и нужна галка "I understand the address is rewritten".

   Результат: "Pull request #N created." + адрес текстом и **Copy link** (редактор ссылку не открывает). Без токена (`no_token`) появится кнопка **Open Git Account**.
3. **Агент:** «Создай черновой PR из `agent/demo` в `main` через `forge_create_pr`».
   - Окно "Agent request" покажет "Create a draft PR in github.com/<owner>/<repo> (remote origin): agent/demo -> main".
   - Кнопок только две: **"Разрешить один раз"** / **"Отклонить"** (риск-команда, сессионного разрешения нет).
   - PR агента всегда draft: `draft:false` → `denied`. `head` обязан подходить под `push_branches` и существовать локально, remote должен быть в `remotes`.
   - `forge_pr_status` и `forge_list_prs` тоже спрашивают (категория `vcs_forge` = ask).

## 9. На что смотреть / известные ограничения

- **Хранилище токена защищает от логов, ответов MCP и файлов проекта, но не от нативного кода самого проекта**: игровые модули загружаются в процесс редактора.
- **Ссылки в `.snk` отвергаются.** Если `.snk` или `agent_policy.json` — symlink, junction или FIFO, слой политики считается битым: всё `denied` и ERROR `editor/agent_policy`. `mcp.json` в `.snk`-ссылке не создаётся (ошибка при старте сервера).
- Токен MCP и порт (если 0) меняются при каждом старте сервера, поэтому клиента нужно переподключать.
- `ask` при шрифте без кириллицы или в headless без `--agent-policy` — `denied`, вопрос не показывается.
- Состояние git кэшируется на корень проекта: `git init` при открытом проекте не виден до перезапуска.
- `--agent-policy` работает только в `--headless`, файл должен лежать вне проекта и вне его git-дерева. Секция `"vcs"` в нём запрещена.
- Агентские push/fetch/pull требуют git ≥ 2.26. Агенту никогда не доступны force-push, `reset --hard`, удаление веток и rebase.
- Агент не может поменять политику: команды для этого нет, а checkout/pull, меняющий `agent_policy.json`, — `denied`.
- `capture.compare` ничего не масштабирует: другой размер даёт `size_mismatch`, для агента лимит 8 Мпикс.
- Сборка игрового модуля (`build.game_module`, Ctrl+B) для агента — `deny`, пока в проектной политике нет записи именно для этой команды. Сама сборка требует движок, собранный как shared (`SNK_ENGINE_SHARED`), — в `dev-*` пресетах он выключен.
- После File > New Project редактор перезапускается сам. Переносятся ли `--set`-опции в перезапущенный процесс — **(проверить)**; включение сервера через окно MCP / Agents сохраняется в любом случае.
