# API расширения редактора: реестры и снятие регистраций

**Issue:** #590 (эпик #22; #587–#589) · для автора проекта: модуль `game_editor` · заголовки: `Editor/code/editor_system/include/snk/editor/`

Модуль `game_editor` — это отдельная библиотека проекта (`kind: "editor"` в `project.snkproj`), которую редактор грузит после `game`. Она добавляет в редактор панели, команды, рендереры инспектора и виды ассетов, не меняя сам редактор. В игровой `.exe` (Shipping) она не попадает. Рабочий пример — `Editor/data/templates/projects/empty/code/src/game_editor.cpp`, образец для тестов — `tests/editor_api_dll`.

## Как устроен модуль

```cpp
#include <snk/editor/edt_editor_extension.h>

class my_editor_module final : public edt::editor_extension
{
public:
	std::string_view name() const override { return "game_editor"; }  // как в манифесте
	void register_editor(edt::editor_module_context& context) override { /* регистрации */ }
	void shutdown_editor() override { /* своё состояние */ }
};

SNK_DECLARE_EDITOR_MODULE(my_editor_module)
```

`SNK_DECLARE_EDITOR_MODULE` экспортирует функции модуля и `snk_editor_api_version`. Редактор сравнивает её с `SNK_EDITOR_API_VERSION` до создания модуля: major должен совпасть, minor модуля — не быть больше minor редактора. Версия сейчас **2.0**. Модуль, собранный под 1.x, редактор не загружает и не роняет: он отказывает с сообщением «rebuild the project against the current SDK» (`check_editor_api_version`), остальные модули и игра продолжают работать; собрать проект заново под новый SDK. Что изменилось в 2.0 — в разделе «Версия 2.0». Раньше: 1.2 (1.1 добавила превью ассетов; 1.2 — счётчик исполняемых колбэков модуля: панели, действия, инспекторы, asset kinds и обработчики событий, зарегистрированные через `editor_module_context`, считаются, пока работают, и `module_unload_refusal` отказывает выгрузке из них). **Перезагрузка из колбэка модуля.** Колбэки модуля (панель, действие, инспектор, asset kind, фабрика и документ превью, обработчик события, продолжение задачи) считаются, пока работают; синхронный `reload` из такого колбэка отклоняется (`refused`, «the editor modules could not be unloaded: …») и **не повторяется**: откладывайте перезагрузку (`post_main`, `next_frame`). Документ превью модуля редактор держит через считающий прокси: `documents().preview()` и `open_preview()` отдают прокси, поэтому `dynamic_cast` к типу своего документа не сработает; состояние, которое нужно извне, отдавайте через свои сервисы. Модуль, собранный под 1.1, на хосте 1.2 грузится, но его обработчики `subscribe` не считаются (счётчик читает встроенный в модуль код 1.2): пересоберите модуль под 1.2.

CMake: `snk::engine snk::engine_api snk::editor_api` из SDK; библиотека `snk::editor_api` есть только при общем движке.

## Реестры

Всё, что модуль кладёт в редактор, идёт через `editor_module_context`; руками реестры редактора модуль не трогает.

| Реестр | Вызов | Что регистрируется | Ключ |
|---|---|---|---|
| Панели | `add_panel(panel_desc)` | наследник `edt::panel_base`, место в раскладке, пункт меню View | `id` (равен `panel_base::get_id()`) |
| Меню | `add_menu(name)` | верхнее меню | имя |
| Действия | `add_action(action_desc)` или `add_action(cmd::command_desc, action_ui)` | команда (видна агентам и скриптам по своим правам) и её пункт меню и сочетание клавиш | `id` команды |
| Рендереры инспектора | `add_inspector(type, renderer)` | рисует поля компонента по `__type` desc | `type` |
| Виды ассетов | `add_asset_kind(module_asset_kind_desc)` | действия «открыть» и «бросить в сцену» по суффиксу пути; их обратные вызовы получают `editor_module_context&` | `id`; побеждает самый длинный подходящий суффикс |
| Превью ассетов (API 1.1) | `add_asset_preview(module_asset_preview_desc)` | документ предпросмотра по суффиксу; фабрика получает `editor_module_context&` | `id` |
| События | `subscribe(signal, handler)` | подписка на сигнал из `events()` (он только для чтения: `const editor_events&`); соединение держит область модуля | — |
| Задачи | `start_job(...)`, `tasks()` | фоновая работа, привязанная к жизни модуля | — |
| Проблемы | `set_problems(source, items)` | записи списка проблем | `source` |

Правила, общие для всех реестров:
- Неверная регистрация (пустой или занятый id, панель, чьи `id`/`title` не равны собственным, действие без подписи или с неразобранным сочетанием, пустой обработчик) — ошибка в логе: возвращённая регистрация не активна, модуль продолжает грузиться. Занятое сочетание клавиш не ошибка: выигрывает более раннее действие, в лог идёт предупреждение.
- Рендерер на тип, у которого он уже есть, в том числе встроенный, отвергается. Тип desc проекта (в примере `game_note`) — безопасный выбор.
- Тип без рендерера рисуется общим JSON-редактором; рендерер возвращает `true`, если поменял данные.
- Все реестры и панели работают на главном потоке.
- `dialog_service`, `editor_services` (`services()`) и сам `editor_context` модулю не выдаются: через них регистрации ушли бы мимо области (§ «Версия 2.0»).

## Снятие регистраций

Всё, что модуль зарегистрировал, держит `registration_scope`. При выгрузке:

1. `stop_tasks()`: новые задачи отклоняются, запущенные получают stop-токен и ожидаются, продолжения на главном потоке, поставленные раньше, выполняются сейчас (со статусом «отменено»). Задача модуля обязана смотреть на stop-токен.
2. `shutdown_editor()` модуля: здесь освобождается собственное состояние. Редактор вызывает его до снятия регистраций и всегда перед уничтожением модуля. Если оно бросило исключение, шаг 3 всё равно выполняется: область очищается и снимается с учёта до возврата, чтобы редактор не держал указатель в выгружаемый код.
3. Подписки, потом регистрации, потом очистки (`set_problems` и подобное), каждая группа в обратном порядке регистрации. После этого редактор такой же, как до загрузки, а повторная загрузка не конфликтует со старыми записями.

Что требуется от модуля:
- Регистрации и подписки делать только через `editor_module_context`: `events()` с 2.0 константный, подписаться на сигнал руками не получится.
- Не обращаться к `edt::` из статических инициализаторов DLL.
- Не вызывать выгрузку из своих же обратных вызовов: редактор отказывает в выгрузке, пока выполняется продолжение задачи модуля (`editor_context::module_unload_refusal`).

## Версия 2.0 (#663): ни одна функция API не регистрирует мимо области

Гарантия сформулирована так: **ни одна функция, которую API предлагает модулю, не даёт регистрации мимо `registration_scope`**. Полный запрет на уровне языка невозможен: модуль может подключить закрытые заголовки редактора и достать хост другим путём (например, через хранилище приложения), и это вне гарантии. Что закрыто:

- `editor_module_context::services()` удалён. Реестры `editor_services` (`descs()`, `assembler()`, `sfactory()` и указатели `base_*`) принимают desc и спавнеры в обход области; движковые регистрации модуль делает через слой своего игрового модуля. Узкие методы чтения добавляются по запросу конкретного модуля, не заранее.
- `events()` возвращает `const editor_events&`: `events().x.subscribe(...)` не компилируется, подписка — только `editor_module_context::subscribe`. Читать состояние (`subscriber_count`) можно; `emit` у сигнала константный и регистрацией не является.
- `dialogs()` не выдаётся (проверено тестом); обёртка с владельцем появится вместе с первым модулем, которому нужен диалог.
- Виды ассетов и превью модуля — `module_asset_kind_desc` и `module_asset_preview_desc`: их обратные вызовы получают `editor_module_context&`, а не `editor_context&` и не `editor_services&`. `add_asset_kind(asset_kind_desc)` и `add_asset_preview(asset_preview_desc)` принимать перестали; встроенные виды ассетов регистрируются в реестре напрямую и не менялись.
- Каждый закрытый путь закреплён проверкой на этапе компиляции (`tests/edt_editor_api_closed_paths_tests.cpp`): вернуть путь нельзя, не сломав сборку.

Миграция модуля 1.x: убрать вызовы `services()`; `add_asset_kind`/`add_asset_preview` переписать на `module_*_desc` (в обратном вызове вместо `editor_context&` — `editor_module_context&`); пересобрать проект под новый SDK.

## Чего пока нет

- Один `game_editor` можно перезагрузить без `game` (#664: `project_module_host::reload_editor_module(имя)`, он же `reload(имя, ...)`): новая копия проверяется рядом со старой (имя, версия editor API, ключ раскладки), перезагрузка отклоняется до выгрузки, если выполняется колбэк модуля (§ колбэки) или от него зависит другой загруженный модуль; затем выгружается только он, на его место грузится новая копия; если новая сборка не регистрируется — возвращается предыдущая (`rolled_back`), если и она не встаёт — модуль остаётся выгруженным (`lost`) до следующей перезагрузки или перезагрузки `game`. Редактор: сборка сообщает и о editor-модулях (`game_module_built`), Build > Reload Game Module и живая сборка берут их (без имени — сначала runtime-модуль, editor-модуль только если ни один runtime не собран; с явным `module` — любой); для editor-модуля нет снимка Play и swap gate; после сборки и в живом режиме он пропускается, если уже актуален (`is_current`, например после перезагрузки `game`, которая перезагружает и его), а названный явно перезагружается всегда. Действие `build.reload_game_module`, которое выгрузило бы editor-модули (перезагрузка самого editor-модуля или `game` при загруженных editor-модулях), не выполняется внутри вызова, а встаёт в очередь на следующий кадр: вызов мог прийти из колбэка модуля (кнопка его панели). Без имени и без собранного runtime-модуля перезагружаются все собранные editor-модули.
- Если перезагрузка `game` отклонена (новая сборка не принята), а `game_editor` пересобран вместе с ней и загружается отдельно, он встаёт поверх **старого** `game`: ключ раскладки (`snk_module_layout_key`) покрывает типы движка, но не типы самого `game`, так что `game_editor`, использующий новые типы `game`, на старом `game` не проверяется. Если пересобрали оба — сначала дождитесь перезагрузки `game`.
- Редактор не держит файл библиотеки: он грузит **копию** из `.cache/modules/<pid>-<n>/` (как `game.dll`, #435), поэтому «Build > Build Game» на Windows перезаписывает `build/bin/game_editor.dll` и `.pdb`, пока редактор запущен.
