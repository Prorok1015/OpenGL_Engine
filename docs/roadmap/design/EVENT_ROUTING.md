## 1. Что решаем

Есть несколько потребителей, а событие одно: нажатие клавиши, клик, позже, возможно, событие шины. Кто его получает и в каком порядке? Кто может его «съесть», чтобы оно не ушло дальше?

Примеры:
- открыто меню паузы → игра не получает прыжок;
- поле чата с фокусом забирает буквы, но не Escape;
- карта открыта → ввод идёт в мир карты, а не в 3D-мир;
- карта закрыта → наоборот.

Решение — один общий механизм, **стек маршрутизации**. Первым источником становится ввод. Порядок и состав стека:
- задаются по умолчанию в уровне;
- меняются из кода игры во время игры.

## 2. Что есть сейчас

`gs::route_input`, `gs_input_routing.cpp`, стадия `update`, до фаз миров:
- Миры набора сортируются по `world_desc.input_layer`, сверху вниз. При равном слое — по id мира (`stable_sort`, :79).
- Мышь получает верхний мир, чья область захвата (`input_capture.regions`, раскладка прошлого кадра) под курсором. Перетаскивание «липкое».
- Клавиатуру забирает мир с `input_capture.keyboard = true`, иначе она идёт всем.
- Владелец ввода теряет клики, которые захватил UI (:117-129).
- Миры вне привязки редактора получают нейтральное состояние.
- Имя `inp::input_layer` уже занято: это стек обработчиков окна (`scn_world_context.h:45`). Новое понятие называется иначе: **слой маршрута**, `ecs::route_layer`.

## 3. Модель

### 3.1. Стек

У каждого набора миров есть свой **стек маршрута**. Это список слоёв в порядке сверху вниз.

```cpp
struct route_layer_desc {
    std::string name;                         // уникально в пределах мира; ключ памяти фронтов (§5)
    int order = 0;                            // больше — выше; по умолчанию слой ввода мира
    bool active = true;                       // неактивный слой ничего не получает и ничего не забирает
    // Что слой забирает себе (ниже не уходит):
    std::vector<std::string> actions;         // действия: их клавиши
    std::vector<inp::KEYBOARD_BUTTONS> keys;  // отдельные клавиши
    bool text_keys = false;                   // печатные клавиши (§4.4); набор текста — отдельная задача
    std::vector<glm::ivec4> regions;          // клики и колесо в этих прямоугольниках (§4.3)
    bool block_below = false;                 // модальный: ниже не уходит ничего
    // Что слой видит, но пропускает ниже:
    std::vector<std::string> listen;
};
```

- **Базовый слой мира.**
  - У каждого мира есть один слой с именем `"world"` и порядком `world_desc.input_layer`. Он работает как сейчас:
    - UI-мир забирает клики в своих областях;
    - игровой мир получает остальное.
  - Его поля задаются в уровне: новое необязательное поле `world_desc.route`. Без поля поведение прежнее.
- **Свои слои мира.**
  - Код игры кладёт слои поверх базового: меню, диалог, карта (§3.3).
  - Слой живёт, **пока его явно не убрали или не заменили**.
  - В Pause слои заморожены вместе с миром: меню паузы не пропадает от паузы редактора.
  - Со смертью мира умирают и его слои.
- **Порядок стека:**
  1. по `order` слоя, сверху вниз;
  2. при равном `order` — по **индексу мира в `world_desc` уровня**;
  3. внутри мира — последний положенный выше, базовый слой ниже всех своих.
- **Индекс мира в `world_desc`.**
  - Сейчас у `world_context` его нет. #604 добавляет `world_context::desc_index`.
  - Загрузка уровня ставит его по порядку миров в файле.
  - Миры, созданные во время работы, получают индекс по месту в документе редактора, иначе — после последнего:
    - мир, созданный из редактора (`edt_world_controller.cpp:133`);
    - двойник Play (`edt_play_session.cpp:104`).
  - Id мира для порядка не годится: `acquire_free_id` переиспользует свободные id.
  - **Это меняет поведение:** при равном `input_layer` порядок теперь задаёт файл уровня, а не id.

### 3.2. Как проходит событие

Один раз за кадр, в `gs::route_input`:

1. **Сырой ввод кадра** раскладывается на единицы:
   - каждая клавиша;
   - каждая кнопка мыши;
   - движение мыши;
   - колесо.
2. **Стек проходит сверху вниз.** Каждый активный слой:
   - получает единицы, которые до него не забрали;
   - забирает свои по правилам §4;
   - передаёт остаток ниже.
3. **Каждый мир** получает объединение того, что дошло до его слоёв:
   - **маску клавиш и мыши** — по ней `route_input` пишет `input_state`; не дошедшее нейтрально, как сейчас;
   - **маску действий**: действия, объявленные его слоями, клавиши которых дошли до объявившего слоя. Её получает `inp::update_actions`.
4. **Слой с `block_below` внутри того же мира** (меню над базовым слоем) скрывает и действия базового слоя этого мира. Поэтому маска действий считается по слоям, а не по миру.

**Одно действие, несколько клавиш (MoveLeft = A и ←).** Уровень действия для слоя — ИЛИ по тем его клавишам, которые до слоя дошли.
- `released` наступает, только когда до слоя не доходит ни одна из зажатых клавиш действия.
- Пример: A перехватили выше, а ← зажата и дошла — действие остаётся зажатым.

### 3.3. Управление из кода игры

Команды меняют стек **со следующего кадра**: они копятся и применяются в начале следующего `route_input` в порядке вызова. Это детерминированно, и внутри кадра стек не меняется.

```cpp
// Системы мира — ctx-ресурс своего мира:
void map_system(const inp::action_state& a, ecs::route_control& routes) {
    if (a.pressed(k_map)) routes.push({ .name = "map", .order = 10, .block_below = true });
    if (a.pressed(k_close)) routes.remove("map");
}
// Вне систем (настройка модуля, редактор):
module_context.routes("play").set_active("minimap", "world", false);
```

Операции `ecs::route_control`:
- для слоёв своего мира: `push`, `replace`, `remove`, `set_active`, `set_order`;
- для других миров набора, по имени мира: `set_world_active(world, bool)` — включить или выключить все слои мира.

`module_context::routes(set)` даёт те же операции вне систем.

- **RAII.** Слои и команды принадлежат наборам. Наборы слоя модуля уничтожаются вместе со слоем, а значит при выгрузке и при перезагрузке кода. От модуля в стеке ничего не остаётся, в памяти маршрутизатора нет указателей на код модуля.
- **По умолчанию активны все слои.** Неактивный мир не получает ничего. Игра сама переключает активный мир — это и есть ответ на «два 3D-мира» (вопрос М6).

### 3.4. Режимы набора

- **Edit.** Стек работает и в наборах Edit: он решает, какой сырой `input_state` получает мир. Действия существуют только в Play и Step.
- **Pause.** Стек заморожен: слои остаются, команды копятся до продолжения.
- **Step.** Правила `WORLD_BUS.md` §4.2.
- **Привязка редактора** (наведение на Game view, полноэкранный режим) решает, получает ли набор ввод вообще. Стек работает внутри неё.

## 4. Что забирает слой

### 4.1. Клавиши и действия

- `actions`: клавиши этих действий по раскладке.
- `keys`: перечисленные клавиши.
- `block_below`: всё оставшееся.

### 4.2. Мышь: клики, колесо, движение

| Единица | Слой забирает её, если |
|---|---|
| Кнопка мыши | курсор в его `regions` при нажатии (захват «липкий» до отпускания, как сейчас), или `block_below` |
| Колесо | курсор в его `regions`, или `block_below` |
| Движение | идёт перетаскивание, захваченное этим слоем, или `block_below` |

**Движение не забирается областью само по себе.** Иначе прицел-область в центре экрана убил бы обзор камерой, а наведение на кнопку HUD останавливало бы его (вопрос М3).

### 4.3. Действие, забранное наполовину

Это правило ИЛИ из §3.2. Тест: A забрана сверху, ← дошла → `MoveLeft` зажат. Отпустили ← → один `released`.

### 4.4. Печатные клавиши (`text_keys`)

В этом срезе — **только блокировка клавиш**:
- **забирает:** A–Z, K_0–K_9, SPACE, APOSTROPHE, COMMA, MINUS, PERIOD, SLASH, SEMICOLON, EQUAL, GRAVE_ACCENT, LEFT_BRACKET, BACKSLASH, RIGHT_BRACKET, BACKSPACE, DELETE, стрелки, HOME, END, а также цифровой блок KP_0–KP_9, KP_DECIMAL, KP_DIVIDE, KP_MULTIPLY, KP_SUBTRACT, KP_ADD, KP_EQUAL;
- **не забирает:** ESCAPE, ENTER, KP_ENTER, TAB, F1–F25, модификаторы и остальные служебные клавиши.

Сам набор текста — отдельная задача (вопрос М8):
- события символов (`char_event`);
- автоповтор;
- IME.

Сейчас в миры не доходит ни одно из них.

## 5. Фронты по стеку

**Память фронтов** — что было зажато до кадра — хранится **вне миров**, в маршрутизаторе.

- **Ключ:** `{набор, мир, имя слоя}`. Значение — простые данные: битовые маски клавиш и действий, без указателей на код модуля.
- **Запись удаляется** со смертью мира, со снятием слоя и с перезагрузкой кода.

Правила:
- **Перехват сверху** клавиши, которую слой ниже видел зажатой (открылось меню): нижний получает один `released`.
- **Повторное взведение.** Когда перехватчик ушёл (меню закрыли, слой снят, мир выключен), а клавиша всё ещё зажата, нижний **не** получает `pressed`. Действие взводится только после отпускания. Это то же правило, что при возврате курсора на Game view.
- **Новый слой** не видит `pressed` у уже зажатой клавиши. Escape, открывший меню, его же не закроет.
- **Hot reload** (`HOT_RELOAD_PLAY.md`):
  - конфигурация стека — слои, их поля, активность, порядок — **простые данные** и входят в снимок набора (#600);
  - после восстановления память фронтов строится заново по правилу «прошлое = текущее», ложных `pressed` нет.

## 6. Поведение по умолчанию

| Сцена без настроек | Поведение |
|---|---|
| 3D + UI | как сейчас: клики по кнопкам UI — в UI, остальное — в игру; Restart получает игровой мир |
| Два игровых мира (`input_layer` 0) | по умолчанию активны оба. Действия получает первый по `world_desc`: он объявляет все действия раскладки и забирает их клавиши. **Во втором мире перестают работать сырые клавиши действий:** камера на WASD, если WASD привязаны к действиям. При загрузке пишется предупреждение. Игра настраивает это сама: выключает второй мир или убирает у первого лишние действия (вопрос М6). |
| Один мир | как сейчас |

## 7. Другие источники событий (решение)

**События шины мира остаются рассылкой всем подписчикам** (`WORLD_BUS.md` §3, утверждено). Стек их не трогает.

**Рекомендация:** в этом срезе через стек идёт **только ввод**.

Механизм общий: источник — это последовательность единиц с ключом, слои — потребители с правилами «забрать или пропустить». Поэтому позже его можно включить для отдельного типа событий шины, помеченного «поглощаемым» (`events().add<T>({ .consumable = true })`). Тогда подписчики этого типа идут в порядке стека, и первый, кто вернул «съел», останавливает доставку.

Почему не сейчас:
- у подписок шины нет порядка, кроме порядка подписки;
- поглощение потребовало бы связать подписку со слоем;
- для текущих сценариев (звук, HUD, конец клипа) нужна именно рассылка.

Вопрос М11.

## 9. Вопросы владельцу

Термины:
- **«Слой»** — ступень, через которую проходит ввод сверху вниз: меню, UI, игра. Каждая ступень может забрать часть себе.
- **«Мир»** — отдельная сцена уровня, например 3D-игра и UI поверх неё.

- **М1. Меню и модальные окна.** Меню паузы открыто → игра не получает ни клавиш, ни кликов, ни движения мыши, пока меню открыто (рекомендация)?
- **М2. Поле ввода.** В чате с фокусом блокируются буквы, цифры, стрелки, Backspace и цифровой блок, а Escape, Enter, Tab и F-клавиши проходят к игре (рекомендация)?
- **М3. UI по умолчанию.** UI без настроек забирает только клики и колесо над своими кнопками, клавиши уходят в игру. Наведение на кнопку HUD **не** останавливает обзор камерой (рекомендация)?
- **М4. Зажатая клавиша.** Вы держите «вперёд», открывается меню → игра видит отпускание. Меню закрыли, а вы всё держите → игра не видит нового нажатия, пока не нажмёте снова. Escape, открывший меню, его же сразу не закрывает (рекомендация)?
- **М5. Когда изменения вступают в силу.** Меню, открытое в этом кадре, начинает забирать ввод со следующего кадра; внутри кадра порядок не меняется (рекомендация)?
- **М6. Два игровых мира.** Без настроек действия получает первый мир в файле уровня, во втором перестают работать клавиши этих действий, и игра получает предупреждение. Игра сама включает и выключает миры (рекомендация). Или второй мир по умолчанию выключен?
- **М7. Слои из кода игры.** Игра сама открывает и закрывает слой «диалог» поверх своего мира (рекомендация)? Или слои задаются только в файле уровня?
- **М8. Набор текста.** Можно ли в этом срезе печатать текст в игровом UI? Рекомендация: нет, только блокировка клавиш; набор текста (символы, автоповтор, раскладки) — отдельная задача.
- **М9. Пауза редактора.** Пока редактор на паузе, открытое в игре меню продолжает забирать ввод (рекомендация)?
- **М10. Переключение во время игры.** Игра включает ввод мира мини-карты, когда карту открыли, и выключает, когда закрыли. Порядок слоёв тоже можно поменять из кода. Изменения — со следующего кадра (рекомендация)?
- **М11. Не только ввод.** Должны ли слои уметь «съедать» не только ввод, но и события игры (например, «удар» достаётся только щиту, а не персонажу за ним)? Рекомендация: в этом срезе нет, события игры по-прежнему получают все подписчики; механизм позволяет добавить это позже для отдельных типов событий.
- **М12. Порядок при равных слоях.** Если у двух миров одинаковый слой ввода, выше тот, что раньше в файле уровня, а не тот, что создан раньше (рекомендация)?
