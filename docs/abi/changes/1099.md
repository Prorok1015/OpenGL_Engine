#1099: platform::process_confinement replaces `container_name` (std::wstring) with `container`
(std::shared_ptr<const platform::app_container>), a new exported class that makes (or finds) the AppContainer profile
once and holds its SID; run_process adds read and execute on a `read_execute` path only when its access list lacks it. Neither type is
in gs::module_layout_key and no vtable changes: the layout key stays. A module that confines a child it starts must be
rebuilt against an engine with #1099.
core::res::remove_tree_without_following keeps its signature: on Windows it clears READONLY on an entry itself (never
through a reparse point) and removes paths past MAX_PATH.
