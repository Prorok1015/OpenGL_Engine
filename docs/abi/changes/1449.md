#1449: the engine's public descs enter gs::module_layout_key (layout_revision 30): rnd::material_desc, rnd::texture_desc,
scn::prefab_desc, world_desc, level_desc, object_desc, mesh_node_desc, camera_desc, directional_light_desc, screen_anchor_desc,
skybox_desc, input_actions_desc, bone_desc, skinning_desc, skin_weights_desc, animation_clip_desc, animation_collection_desc,
animation_controller_desc, animated_node_desc, scene_anchor_desc and desc::dynamic_desc.
Why: their constructors and copies are implicit or inline (desc_base's copy too), copy_to_same copies inline, schema_desc's
schema_generator builds a T{} and pin_resource<T> allocates in the caller, so a module can make or copy one with its own sizeof.
require/require_sync still hand out what the engine's factory allocated.
Container elements and inline members, and where their size is now seen:
- listed now: scn::animation_node with animation_pos_key and animation_rotate_key (animation_scale_key is the same type
  as pos_key) for animation_clip_desc::channels; scn::input_action_entry and input_binding_entry for
  input_actions_desc::actions; scn::input_stack_desc (world_desc::input_stack, also inside the optional's size).
- already listed: res::tag (material samplers_textures, camera targets, skin_weights/skinning tags), res_handle<int> (every
  res_handle<T> member: material shader, mesh_node geometry/material, skybox material, level worlds, collection clips),
  driver::texture_header (texture_desc::header), prefab_node/prefab_comp_node/comp_edit/override_record (prefab_desc::root),
  inp::gamepad_config (input_gamepad_settings), desc::dyn_blob and schema_binding (dynamic_desc), glm::mat4, boost::json::value.
- seen through the desc's own size: input_action_list and input_gamepad_settings (members by value), fixed_vector<res::tag, 4>,
  enums and scalars; std::string, std::uint32_t/uint64_t vectors need no entry.
gui::theme_desc enters edt::editor_layout_key (editor_layout_revision 3): an editor module includes gui (engine_api) and may
make or copy it; the game key cannot list it (snk::game does not link snk::gui) and a game module gets no gui service.
Left out: rnd::texture_2d_desc and texture_cubemap_desc (headers outside include/, not exported: a module cannot name them).
Rebuild modules.
