#1312: layout_revision 25: the accessors module code calls on rnd::render_system and its managers are exports instead
of inline code over their members, so a module no longer reads their layout:
- rnd::render_system (not an exported class): get_texture_manager, get_render_targets, add_render_pass,
  remove_render_pass, get_driver, set_/get_skinning_manager, set_/get_material_compiler and material_instances are new
  SNK_API members. remove_render_pass now removes every occurrence of the pass and does nothing for one that is not
  there (before: erase at std::remove's result, undefined for a missing pass);
- rnd::texture_manager: its constructor, on_owner_thread, generation, register_loader and unregister_loader are defined
  in the engine;
- rnd::material_instance_cache: size, compilations, a declared destructor and key::operator== are defined in the engine;
- rnd::skinning_manager is now an exported class (SNK_API); its constructor, destructor, register_weights, generation,
  version and index_builds are defined in the engine (build_indices was already out of line, but not exported).
rnd::texture_resolver (the base of texture_manager, whose binding() module code can call) is pinned:
texture_resolver_abi_revision (1) joins gs::module_layout_key. AbiInlineBoundaryTests covers the four headers. A module
built before #1312 is refused until it is rebuilt.
