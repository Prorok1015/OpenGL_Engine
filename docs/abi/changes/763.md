#763: new exports desc::migrations::rename/remove/set_default and desc::schema_migrations_problem (desc_migrations.h),
and the non-virtual overloads desc::desc_system::register_schema(type_schema, const json::array&),
scn::register_schema_component(..., const json::array&) and gs::module_context::register_component(type_schema,
const json::array&). The declarative steps cross into a module as a boost::json::array (Boost is pinned by its version in
gs::module_layout_key); the parsed step type stays inside the desc library, and desc::type_schema is not changed, so no
type in the layout key changes and the layout key stays. desc::desc_system, engine-created and only reached through a
reference by a module, gets one member appended at its end. A module that calls the new overloads needs an engine with
#763; an older module keeps working.
