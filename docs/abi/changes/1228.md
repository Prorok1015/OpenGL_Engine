#1228 (PR C): desc::desc_system::register_schema refuses a schema whose field key or read alias does not start with
'/', for a runtime schema and for a C++ one (register_desc reaches it); desc::bind_described asserts the same. No such
schema exists: parse_type_schema already refused a JSON key or alias without '/', and every C++ key() and alias() starts
with one. Before, such a key was read as one escaped object key by the override check of scn_prefab_desc and as a path by
desc_system and the editor; every reader now takes field.key and the aliases as JSON pointers. No signature, type or
layout changes: the module layout key, layout_revision and SNK_MODULE_API_VERSION stay. A module that built a schema in
C++ with such a key now has its registration refused (logged) instead of read two ways.
#1228 (PR B): desc::desc_system::register_schema(schema, migrations) also refuses declarative steps whose rename target or
set_default pointer, followed through the later steps (their renames carry it, their removals drop the check), reaches no
field of the schema the steps lead to, or whose default does not fit that field (check_override_object). No signature,
type or layout changes: the module layout key, layout_revision and SNK_MODULE_API_VERSION stay. A module whose steps put a
value where its schema has no field now has the component's registration refused (logged) instead of writing data the
current version drops.
