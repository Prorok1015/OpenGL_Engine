## Controller Decomposition

`editor_system` was split into 4 classes connected via `scene_document` and callbacks:

| Class | File | Responsibility |
|-------|------|----------------|
| `editor_system` | `controller/edt_editor_system.cpp/h` | Thin coordinator: init, panel wiring, camera, async orchestration |
| `scene_editor` | `controller/edt_scene_editor.cpp/h` | Entity CRUD (create/delete/duplicate/reparent), desc tree helpers, `serialize_and_push`, `sync_ecs_transforms_to_desc` |
| `level_controller` | `controller/edt_level_controller.cpp/h` | Level I/O: new/load/save/quicksave, `write_level_to_disk`, `populate_worlds_from_level`, templates |
| `world_controller` | `controller/edt_world_controller.cpp/h` | Multi-world: `switch_to_world`, `create_world` |

**Documents** (`include/snk/editor/edt_document.h`, `edt_document_manager.h`; `editor_context::documents()`): `document` has `id/kind/title/source/is_dirty/generation/can_save/save/save_as`. `document_manager` holds the one `scene_document` (owned by `editor_system`, the controllers are built on it) and at most one `prefab_document` preview: `scene()`, `active()`, `set_active(id)`, `open_prefab(tag)`, `preview()`, `close(id)` (the scene cannot be closed), `for_each`. It raises `document_opened/closed/activated`.

**`scene_document`** (`controller/edt_scene_document.h`) holds mutable state shared between controllers:
- Level identity: `editor_tag`, `level_tag`, `level_name`; the dirty flag is `is_dirty()` / `mark_clean()`
- Multi-world: `world_descs`, `world_names`, `worlds_systems_list`, `active_world_idx`
- `camera` (editor camera state, survives the world reload)

**`editor_services`** (`include/snk/editor/edt_editor_services.h`): `ctx_manager` (weak_ptr), `level_set()` (the `level` context set), `active_layer()` (the context manager's game layer) and the game services `descs()`, `resources()`, `assembler()`, `sfactory()` — the active layer's, else the `base_*` ones of the `app_data_storage`. Owned by `editor_system` (declared before the controllers, filled in `init()`); the controllers, `prefab_document`, `document_manager`, the override `view_cache`, the state commands and `editor_context` take it by reference. It lives as long as `editor_system`, not as long as a document. **Never keep a game service taken from it**: a game module replaces the game layer, so take them at the moment of use. Store and erase through `writable_resources()` (the base `resource_system`): a module's layer only writes under `memory://modules/<name>/`. The editor's own tools (model importer, asset exporter, icons, templates) stay on the base `desc_system`/`resource_system` of `editor_system`.

**Every edit ends in `scene_document::commit(label, mode)`**: it marks the document dirty, bumps `desc_generation`, pushes the descs into the level (`scene_editor::serialize_and_push`, installed by `scene_editor` through `set_pusher`) and emits `events.document_changed(id, generation)`. A push that finds no level emits nothing. `commit_mode::state_only` skips the push and the announcement (new level, new world: the contexts are already built; nothing was announced before either). **Undo history** (#141-#144, `snk/editor/edt_document_history.h` + `controller/edt_scene_history.h`, design in `docs/epics/editor/EPIC-15.md`): a push commit diffs the worlds against the last commit by node id and records one `history_change` (keys `node:<world>:<id>`) under `edit_origin()` (`edit_origin_scope` for an agent); `is_dirty()` = something unrecorded or not at the save point (`mark_clean()`); `undo()/redo()/rollback_group()` apply it and rebuild every world they changed (the active one through the pusher, others through `set_world_reloader` = `scene_editor::reload_world`; `set_before_history_apply` runs first: pointers into the worlds go stale). A change that only moved a node (positional) has the node's key but no copy of it, and only moves it; a rollback stops at a shared key or at `history_change::undo_conflict()` (a node someone put under a node the change created). `state_only`, a level load/reload/detach (`reset_history()`) are boundaries; the live transforms written back before a save are `rebase_history()`. An edit the diff cannot compare (a node without an id, an id twice) clears the history and stays dirty. `~editor_system` calls `document_manager::shutdown()` (closes the preview, drops the scene) because the context outlives the system. Never set the dirty flag or call `serialize_and_push` from an edit directly. Save / Save As go through `document::save()/save_as()` (handlers set by `editor_system`); the File menu and the exit prompt still go through `file_menu` and `dialog_service`.

**`prefab_document`** (`controller/edt_prefab_document.h`): read-only (`can_save()` false), opened with `document_manager::open_prefab`, owns the set `preview:<tag>` while open.

Controllers communicate via `std::function` callbacks set by `editor_system` during `init()`.

## Panels

| Panel | Header | Purpose |
|-------|--------|---------|
| `scene_hierarchy_panel` | `edt_scene_hierarchy_panel.h` | Prefab node tree + world tabs; callbacks for create/delete/rename/duplicate/reparent |
| `inspector_panel` | `edt_inspector_panel.h` | Component property editor; custom renderer from `inspector_registry`, else the UI generated from the desc schema (`edt_schema_inspector.h`), else generic JSON |
| `viewport_panel` | `edt_viewport_panel.h` | 3D view + transform gizmo + orientation gizmo; fires `on_transform_committed` |
| `game_view_panel` | `edt_game_view_panel.h` | "Game view" (View menu; `editor/show_game_view` opens it at startup): camera picker + image of the picked game camera; the cameras that draw into the picked camera's texture (the worlds of one set share it, `camera_redirector`) get the viewport, all other game cameras are switched off (logic in `edt_game_view_logic.h`, unit-tested) |
| `console_panel` | `edt_console_panel.h` | `add_log(level, msg)`, max 10K entries with 25% trim, counts per level, filter, clear |
| `problems_panel` | `edt_problems_panel.h` | "Problems" (open by default, docked with the console): table of `editor_context::problems()` (severity, file:line relative to the project root, message; notes in the row's tooltip, rows clipped with `ImGuiListClipper`), counts per severity as filters, "Copy" in the row's context menu |
| `blackboard_panel` | `edt_blackboard_panel.h` | "Blackboard" (View menu, closed by default): read-only table of the committed blackboard of a context set (key, value, type, writer) with a set picker and a key filter; the rows and the value text are `edt_blackboard_view.h` (no ImGui, unit-tested) |
| `asset_browser_panel` | `edt_asset_browser_panel.h` | Directory tree + file grid; drag-drop to viewport |
| `dockspace` | `edt_dockspace.h` | ImGui DockSpace + default layout; the menu bar is `draw_main_menu` (`edt_main_menu.h`) |
| `panel_base` | `edt_panel_base.h` | `render()` wraps ImGui::Begin/End; `virtual on_render()` |

All panels are `shared_ptr` members of `editor_system` and are registered in `editor_context::panels()` (`panel_registry`: id, title, `dock_slot`, `open_by_default`; registration order = render order = View menu order). `dockspace` calls `render_all()` each frame. Menu items and shortcuts are `editor_context::actions()` (`action_registry`); `file_menu::register_actions` adds the File items. Every action has `args_schema`/`result_schema` (JSON Schema subset, `snk/command/cmd_json_schema.h`) and runs through `action_registry::invoke(id, json)`; it never reads ImGui input - the menu click or shortcut runs `activate`, which collects arguments via `dialog_service` and then calls `invoke`. `add()` returns a RAII `registration` (keep it as long as the entry should exist). `action_registry` owns a `cmd::command_registry` (engine module `snk::command`: id, schemas, `enabled`, `invoke`) and keeps the editor-only part (label, menu, shortcut, `activate`) in a side table keyed by id; `commands()` is the engine registry. Edit menu (#145, `controller/edt_edit_menu.h`): `edit.undo` (Ctrl+Z) / `edit.redo` (Ctrl+Y; hidden `edit.redo_alt` Ctrl+Shift+Z) over `document_manager::active()` (`document::undo/redo/next_undo_entry`: label and origin; the result is `{applied, label?, origin?}`), labelled in the menu with the record ("Undo Rename node", " (agent)"), disabled while an ImGui item is active or a `dialog_service` dialog is pending; closing the prefab editor window by any means closes its preview document; `action_ui::dynamic_label` gives a live menu text and `yields_to_text_input` leaves the chord to a focused text field. File menu: Save Level (`file.save`, Ctrl+S) overwrites the level, or opens Save As if it has no path; Save Level As... (`file.save_as`, Ctrl+Shift+S) always asks for a path. The window's own close request (X, Alt+F4) is vetoed and goes through `file_menu::exit` (`attach_window_close`), so it asks about unsaved changes like File > Exit. In the editor that registry is the process-wide `cmd::command_registry` that `core_module` puts in `app_data_storage` (engine commands such as `log.read` are registered there; `editor_context` passes it to `action_registry(shared)`); `action_registry()` alone owns a private one (tests).

Services seen by scripts and agents (A2, `edt_service_commands.h`): `job_service` raises `editor_events::job_started/job_progress/job_finished` (progress is polled once per frame by `job_service::pump()` in the `editor_jobs` frame stage) and serves `job.list`, `job.get{id}`, `job.cancel{id}` (a `done` job started with `start_with_result` keeps the JSON its work returned as `job_info::result`: `job.get` shows it, `job_finished` carries it as its 4th argument; the kept results stay under `job_service::RESULT_BUDGET` (16 MiB serialized): the oldest are dropped first, the newest always stays, and a dropped one reads `result_dropped: true`); every `dialog_service` request has an id, a kind and an answer schema (`list()`), and `dialog.list` / `dialog.answer{id, answer}` resolve it through the same callback a click uses. The engine log is a ring journal (`engine::read_log_journal`, command `log.read`); `engine::add_log_sink` (base-only `<snk/common/logger/engine_log_sinks.h>`) returns an RAII handle (the console panel is one sink, `editor_system::m_log_sink`). `problem_list` (`edt_problem_list.h`, `editor_context::problems()`) holds the problems per source (`set(source, items)` replaces that source's set, `clear(source)`), raises `editor_events::problems_changed(source)` and serves `problems.list{source?, severity?}` (allowed to agents by id); `build_output_parser` (`game_build/edt_build_diagnostics.h`) turns build output lines into `problem`s.

**Building the game module** (#434, `game_build/edt_game_builder.h`): `game_builder` (created by `editor_system::init`, destroyed before the context) registers `build.game_module` (Build > Build Game, Ctrl+B; args `{configuration?: "debuggame"|"release"}`, result `{started, job}`; a second call while a build runs fails with `busy`; `risk = deny_by_default`, so `agent_may_use` keeps it from MCP agents: it runs the project's CMake code). Enabled only with a project open, `<root>/code/CMakePresets.json` present and the shared engine (`SNK_ENGINE_SHARED`). The job (`ds::lane::io`, `job.cancel`, Cancel or Esc in its non-modal progress window) finds the toolchain (`edt_toolchain.h`: Windows = vswhere -> `cmd /u /d /v:off /s /c call <vs>\VC\Auxiliary\Build\vcvars64.bat >nul 2>&1 && set` read raw (`process_options::raw_output`) as UTF-16LE, a path with `& | < > ^ % !` refused, + `VSLANG=1033`, cmake/ninja of VS unless on PATH; Linux = own environment + `LC_ALL=C`, cmake/ninja on PATH; cached per session, failures not), then runs `cmake --preset <preset>` and `cmake --build --preset <preset> [--parallel N] [--verbose]` in `<root>/code` with `SNAKE_SDK_DIR`; every line goes through `build_output_parser` into `problems()` source `build` (cleared at the start of a `dialog` build; a `problems_only` build replaces them only when it ends, so a restarted or cancelled background build leaves them as they were), ninja's `[n/m]` is the progress. A failure shows a message dialog; a cancel shows nothing. Processes run through an injected runner (`platform::run_process` by default), so the tests fake it. cfg: `build/sdk_dir` (else `<exe>/../lib/cmake/snake_sdk`, else `SNK_BUILD_TREE_SDK_DIR` = `<build>/snake_sdk`), `build/cmake`, `build/vs_path`, `build/vs_min_version` (17.14), `build/configuration` (debuggame). Per build everything comes from a `build_request` (`configuration`, `preset` (empty = configuration), `jobs` (0 = no `--parallel`), `priority` (`low` = `process_options::low_priority`: BELOW_NORMAL / nice 10 for the process group), `cancel_on_restart` (stops the running build and runs once it stopped, latest request only; else `busy`), `preemptible` (a background build: a request that is not preemptible stops it the same way instead of being `busy`; a preemptible request meeting the person's build, running or waiting, is `busy`; `building_preemptible()` / `is_manual_build_running()` tell the two apart), `verbosity`, `reload_after`, `report` (`dialog`; `problems_only`: no message dialog, the failure tail and the start/built lines at debug, problems as always), `show_progress` (false: opens no progress window, one already open stays)) given to `game_builder::start`; the action makes it with `make_manual_build_request` from `options.settings()` (read at every start; the editor loads `<root>/.snk/build.json`: `configuration`, `jobs_mode` auto|manual, `reload_after_build`, `build_before_play` (stored only), `log_verbosity` errors|normal|verbose, `live_enabled`, `live_quiet_ms` (3000, 0..600000), `live_jobs` (0 = auto, 0..1024); unknown keys kept by `merge_build_settings`, bad values warn and default), `options.preset_for` and `options.auto_jobs` (manual jobs, or no `auto_jobs`, = 0: the preset decides). `make_live_build_request` (#445, live mode): configuration as without an argument, `live_jobs` else min(2, `auto_jobs`) (at least 1), low priority, `cancel_on_restart`, settings' verbosity, `problems_only`, no progress window, `reload_after` false, `preemptible` (Build Game stops it: owner decision), fresh as manual. A build stopped for a restart finishes its job as `done`. Configuration: argument > build.json > cfg. Verbosity sets the level of the output tail on success (errors: none, normal: debug, verbose: info; a failure is always warn). After a successful build `options.events->game_module_built` gets `{module, path (absolute build/bin file that exists), configuration, job, reload}` per runtime module; never after a failure, cancel or restart. **Reloading the game module** (#435, `game_build/edt_game_reloader.h`): `game_reloader` registers `build.reload_game_module` (Build > Reload Game Module; args `{module?}`, result `{status, message}`; `deny_by_default` like the build; greyed out and refused only during the person's build (`options.building`); during a live build (`background_building`) the action stops it through `stop_background` and returns `{status: "queued"}`: the reload waits as the implicit `edt/reload_game_module/<module>` (`options.each_frame`, re-armed every UI frame while any build runs, since the stopping job may still write the file) and then runs once with the usual messages; a second click finds the id taken and adds nothing; live mode's start gate (`reload_pending`) holds the next live build until it has run; without `each_frame` it is refused while the job is stopping) and `editor_system` reloads on `game_module_built` (when `reload`) on the next UI frame. Both go through `core::project_module_host::reload` (put in the storage by `main`): the copy is checked next to the running module, then swapped; a failed build rolls back to the previous copy. Around the swap `module_swap_gate` (`controller/edt_module_swap_gate.h`; `editor_system` routes the game layer changes through `on_game_layer_change` and hands `hooks()` to the host) holds the level detached: it keeps its unsaved edits and is built once, in the new layer. A refused or rolled-back build is shown as a message. Rule of the module API: nothing of a module's image (an exception its code threw, an object, a string, a vtable) may outlive the unload of its library; `module_loader` copies a module exception's message while the code is loaded and throws the host's own `std::logic_error`. Presets (#444, `<snk/project/prj_cmake_presets.h>`): the editor never writes `code/CMakePresets.json`; per-user defines/jobs go to its own `user-<cfg>` presets in `code/CMakeUserPresets.json` as an edit list re-applied to the file read fresh at save (`save_user_presets`), keeping everything else. `preset_for` = `preset_for_configuration` (`user-<cfg>` when CMakeUserPresets.json has it; a broken file warns and gives `<cfg>`), `auto_jobs` = `estimate_jobs().jobs`. **Build Settings** (`build_settings_panel`, floating, closed by default; action `build.settings.open`, Build > Build Settings..., not a tool): team defines of CMakePresets.json read-only, the user's defines and jobs (Manual: `jobs` of every `user-<cfg>` build preset) in CMakeUserPresets.json, default configuration, module reload, log verbosity; `build_before_play` hidden until Play exists. All state is `build_settings_model` (load / queued edits validated by `check_user_define` / `dirty`, `revert`, `pending_files`, `changed_on_disk` / `apply`: build.json first via `update_build_settings` (only the edited fields, merged onto the file as it is now; a broken build.json is never overwritten), then the user presets via `save_user_presets`; atomic writes through `prj::write_text_atomically`, or the `set_writer` fake in tests). While the person's build runs (`set_building` = `is_manual_build_running`) a define cannot be removed nor a removal applied: that build's configure would clear the new mark. A live build is stopped instead: `apply` calls `set_stop_background` (`editor_system::stop_live_build` = `game_builder::stop_background`) before it writes a mark, and live mode builds again by itself; a build still configuring meanwhile (e.g. the live one stopping while the person's waits) cannot clear the newer mark either, thanks to `fresh_generation`. A mark cleared on disk is taken over silently (`refresh_fresh_configure`). Removing a user define of `<cfg>` adds `<cfg>` to build.json `fresh_configure` (CMakeCache.txt keeps a removed define, and `user-<cfg>` shares the build tree): the next build configures with `cmake --preset <p> --fresh` (`build_request::fresh`), and `options.on_fresh_configured` (wired to `clear_fresh_configure`) drops it after a configure step that succeeded, unless the mark was written again since that build's request was made: every mark bumps build.json `fresh_generation` (left out while 0, old files read 0), the request carries the value it was made with (`build_request::fresh_generation`), and `clear_fresh_configure(dir, cfg, generation)` clears only while it is unchanged. `game_builder::stop_background()` stops only a running preemptible build, through the restart stop source rather than `job.cancel`: its on_done still runs (outcome `preempted`; a stopped build reports no configure, so its `--fresh` mark stays: one extra fresh configure, never a lost mark), a waiting live restart is dropped (told `preempted`), a waiting request of the person's stays and starts; nothing when no preemptible build runs. The editor never stops a live build with `cancel()`, which would drop that waiting request and give live mode no outcome. Agents read the same files through `build.settings.get` (incl. `live: {enabled, quiet_ms, jobs}`; read-only, allowed by id; `no_project` without a project); there is no set.

**Version control** (#454, `vcs/edt_vcs_service.h`): `vcs_service` (created by `editor_system::init` with `context.jobs()` and the project root) finds git at start (cfg `vcs/git`, else `git`/`git.exe` on PATH; `git --version`) and the repository (`git rev-parse --show-toplevel` from the project root, cached per project root). Both probes run on the main thread with a hard timeout (`vcs_options::probe_timeout`, 5 s: a `std::jthread` watchdog stops git; then `vcs_unavailable`, "git did not answer within 5 s", WARN). Without git, a project or a repository it is unavailable with a reason and `code` `vcs_unavailable` / `no_project` / what git said (`not_a_repository`, ...); the editor keeps running. Only `vcs_unavailable` and `no_project` make the commands refuse at once; anything git reports (a folder that is not a repository included) comes back as the job's result. **Live mode** (#445, `game_build/edt_live_build.h`): `live_build` is a pure state machine over `live_build_deps` (`now`, `settings`, `make_request` = `make_live_build_request`, `start_build`/`is_building` = the `game_builder`, `stop_background` = `game_builder::stop_background`, `reload(module, done)` = `game_reloader::reload_quiet` asked for on the next UI frame like #435 (never inside `tick`: only there is the module swap safe), `is_loaded_current` = `core::project_module_host::is_current` (the running copy was made from the build/bin file as it is now: same file, size, write time), `modules` = the project's runtime modules, `reload_pending` = an implicit module reload waits for the UI stage) and the `problem_list`. Inputs: `set_enabled` (off stops a running live build through `stop_background`, never the person's, and a manual request waiting for it stays queued), `on_changes(span<source_change{path, relevant}>)` (ignored when off or without a relevant change), `tick()` every frame (requests the reloads, never in the job pump), `rebuild_now()` (no debounce), `reload_now()` -> `{requested|up_to_date|refused, message}` (no quiet period; the modules of the last successful live build, else `modules`; only those not `is_loaded_current`; none: `up_to_date` "up to date", no swap; refused when off, while a build runs or reloads wait). A change starts a build `k_debounce` (500 ms) after the last one; a change during a build restarts it (`cancel_on_restart`). The result comes through `build_request::on_finished(build_outcome{succeeded|failed|restarted, job, errors, warnings, modules, message})`, called by `game_builder` on the main thread in `finish` (not for `job.cancel`: `is_building` false with no outcome = cancelled -> `idle`; never judge a build by `job_finished`, a restarted one ends `done`). Success with no change since the start: `settling` until `now - last_change >= live_quiet_ms`, then each produced module that is not current is requested (none: `reloaded` "up to date") and the state stays `reloading` until all have reported; a reload not taken -> `reload_failed` plus Problems source `reload` (warning for refused, else error), cleared by the next successful reload. A late result (a change, build or newer request came after it) still updates Problems unless a newer round finished, but never moves the state; a change during `reloading` debounces into a build as in `settling`. A start refused with `busy` (the person's build) stays `pending`; other refusals -> `errors`, warned once per message. No live build starts in the tick in which any build was seen to end (that frame's UI stage may run #435's reload, which a running build would refuse) nor while `reload_pending`; `rebuild_now` then queues. The person's build preempts a live one (`build_request::preemptible`): its outcome `preempted` (also when the editor stops it: Reload, a define removal) keeps the changes dirty, `pending` "waiting for the running build", and live mode builds again after the manual build. A live restart that waited and was then refused comes as `failed` with `not_started`: `errors` with the reason, changes kept (one more start, refused the ordinary way, then it waits for the next change). `live_quiet_ms` is re-read from the settings while settling (at most every 200 ms), so a lower value takes effect at once. `on_manual_build_succeeded()` turns `errors` into `idle` "manual build succeeded" and clears the counts. States: off, idle, pending, building, errors, settling, reloading, reloaded, reload_failed; `status()` = `{state, errors, warnings, configuration, job, last_build_end, last_reload, message}`.

```
  → scene_document::commit("Move entity")
```

The editor never finds nodes by name (names are display only): hierarchy, viewport and `scene_editor` pass `node_id`s / id paths. Inspector edits of a node inside a prefab instance go through `edt_override_edit.h` (records on the instance node; "Reset to base" drops them).

**ECS → Desc** (called before save): `scene_editor::sync_ecs_transforms_to_desc()` reads `local_transform` of entities with a `node_id_component`, resolves the path, and writes back to the (non-instanced) desc nodes.

## Level JSON Schema

```json
{
  "worlds": [
    {
      "name": "World0",
      "prefab_desc": { /* prefab_node tree */ },
      "systems": ["SystemA", "SystemB"]
    }
  ]
}
```

`level_controller::build_level_json()` is the single source of truth. `level_controller::populate_worlds_from_level()` reconstructs `scene_document::world_descs` on load.

## Multi-World

- `scene_document::world_descs` — vector, indexed by `active_world_idx`
- `scene_document::active_world_desc()` / `active_world_name()` — pointers, null when the level has no worlds (`active_world_idx = -1`, arrays empty; `world_controller::clear_active_world()`). Never index `world_descs[active_world_idx]` directly.
- Hierarchy panel shows a tab per world; switching calls `world_controller::switch_to_world(idx)` which saves editor camera, tears down old registry, rebuilds new one
- `scene_document::worlds_systems_list` — per-world list of system names (parallel to `world_descs`)

**Single source of truth for world order (critical invariant):** the three parallel
`scene_document` arrays (`world_descs` / `world_names` / `worlds_systems_list`) MUST be
built from the same ordered source — the desc-ordered world list. Do NOT build them by
iterating `scn::context_set::for_each`: it walks the contexts by **context id**, which fills
gaps left by removed worlds and so is not desc/insertion order, so with >=2 worlds the parallel arrays desync. Derive names and
per-world systems via `edt::derive_world_arrays` (`controller/edt_level_controller.h`), and
keep `populate_worlds_from_level` as the single build point on load. Covered by
`tests/edt_world_array_sync_tests.cpp`.

**Hot reload:** `scn::context_manager` drops/rebuilds only the `kind==level` contexts of the set `"level"`, so worlds created in the
editor but not yet saved survive. After every reload (world list or systems only) it calls `level_controller::resync_worlds_after_reload()`
(`merge_reloaded_worlds` + `derive_world_arrays`), which keeps the arrays aligned with the level. A reload
whose world desc fails to load is skipped entirely (current level kept, no callback).

## Prefab Node Format (critical)

```
prefab_desc::prefab_node {
  name, position, rotation(Euler deg), scale
  components: unordered_map<string, prefab_comp_node>
  children: vector<prefab_node>
}
prefab_comp_node { type_name, parent_desc, overrides(json::object) }
```

- `children` serialized as a JSON **array** of nodes `{ "__id", "name", "transform", "components", "children" }` (format v2; v1 keyed them by name and is migrated on load)
- `components` key = type_name (e.g. `"mesh_node_desc"`, `"bone_desc"`)
- `rotation` stores Euler degrees: `x=pitch, y=yaw, z=roll`; reconstructed via `yawPitchRoll(y,x,z)`

## Model Import Pipeline

Models (`.glb`, `.obj`, `.fbx`, `.gltf`) are loaded via `scn::model_importer_adapter` (only with `SNK_WITH_ASSIMP=ON`; with OFF there is no adapter, "Import Model" is disabled and loading such a file fails with a "No adapter found" log):
- Outputs `prefab_desc` (not legacy prototype)
- Geometry stored at `memory://path/name.geom.desc` (separate resource)
- Mesh nodes → `mesh_node_desc` components referencing geometry by tag
- Skinning → `skinning_desc` + bone weights registered with `rnd::skinning_manager`
- Bone nodes → `bone_desc` components with offset matrix + global index
- Animations → `animations_desc` on root, `keyframes_desc` on each animated node

Import in editor: File menu → `dialog_service::pick_file` → `editor_system::start_import` → async import → export dialog → auto-add to scene.

## Viewport & Gizmo

- Viewport shows the editor camera texture (`__editor_camera_rt`); game cameras (no color target = backbuffer) are redirected to their own textures by the `editor_redirect_cameras` stage (before `extract`)
- `ImTextureID` obtained via the injected `gui::gui_system&` (from `app_data_storage`, no global accessor): `gui.get_backend_interface()->to_imgui(handle)` with a `texture_handle` (`texture_manager::binding(id_of(tag)).handle` or `render_targets::registry::current(tag)`)
- Gizmo modes: Translate / Rotate / Scale (keyboard shortcuts T/R/S)
- Transform committed only on gizmo release (not every frame)
- `edt_transform_gizmo.hpp` — pure ImGui DrawList implementation, no external gizmo lib

## Headless (#452)

`editor --headless --project <dir>`: no display, no GPU, no panels (CI step "Headless run (no display)" in `editor-smoke`; `tools/run_headless.sh` is the separate Xvfb path for screenshots).
- `--headless` sets `editor/headless`, `app/non_interactive`, `project/required` (no `--project` → exit 2, like any project error), `window/system=null` (`wnd::null_window_system`) and `render/backend=null`; `gui_init` picks `gui::null_imgui_backend` for a window without a GL surface.
- `main` scans argv for `--headless`/`--mcp-stdio` before `init_logger`: the console log goes to **stderr**, stdout stays empty for a protocol. `--help` still prints to stdout.
- The `ui` stage does not draw panels: it runs only the implicit callbacks (`editor_system::run_implicit_callbacks`) inside `gui_system::run_without_drawing` (a CPU-only ImGui frame). They must keep running: the startup level load, `next_frame` work (module reload), progress windows and dialogs live there and use ImGui. A dialog that waits for an answer waits forever in headless (later: `unavailable_headless`).
- The panels never run: nothing sizes the editor/game camera targets by a panel or binds input, so `viewport.capture` may have nothing to read.
- `app/exit_after_frames N` (core, any host): the loop stops after N frames with exit code 0 — a smoke-test hook.
- A successful level load logs `level loaded: <tag>` (`Editor/LoadLevel`); `editor/exit_after_level_loaded` stops the loop right after it (exit 0). CI uses it with `app/exit_after_frames` as the cap, so a level that never loads fails the step.
- Until dialogs fail fast in headless, a dialog that comes on screen logs a WARN (`editor/dialog`): only MCP `dialog.answer` can answer it.
- Options are parsed without abbreviations (`allow_guessing` off): `--head` is an error, not `--headless`.

## Common Pitfalls

- **EnTT `registry::each()` does not exist** — use `registry.storage<entt::entity>()` to iterate all entities
- **EnTT forward declare** — use `#include <entt/fwd.hpp>`, not `namespace entt { class registry; }`
- **Input routing**: ECS input is routed by `inp::input_router`; a panel binds its hovered image every frame (`bind_item_input`), the context under the cursor gets the full `inp::input_state`, all others a neutral one. Never set `inp::input_focus` by hand
- **Edits go through `scene_document::commit()`**, which calls `serialize_and_push()` - destructive — tears down and rebuilds the entire ECS world; don't hold raw pointers to registry components across it
- **Camera state**: `scene_editor::on_save_camera` runs before the push and `on_inject_camera` after (state in `scene_document::camera`) — otherwise camera resets
- **Memory resources**: `memory://` protocol stores resources at runtime; `res://` resolves from filesystem via `resource.path`
- **`get_field_desc<T>` with inline objects** requires `__type` field present in the JSON object
- **`children` is a JSON array of named nodes (v2)** — iterate via `as_array()`; a v1 object is only valid before `migrate_tree`
- **No C functions** — prefer `std::format_to_n` over `snprintf`/`strncpy`, C++ alternatives over C stdlib
