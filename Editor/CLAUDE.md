## Controller Decomposition

`editor_system` was split into 4 classes connected via `scene_document` and callbacks:

| Class | File | Responsibility |
|-------|------|----------------|
| `editor_system` | `controller/edt_editor_system.cpp/h` | Thin coordinator: init, panel wiring, camera, async orchestration |
| `scene_editor` | `controller/edt_scene_editor.cpp/h` | Entity CRUD (create/delete/duplicate/reparent), desc tree helpers, `serialize_and_push`, `sync_ecs_transforms_to_desc` |
| `level_controller` | `controller/edt_level_controller.cpp/h` | Level I/O: new/load/save/quicksave, `write_level_to_disk`, `populate_worlds_from_level`, templates |
| `world_controller` | `controller/edt_world_controller.cpp/h` | Multi-world: `switch_to_world`, `create_world` |

**Documents** (`include/snk/editor/edt_document.h`, `edt_document_manager.h`; `editor_context::documents()`): `document` has `id/kind/title/source/is_dirty/generation/can_save/save/save_as`. `document_manager` holds the one `scene_document` (owned by `editor_system`, the controllers are built on it) and at most one `prefab_document` preview: `scene()`, `active()`, `set_active(id)`, `open_prefab(tag)`, `preview()`, `close(id)` (the scene cannot be closed), `for_each`. It raises `document_opened/closed/activated`.

**`scene_document`** (`controller/edt_scene_document.h`) holds mutable state shared between controllers:
- Level identity: `editor_tag`, `level_tag`, `level_name`; the dirty flag is `is_dirty()` / `mark_clean()`
- Multi-world: `world_descs`, `world_names`, `worlds_systems_list`, `active_world_idx`
- `camera` (editor camera state, survives the world reload)

**`editor_services`** (`include/snk/editor/edt_editor_services.h`): `ctx_manager` (weak_ptr), `level_set()` (the `level` context set), `active_layer()` (the context manager's game layer) and the game services `descs()`, `resources()`, `assembler()`, `sfactory()` — the active layer's, else the `base_*` ones of the `app_data_storage`. Owned by `editor_system` (declared before the controllers, filled in `init()`); the controllers, `prefab_document`, `document_manager`, the override `view_cache`, the state commands and `editor_context` take it by reference. It lives as long as `editor_system`, not as long as a document. **Never keep a game service taken from it**: a game module replaces the game layer, so take them at the moment of use. Store and erase through `writable_resources()` (the base `resource_system`): a module's layer only writes under `memory://modules/<name>/`. The editor's own tools (model importer, asset exporter, icons, templates) stay on the base `desc_system`/`resource_system` of `editor_system`.

**Every edit ends in `scene_document::commit(label, mode)`**: it marks the document dirty, bumps `desc_generation`, pushes the descs into the level (`scene_editor::serialize_and_push`, installed by `scene_editor` through `set_pusher`) and emits `events.document_changed(id, generation)`. A push that finds no level emits nothing. `commit_mode::state_only` skips the push and the announcement (new level, new world: the contexts are already built; nothing was announced before either). **Undo history** (#141-#144, `snk/editor/edt_document_history.h` + `controller/edt_scene_history.h`, design in `docs/epics/editor/EPIC-15.md`): a push commit diffs the worlds against the last commit by node id and records one `history_change` (keys `node:<world>:<id>`) under `edit_origin()` (`edit_origin_scope` for an agent); `is_dirty()` = something unrecorded or not at the save point (`mark_clean()`); `undo()/redo()/rollback_group()` apply it and rebuild every world they changed (the active one through the pusher, others through `set_world_reloader` = `scene_editor::reload_world`; `set_before_history_apply` runs first: pointers into the worlds go stale). A change that only moved a node (positional) has the node's key but no copy of it, and only moves it; a rollback stops at a shared key or at `history_change::undo_conflict()` (a node someone put under a node the change created). `state_only`, a level load/reload/detach (`reset_history()`) are boundaries; the live transforms written back before a save are `rebase_history()`. An edit the diff cannot compare (a node without an id, an id twice) clears the history and stays dirty. `~editor_system` calls `document_manager::shutdown()` (closes the preview, drops the scene) because the context outlives the system. Never set the dirty flag or call `serialize_and_push` from an edit directly. Save / Save As go through `document::save()/save_as()` (handlers set by `editor_system`); the File menu and the exit prompt still go through `file_menu` and `dialog_service`.

**`prefab_document`** (`controller/edt_prefab_document.h`): read-only (`can_save()` false), opened with `document_manager::open_prefab`, owns the set `preview:<tag>` while open.

Controllers communicate via `std::function` callbacks set by `editor_system` during `init()`.

| `git_panel` | `edt_git_panel.h` | "Git" (View menu, closed by default, #456): branch, upstream ahead/behind, Refresh/Fetch/Pull/Push ("running..." + a progress bar of the write's `job_progress` (`git_panel_model::busy_progress`, cleared when it ends) + Cancel), staged/changes/untracked with stage checkboxes, commit message + Commit, branch combo (switch asks first when there are changes) + create, diff of the selected file through `ImGuiListClipper`. Only draws `git_panel_model`, which runs every action as a `vcs.*` command (`action_registry::invoke`, origin ui) and takes the results from `job_finished`; git errors are `vcs` warnings and a line in the panel. Reads nothing while hidden; a code:// or res:// change (`res://` reports changes, #515) refreshes it 1 s after the last one, `editor_events::repository_changed` (#485, see the watcher in Version control) 250 ms after the last one (`k_repo_delay`); hidden, either only marks it stale and it refreshes when shown; `refs` also reloads the History tab (`git_panel_model::refs_changed`). An untracked file shows no diff. Tab History (#457): `vcs::history_model` (read only while the tab is shown, reloaded after every write of the panel: `git_panel_model::writes_finished`) in a clipped table (graph from `commit_graph` drawn with `vcs::row_segments` of `edt_history_view.h`, ref labels, subject, author, age), every branch, remote branch and tag (or one branch), author and message filters, the selected commit's files and a file's diff against the first parent (`history_ports_of` in `edt_git_panel_model.h` turns `history_model::ports::extended_reads` on; covered end to end by `RealRepository_TheHistoryTab_ReadsEveryBranch_FiltersAndShowsACommitsFilesAndDiff`), Copy hash |
| `asset_browser_panel` | `edt_asset_browser_panel.h` | Directory tree + file grid; drag-drop to viewport |
| `dockspace` | `edt_dockspace.h` | ImGui DockSpace + default layout; the menu bar is `draw_main_menu` (`edt_main_menu.h`) |
| `panel_base` | `edt_panel_base.h` | `render()` wraps ImGui::Begin/End; `virtual on_render()` |

All panels are `shared_ptr` members of `editor_system` and are registered in `editor_context::panels()` (`panel_registry`: id, title, `dock_slot`, `open_by_default`; registration order = render order = View menu order). `dockspace` calls `render_all()` each frame. Menu items and shortcuts are `editor_context::actions()` (`action_registry`); `file_menu::register_actions` adds the File items. Every action has `args_schema`/`result_schema` (JSON Schema subset, `snk/command/cmd_json_schema.h`) and runs through `action_registry::invoke(id, json)`; it never reads ImGui input - the menu click or shortcut runs `activate`, which collects arguments via `dialog_service` and then calls `invoke`. `add()` returns a RAII `registration` (keep it as long as the entry should exist). `action_registry` owns a `cmd::command_registry` (engine module `snk::command`: id, schemas, `enabled`, `invoke`) and keeps the editor-only part (label, menu, shortcut, `activate`) in a side table keyed by id; `commands()` is the engine registry. Edit menu (#145, `controller/edt_edit_menu.h`): `edit.undo` (Ctrl+Z) / `edit.redo` (Ctrl+Y; hidden `edit.redo_alt` Ctrl+Shift+Z) over `document_manager::active()` (`document::undo/redo/next_undo_entry`: label and origin; the result is `{applied, label?, origin?}`), labelled in the menu with the record ("Undo Rename node", " (agent)"), disabled while an ImGui item is active or a `dialog_service` dialog is pending; closing the prefab editor window by any means closes its preview document; `action_ui::dynamic_label` gives a live menu text and `yields_to_text_input` leaves the chord to a focused text field. File menu: Save Level (`file.save`, Ctrl+S) overwrites the level, or opens Save As if it has no path; Save Level As... (`file.save_as`, Ctrl+Shift+S) always asks for a path. The window's own close request (X, Alt+F4) is vetoed and goes through `file_menu::exit` (`attach_window_close`), so it asks about unsaved changes like File > Exit. In the editor that registry is the process-wide `cmd::command_registry` that `core_module` puts in `app_data_storage` (engine commands such as `log.read` are registered there; `editor_context` passes it to `action_registry(shared)`); `action_registry()` alone owns a private one (tests).

Services seen by scripts and agents (A2, `edt_service_commands.h`): `job_service` raises `editor_events::job_started/job_progress/job_finished` (progress is polled once per frame by `job_service::pump()` in the `editor_jobs` frame stage) and serves `job.list`, `job.get{id}`, `job.cancel{id}` (a `done` job started with `start_with_result` keeps the JSON its work returned as `job_info::result`: `job.get` shows it, `job_finished` carries it as its 4th argument; the kept results stay under `job_service::RESULT_BUDGET` (16 MiB serialized): the oldest are dropped first, the newest always stays, and a dropped one reads `result_dropped: true`); every `dialog_service` request has an id, a kind and an answer schema (`list()`), and `dialog.list` / `dialog.answer{id, answer}` resolve it through the same callback a click uses. The engine log is a ring journal (`engine::read_log_journal`, command `log.read`); `engine::add_log_sink` (base-only `<snk/common/logger/engine_log_sinks.h>`) returns an RAII handle (the console panel is one sink, `editor_system::m_log_sink`). `problem_list` (`edt_problem_list.h`, `editor_context::problems()`) holds the problems per source (`set(source, items)` replaces that source's set, `clear(source)`), raises `editor_events::problems_changed(source)` and serves `problems.list{source?, severity?}` (category `read`); `build_output_parser` (`game_build/edt_build_diagnostics.h`) turns build output lines into `problem`s.

**Building the game module** (#434, `game_build/edt_game_builder.h`): `game_builder` (created by `editor_system::init`, destroyed before the context) registers `build.game_module` (Build > Build Game, Ctrl+B; args `{configuration?: "debuggame"|"release"}`, result `{started, job}`; a second call while a build runs fails with `busy`; `risk = deny_by_default`, so the agent policy keeps it at `deny` until a per-command entry in the project's `.snk/agent_policy.json` says otherwise: it runs the project's CMake code). Enabled only with a project open, `<root>/code/CMakePresets.json` present and the shared engine (`SNK_ENGINE_SHARED`). The job (`ds::lane::io`, `job.cancel`, Cancel or Esc in its non-modal progress window) finds the toolchain (`edt_toolchain.h`: Windows = vswhere -> `cmd /u /d /v:off /s /c call <vs>\VC\Auxiliary\Build\vcvars64.bat >nul 2>&1 && set` read raw (`process_options::raw_output`) as UTF-16LE, a path with `& | < > ^ % !` refused, + `VSLANG=1033`, cmake/ninja of VS unless on PATH; Linux = own environment + `LC_ALL=C`, cmake/ninja on PATH; cached per session, failures not), then runs `cmake --preset <preset>` and `cmake --build --preset <preset> [--parallel N] [--verbose]` in `<root>/code` with `SNAKE_SDK_DIR`; every line goes through `build_output_parser` into `problems()` source `build` (cleared at the start of a `dialog` build; a `problems_only` build replaces them only when it ends, so a restarted or cancelled background build leaves them as they were), ninja's `[n/m]` is the progress. A failure shows a message dialog; a cancel shows nothing. Processes run through an injected runner (`platform::run_process` by default), so the tests fake it. cfg: `build/sdk_dir` (else `<exe>/../lib/cmake/snake_sdk`, else `SNK_BUILD_TREE_SDK_DIR` = `<build>/snake_sdk`), `build/cmake`, `build/vs_path`, `build/vs_min_version` (17.14), `build/configuration` (debuggame). Per build everything comes from a `build_request` (`configuration`, `preset` (empty = configuration), `jobs` (0 = no `--parallel`), `priority` (`low` = `process_options::low_priority`: BELOW_NORMAL / nice 10 for the process group), `cancel_on_restart` (stops the running build and runs once it stopped, latest request only; else `busy`), `preemptible` (a background build: a request that is not preemptible stops it the same way instead of being `busy`; a preemptible request meeting the person's build, running or waiting, is `busy`; `building_preemptible()` / `is_manual_build_running()` tell the two apart), `verbosity`, `reload_after`, `report` (`dialog`; `problems_only`: no message dialog, the failure tail and the start/built lines at debug, problems as always), `show_progress` (false: opens no progress window, one already open stays)) given to `game_builder::start`; the action makes it with `make_manual_build_request` from `options.settings()` (read at every start; the editor loads `<root>/.snk/build.json`: `configuration`, `jobs_mode` auto|manual, `reload_after_build`, `build_before_play` (stored only), `log_verbosity` errors|normal|verbose, `live_enabled`, `live_quiet_ms` (3000, 0..600000), `live_jobs` (0 = auto, 0..1024); unknown keys kept by `merge_build_settings`, bad values warn and default), `options.preset_for` and `options.auto_jobs` (manual jobs, or no `auto_jobs`, = 0: the preset decides). `make_live_build_request` (#445, live mode): configuration as without an argument, `live_jobs` else min(2, `auto_jobs`) (at least 1), low priority, `cancel_on_restart`, settings' verbosity, `problems_only`, no progress window, `reload_after` false, `preemptible` (Build Game stops it: owner decision), fresh as manual. A build stopped for a restart finishes its job as `done`. Configuration: argument > build.json > cfg. Verbosity sets the level of the output tail on success (errors: none, normal: debug, verbose: info; a failure is always warn). After a successful build `options.events->game_module_built` gets `{module, path (absolute build/bin file that exists), configuration, job, reload}` per runtime module; never after a failure, cancel or restart. **Reloading the game module** (#435, `game_build/edt_game_reloader.h`): `game_reloader` registers `build.reload_game_module` (Build > Reload Game Module; args `{module?}`, result `{status, message}`; `deny_by_default` like the build; greyed out and refused only during the person's build (`options.building`); during a live build (`background_building`) the action stops it through `stop_background` and returns `{status: "queued"}`: the reload waits as the implicit `edt/reload_game_module/<module>` (`options.each_frame`, re-armed every UI frame while any build runs, since the stopping job may still write the file) and then runs once with the usual messages; a second click finds the id taken and adds nothing; live mode's start gate (`reload_pending`) holds the next live build until it has run; without `each_frame` it is refused while the job is stopping) and `editor_system` reloads on `game_module_built` (when `reload`) on the next UI frame. Both go through `core::project_module_host::reload` (put in the storage by `main`): the copy is checked next to the running module, then swapped; a failed build rolls back to the previous copy. Around the swap `module_swap_gate` (`controller/edt_module_swap_gate.h`; `editor_system` routes the game layer changes through `on_game_layer_change` and hands `hooks()` to the host) holds the level detached: it keeps its unsaved edits and is built once, in the new layer. A refused or rolled-back build is shown as a message. Rule of the module API: nothing of a module's image (an exception its code threw, an object, a string, a vtable) may outlive the unload of its library; `module_loader` copies a module exception's message while the code is loaded and throws the host's own `std::logic_error`. Presets (#444, `<snk/project/prj_cmake_presets.h>`): the editor never writes `code/CMakePresets.json`; per-user defines/jobs go to its own `user-<cfg>` presets in `code/CMakeUserPresets.json` as an edit list re-applied to the file read fresh at save (`save_user_presets`), keeping everything else. `preset_for` = `preset_for_configuration` (`user-<cfg>` when CMakeUserPresets.json has it; a broken file warns and gives `<cfg>`), `auto_jobs` = `estimate_jobs().jobs`. **Build Settings** (`build_settings_panel`, floating, closed by default; action `build.settings.open`, Build > Build Settings..., not a tool): team defines of CMakePresets.json read-only, the user's defines and jobs (Manual: `jobs` of every `user-<cfg>` build preset) in CMakeUserPresets.json, default configuration, module reload, log verbosity; `build_before_play` hidden until Play exists. **Repository watcher** (#485, `vcs/edt_repository_watcher.h`, no ImGui): `editor_system` creates it after `m_vcs` and ticks it in the `editor_vcs` frame stage (after `editor_live`). Each frame `repository_watcher::follow(vcs_service&)` compares `vcs_service::state_generation()` (moved by every probe) and only then re-arms from `cached_state()` + `probed_project()` (`set_paths(git_dir, common_dir, root, project root)`, no event; the same paths again keep the baseline; off without a repository or without both folders, and off while `vcs_service::current_project()` (the project-root function, no probe) differs from `probed_project()`: a switch nothing has probed yet; the next probe arms it, a switch back re-arms from the cached state). It never calls `info()`, so it never probes: it follows whatever probed (the constructor, `vcs.info`, the Git panel's refresh, any `vcs.*` command); a closed panel needs no events and refreshes when shown. At most every 500 ms it compares (write time, size, existence) of: `index` kind = `<git_dir>/index` and the top-level files (not folders, not `.git`) of the repository root and of the project root; `refs` kind = `<git_dir>/HEAD`, `FETCH_HEAD`, `ORIG_HEAD`, `MERGE_HEAD`, `<common_dir>/packed-refs` and every file under `<common_dir>/refs/` (never objects/ or logs/). The editor writes nothing there that would churn: its log goes to the `logs/` folder (`engine.log`) and ImGui's ini is off (`io.IniFilename = nullptr`). Past 4096 entries under refs/ it watches only the folders under refs/ at once; a walk over 2 ms (checked every 64 entries and after each folder) is given up (the refs/ files are not compared that poll, HEAD and the other fixed files still are) and 3 such walks in a row switch too; one WARN, until re-armed; the poll that switches, and the first walk that finishes after given-up ones, have nothing to compare with and report `refs` once (a possibly spurious refresh rather than a lost one); a new branch folder or a ref added or renamed into a folder still shows. Git is never run; each poll gives each kind at most once and `editor_system` raises `editor_events::repository_changed(repository_change::index|refs)`. The editor's own **writes** (every `vcs_service` write job: the panel's and agents') do not raise `index`; reads pass `--no-optional-locks` and never touch the index, so an outside `git add` during a panel read is still reported. `vcs_service::set_write_observer` calls `begin_own_write` on the main thread before each write job starts (an index change seen then is someone else's and is still reported), the write jobs count themselves in `running_writes()` (atomic, down when a job ends or is dropped unrun), and the tick that finds the count back at 0 takes the index and top-level files as they are; so a write that starts and ends between two ticks is covered too. `refs` is never suppressed. Every refs change moves `git_panel_model::refs_changed()`, the panel's own writes included (owner decision: one extra History reload after the panel's commit rather than a lost one). Ports (`now`, `stat_file`, `list_dir`, `own_writes_running`) are faked in `edt_repository_watcher_tests.cpp`; `RealRepository_TheWatcher_SeesACommitAndACheckoutMadeOutsideTheEditor`, `RealRepository_AnIndexChangeDuringARead_IsReported_DuringAWrite_IsNot` and `TheWatcher_FollowsTheCachedStateWithoutProbing_AndReArmsAfterAProbeOfANewProject` run it with the service.

**Agent policy for git** (#455, `vcs/edt_vcs_policy.h`, `core/edt_agent_policy.h`): the categories `vcs_read`, `vcs_commit`, `vcs_branch`, `vcs_sync`, `vcs_push` are `allow` by default and can be set in `categories` like any other; what a guarded write may touch is held by **hard rules** that apply under any mode. The policy file (both layers) takes an optional section `"vcs": {"push_branches": [..], "remotes": [..], "protected_branches": [..], "allow_hooks": bool, "allow_filters": bool, "allow_repo_credential_helper": bool, "allow_any_repo_config": bool}` (`policy_layer::vcs`, a `vcs_policy_layer` of optionals; every key optional; an unknown key, a wrong type or an empty string is an error of the layer, which then fails closed like any other). `agent_policy::effective_vcs()` (main thread, re-reads changed files) gives a `vcs_policy`: `push_branches` = the project's list, else `{"agent/*"}`; `remotes` = the project's, else `{"origin"}`; a personal list only narrows either (a project entry stays only if the personal list names it too; the pattern strings are compared, not what they match: a personal `agent/me/*` drops a project `agent/*` and leaves no push branch at all, which fails closed); `protected_branches` = `main`, `master` and both layers' entries; each flag = the project's value (default false) and not switched off by the personal layer. A personal layer that sets a flag to `true` is a parse error of that layer ("only the project policy can allow ..."; `parse_policy_layer(text, policy_layer_kind::personal)`); `false` there switches it off. A broken layer (either): no push branch, no remote, every flag off, main/master protected. `editor_system::init` sets `vcs_service::set_policy_file` to the project policy file and `vcs_service::set_policy_source` to `m_agent_access->policy().effective_vcs()` once `agent_access` exists (null-safe; without the agent server the defaults and `set_write_permissions` apply); the service asks it at the start of every guarded write, so an edit of a policy file applies to the next write. Hard rules (only for `caller.kind != ui`; checked before git writes anything, a refusal is a `done` job with `result.error.code = "denied"`): a guarded push branch or branch.create name follows git's ref name rules (no leading `-`, `/` or `.` component, no `..`, `@{`, `//`, `\`, space, control character, `~ ^ : ? * [`, no trailing `/` or `.`, no component ending in `.lock`, not `@`) or the call is `invalid_args` before any job; a push only to a branch matching `push_branches` (glob `vcs_glob_match`: `*` any run including `/`, `?` one character, case-sensitive) and matching none of `protected_branches` (same glob, without case: `Main` is protected); fetch, pull and push only to a remote in `remotes` (exact); with none named the job resolves the remote once, as git would (the current branch's `branch.<b>.remote`, else the only configured remote, else origin), checks that one (after the repository config check) and passes it to git by name, so neither git's defaults nor a checkout on the other io thread can change it; a guarded pull without a branch fetches the current branch's `branch.<b>.merge` by name, and with a remote named but no branch only when the current branch tracks that very remote (else `invalid_args` "name the branch to pull from <remote>") (a plain `refs/...` ref; detached HEAD or no upstream: `git_failed`, no guess). An agent must not change the policy that judges it: a guarded checkout or pull whose target commit changes the project's policy file (`vcs_service::set_policy_file`, the editor's `<project>/.snk/agent_policy.json`; default `<project root>/.snk/agent_policy.json`; its path in the repository comes from `rev-parse --show-toplevel --show-prefix` in its folder, so a project in a subfolder of the repository works) is `denied` before git runs (`diff-tree --quiet HEAD <target oid> -- <path>`: changed or any failure denies; without HEAD, a target whose tree has the file denies). An agent's push is `push --recurse-submodules=no --no-follow-tags [--set-upstream] --end-of-options <remote> refs/heads/<b>:refs/heads/<b>`: never tags, and push.default, `remote.*.push` and `branch.*.merge` cannot redirect it; a person's push is unchanged. Checkout is never forced. The four flags open: `allow_hooks` - the repository's hooks (`.git/hooks`, `core.hooksPath`, config-based `hook.*`) run on the agent's writes; `allow_filters` - clean/smudge/process drivers of `.gitattributes` run (LFS among them); `allow_repo_credential_helper` - a credential helper program from the repository's own config runs on fetch/pull/push; `allow_any_repo_config` - the allowlist of the repository's config keys is skipped (every override and the other rules stay). Commits: `start_*` take a `cmd::origin` (kind and session; overloads taking only `cmd::origin_kind` remain); a guarded commit loses every line of its message that reads as an `Agent-Session:` trailer (any case, spaces before the colon; a message left empty is `invalid_args`) and, when its session matches `^[0-9a-f-]{1,64}$`, gets `Agent-Session: <session>` as the last paragraph; a person's commit is never changed. Covered by `AnAgentsPush_OutsideThePolicysBranches_IsDeniedBeforeGitRuns`, `AnAgentsNetworkCall_ToARemoteOutsideThePolicy_IsDenied`, `AnAgentsPush_UsesAnExplicitRefspec_WhateverTheUpstreamSays`, `AGuardedBranchName_FollowsGitsRefNameRules`, `APolicySource_DecidesWhetherAnAgentsCommitRunsTheHook`, `AnAgentsCommit_CarriesItsSessionAsATrailer`, `AGuardedCheckout_ThatChangesTheAgentPolicyFile_IsDenied`, `AGuardedCheckout_ChecksThePolicyFileOfAProjectInASubfolder`, `AGuardedPull_ThatChangesTheAgentPolicyFile_IsDenied`, `AnOmittedRemote_IsResolvedOnce_AsGitWould_AndNamedToGit`, `AnAgentsPull_WithoutARemote_IsCheckedAgainstTheBranchsRemote`, `APersonalLayerThatAllowsAFlag_ClosesEveryAgentNetworkCall` and the `EdtAgentPolicyVcs` suite.

**Live mode** (#445, `game_build/edt_live_build.h`): `live_build` is a pure state machine over `live_build_deps` (`now`, `settings`, `make_request` = `make_live_build_request`, `start_build`/`is_building` = the `game_builder`, `stop_background` = `game_builder::stop_background`, `reload(module, done)` = `game_reloader::reload_quiet` asked for on the next UI frame like #435 (never inside `tick`: only there is the module swap safe), `is_loaded_current` = `core::project_module_host::is_current` (the running copy was made from the build/bin file as it is now: same file, size, write time), `modules` = the project's runtime modules, `reload_pending` = an implicit module reload waits for the UI stage) and the `problem_list`. Inputs: `set_enabled` (off stops a running live build through `stop_background`, never the person's, and a manual request waiting for it stays queued), `on_changes(span<source_change{path, relevant}>)` (ignored when off or without a relevant change), `tick()` every frame (requests the reloads, never in the job pump), `rebuild_now()` (no debounce), `reload_now()` -> `{requested|up_to_date|refused, message}` (no quiet period; the modules of the last successful live build, else `modules`; only those not `is_loaded_current`; none: `up_to_date` "up to date", no swap; refused when off, while a build runs or reloads wait). A change starts a build `k_debounce` (500 ms) after the last one; a change during a build restarts it (`cancel_on_restart`). The result comes through `build_request::on_finished(build_outcome{succeeded|failed|restarted, job, errors, warnings, modules, message})`, called by `game_builder` on the main thread in `finish` (not for `job.cancel`: `is_building` false with no outcome = cancelled -> `idle`; never judge a build by `job_finished`, a restarted one ends `done`). Success with no change since the start: `settling` until `now - last_change >= live_quiet_ms`, then each produced module that is not current is requested (none: `reloaded` "up to date") and the state stays `reloading` until all have reported; a reload not taken -> `reload_failed` plus Problems source `reload` (warning for refused, else error), cleared by the next successful reload. A late result (a change, build or newer request came after it) still updates Problems unless a newer round finished, but never moves the state; a change during `reloading` debounces into a build as in `settling`. A start refused with `busy` (the person's build) stays `pending`; other refusals -> `errors`, warned once per message. No live build starts in the tick in which any build was seen to end (that frame's UI stage may run #435's reload, which a running build would refuse) nor while `reload_pending`; `rebuild_now` then queues. The person's build preempts a live one (`build_request::preemptible`): its outcome `preempted` (also when the editor stops it: Reload, a define removal) keeps the changes dirty, `pending` "waiting for the running build", and live mode builds again after the manual build. A live restart that waited and was then refused comes as `failed` with `not_started`: `errors` with the reason, changes kept (one more start, refused the ordinary way, then it waits for the next change). `live_quiet_ms` is re-read from the settings while settling (at most every 200 ms), so a lower value takes effect at once. `on_manual_build_succeeded()` turns `errors` into `idle` "manual build succeeded" and clears the counts. States: off, idle, pending, building, errors, settling, reloading, reloaded, reload_failed; `status()` = `{state, errors, warnings, configuration, job, last_build_end, last_reload, message}`.

## Desc ↔ ECS Edit Loop

```
User edits in Inspector
  → inspector on_node_changed callback
  → scene_document::commit("Edit node") → scene_editor::serialize_and_push()
      → active_world_desc serialized to JSON
      → desc_system re-parses level desc
      → ecs_assembler re-assembles world registry
  → Viewport reflects changes next frame

Gizmo drag committed
  → on_transform_committed(node_id path, pos, rot, scale)   (path = scn::node_id_component of the entity)
  → scene_editor::resolve_node_path in active_world_desc → { owner, target }
  → target empty: update owner.position / rotation / scale
  → target non-empty (node inside a prefab instance): override_edit::write_transform → override_record on owner
  → scene_document::commit("Move entity")
```

The editor never finds nodes by name (names are display only): hierarchy, viewport and `scene_editor` pass `node_id`s / id paths. Inspector edits of a node inside a prefab instance go through `edt_override_edit.h` (records on the instance node; "Reset to base" drops them).

**ECS → Desc** (called before save): `scene_editor::sync_ecs_transforms_to_desc()` reads `local_transform` of entities with a `node_id_component`, resolves the path, and writes back to the (non-instanced) desc nodes.

## Multi-World

- `scene_document::world_descs` — vector, indexed by `active_world_idx`
- `scene_document::active_world_desc()` / `active_world_name()` — pointers, null when the level has no worlds (`active_world_idx = -1`, arrays empty; `world_controller::clear_active_world()`). Never index `world_descs[active_world_idx]` directly.
- Hierarchy panel shows a tab per world; switching calls `world_controller::switch_to_world(idx)` which saves editor camera, tears down old registry, rebuilds new one
- `scene_document::worlds_systems_list` — per-world list of system names (parallel to `world_descs`)

**Single source of truth for world order (critical invariant):** the three parallel
`scene_document` arrays (`world_descs` / `world_names` / `worlds_systems_list`) MUST be
built from the same ordered source — the desc-ordered world list. Do NOT build them by
iterating `scn::context_set::for_each`: it walks the contexts by **context id**, which fills
gaps left by removed worlds and so is not desc/insertion order, so with >=2 worlds the parallel arrays desync. Derive names and
per-world systems via `edt::derive_world_arrays` (`controller/edt_level_controller.h`), and
keep `populate_worlds_from_level` as the single build point on load. Covered by
`tests/edt_world_array_sync_tests.cpp`.

**Hot reload:** `scn::context_manager` drops/rebuilds only the `kind==level` contexts of the set `"level"`, so worlds created in the
editor but not yet saved survive. After every reload (world list or systems only) it calls `level_controller::resync_worlds_after_reload()`
(`merge_reloaded_worlds` + `derive_world_arrays`), which keeps the arrays aligned with the level. A reload
whose world desc fails to load is skipped entirely (current level kept, no callback).

## Prefab Node Format (critical)

```
prefab_desc::prefab_node {
  name, position, rotation(Euler deg), scale
  components: unordered_map<string, prefab_comp_node>
  children: vector<prefab_node>
}
prefab_comp_node { type_name, parent_desc, overrides(json::object) }
```

- `children` serialized as a JSON **array** of nodes `{ "__id", "name", "transform", "components", "children" }` (format v2; v1 keyed them by name and is migrated on load)
- `components` key = type_name (e.g. `"mesh_node_desc"`, `"bone_desc"`)
- `rotation` stores Euler degrees: `x=pitch, y=yaw, z=roll`; reconstructed via `yawPitchRoll(y,x,z)`

## Headless (#452)

`editor --headless --project <dir>`: no display, no GPU, no panels (CI step "Headless run (no display)" in `editor-smoke`; `tools/run_headless.sh` is the separate Xvfb path for screenshots).
- `--headless` sets `editor/headless`, `app/non_interactive`, `project/required` (no `--project` → exit 2, like any project error), `window/system=null` (`wnd::null_window_system`) and `render/backend=null`; `gui_init` picks `gui::null_imgui_backend` for a window without a GL surface.
- `main` scans argv for `--headless`/`--mcp-stdio` before `init_logger`: the console log goes to **stderr**, stdout stays empty for a protocol. `--help` still prints to stdout (to stderr with `--mcp-stdio`).
- The `ui` stage does not draw panels: it runs only the implicit callbacks (`editor_system::run_implicit_callbacks`) inside `gui_system::run_without_drawing` (a CPU-only ImGui frame). They must keep running: the startup level load, `next_frame` work (module reload), progress windows and dialogs live there and use ImGui.
- Dialogs never wait: `editor_system::init` gives `dialog_service` the auto answer `cancel_all` + `warn_headless`, so every dialog is dismissed in the frame it comes up, `draw()` never runs, and each logs WARN `dialog` "headless: '<title>' cancelled: nobody to answer" (unsaved prompt -> `cancel`, file/path pick -> nothing, `choose` -> nullopt, message -> dismissed, title "Error: <text>"). `dialog.answer` stays `not_for_agents`. A project held for its engine version never gets that far headless (`app/non_interactive` refuses it with exit 3 first); with `-s app/non_interactive false` the version prompt is auto-cancelled, and because `project/required` is set (`held_project::required`) a cancel or "Continue Without Project" is `held_project::decision::no_project`: the editor quits and exits 2, like a run without `--project` (`exit_code_for`; a run that does not require a project goes on without it as before).
- `unavailable_headless`: a command with `command_desc::needs_display` (`viewport.capture`, `capture.compare`) answers `cmd::codes::unavailable_headless` to every caller, before the schema check and the policy gate (`command_registry::set_headless`, turned on by `editor_system::init` in headless). `tools/list` keeps such a tool when the policy shows it but marks it: description + " (unavailable in headless mode)" and `_meta: {"snk/unavailableHeadless": true}` (`mcp::tool_info::unavailable_headless`, filled by `mcp_bridge_host` from `needs_display && registry.headless()`; no standard annotation); `snk://viewport/*` answer `unavailable_headless: ...`.
- The panels never run: nothing sizes the editor/game camera targets by a panel or binds input (hence `viewport.capture` and `capture.compare` are `unavailable_headless`).
- `capture.compare{reference, viewport?="game", fuzz?=4, max_diff_pct?=2, max_source_pixels?}` (category `read`, `needs_display`; `rnd_capture_commands.h`, registered by `render_init` with the base `resource_system`) -> `{match, diff_pixels, total_pixels, diff_pct, width, height, viewport, reference}`: the view's full-size capture against a `res://` .png/.jpg/.jpeg (no `.pct`); a pixel differs when R, G or B differs by more than `fuzz` % of 255 (`compare -metric AE -fuzz` of `tools/headless/check_smoke.sh`, per channel; `rnd::compare_rgb_of_rgba8`), alpha is ignored on both sides; `match` = `diff_pct <= max_diff_pct`. Only `res://` (no `project://` scheme exists), no absolute path, `..`, `.`, `\` or `:`, refused before the resource system (`invalid_args`). The reference is read as bytes (`require_sync<res::binary_resource>`: cache key tag+type, so no clash with a `picture_resource` of the same tag; handles are local to the call, nothing is kept) and checked before any decode: over 64 MiB (`capture_compare_max_reference_bytes`), not a PNG/JPEG by magic bytes, a side over 16384 (`capture_compare_max_reference_side`, PNG size read from the IHDR, else `stbi_info`) or more than `min(capture_service::max_pixels, max_source_pixels)` pixels → `invalid_args`; an unreadable header → `failed`; a load error → `failed` "the reference '<tag>' cannot be loaded" (the resolver detail, which may hold a disk path, is only logged). Then the view is captured (`max_source_pixels` bounds it), a different size is `size_mismatch` (both named) before decoding; the decode (`stb_image::Image::read_from_memory`) records the global stb flip it ran with (`Image::flipped()`) and the rows are turned top-first by it. Agent calls: `mcp_bridge_host` caps `max_source_pixels` at the `viewport.capture` agent ceiling (8 Mpx); nothing is scaled, a bigger view or reference is refused.
- `app/exit_after_frames N` (core, any host): the loop stops after N frames with exit code 0 — a smoke-test hook.
- A successful level load logs `level loaded: <tag>` (`Editor/LoadLevel`); `editor/exit_after_level_loaded` stops the loop right after it (exit 0). CI uses it with `app/exit_after_frames` as the cap, so a level that never loads fails the step.
- Nobody is asked: `agent_access::set_headless(true)` keeps the gate's `can_ask` false whatever `frame()`, the font or the routing say, so an `ask` is `denied` unless `--agent-policy` answers it.
- `--agent-policy <file>` (cfg `editor/agent_policy_file`, a path relative to the working directory; `agent_policy::set_preanswers_file`): a person's answers to `ask` given in advance, not a policy layer. It applies only in a headless editor (`agent_access::set_headless` -> `agent_policy::set_headless`; `editor_system` loads the file only then, with a window it logs one WARN "--agent-policy ignored: not headless"); with a window the whole file is ignored, also when nobody can be asked there (a font without Cyrillic, before the first frame): `ask` stays `denied` as before. Same format as `agent_policy.json` without a `"vcs"` section (any `"vcs"` key is an error of the file: git rules come from the two layers only). `apply_preanswers` (the only place it decides) runs on the two layers' result after the #483 approval (a pending loosening of the project file is held to the approved copy first, so the file never lifts above the approved level): `ask` -> `allow` by the command's own entry, or its category's for a command without `risk`; any entry stricter than the result tightens; a deny (a layer's, the defaults' or a risk's, `unset`/`not_for_agents`, live off) is never lifted. A missing or broken file, or one inside the project or inside the git worktree holding it (the nearest folder up from the project root with a `.git` entry; canonical paths; "the --agent-policy file must be outside the project"): ERROR at load and every agent request `denied`. Read once at startup (`set_preanswers_file(file, project_root)`): a change while running is ignored until a restart, with one WARN "changed while running: ignored until restart". Without an agent server the option only logs a WARN. Tests: `EdtAgentPolicyPreanswers`, `EdtAgentAccess/Headless_*`.
- Options are parsed without abbreviations (`allow_guessing` off): `--head` is an error, not `--headless`.
- `--mcp-stdio` (cfg `editor/mcp_stdio`): MCP over stdin/stdout, one line per message (`mcp::stdio_transport`, `Editor/code/mcp_server/mcp_stdio.cpp`). `main` calls `platform::take_stdout_for_protocol` (`plt_stdio.h`) before the logger: fd 1 goes to stderr, the saved fd (in the storage as `platform::protocol_stdout`) is written only by the transport, so never print to stdout. `agent_server` owns the bridge once and runs HTTP (`editor/agent_server`) and/or stdio; the JSON-RPC methods are `mcp::rpc_dispatcher` (`mcp_rpc.h`) for both. Lines go out through the transport's own writer thread (queue up to 64 MiB; input lines up to 4 MiB), so the main thread never waits for the client; a client that does not read (overflow) or closed stdout (write error) ends the session like EOF. Closing stdin: headless drops unsaved changes of every open document (WARN) and stops with 0; with a window only the session ends (`on_stdio_input_closed`, `core/edt_editor_quit.h`).
- `editor.quit{discard_unsaved?}` (category `editor_control`) exists only with stdio and headless (`editor_quit_available`) and only the stdio session may call it; dirty without `discard_unsaved` is `needs_input`. Listed to every MCP session under the owner's defaults (`editor_control`: allow); an HTTP session's call is `denied`.
- `app/headless_target_fps` (60, 0 = no limit): with `window/system=null` the loop sleeps until `frame_start + 1/fps` (`app::loop_service::set_frame_limit`, wired in `core_module`).

## Play Mode (#39, US-63-B)

`play_session` (`controller/edt_play_session.h`, owned by `editor_system`) is a session of `scene_document`, not a document: `stopped | playing | paused`, every change raises `editor_events::play_state_changed(play_state, play_reason)` (`user`, `agent`, `module_reloaded`, `stopped_for_reload`; names via `play_state_name`/`play_reason_name`).
- **start()** refuses (logged to `play`, `start_refusal()` says why) without a level with a world, when active or stopping, while a level load or an asset add is in flight (`play_session_options::start_blocker`, wired by `editor_system` to `m_loading_level` / `m_pending_desc_handle`; `poll_level_load` also stops Play before `finish_level_load`), or when a set `"play"` is left over (`ENGINE_VERIFY`, never reused). It snapshots the editor camera, active world, selection and the level's `active`/`extract`, builds the set `"play"` (`edt::k_play_set`) on the game layer with `set_options{ .hot_reload = false }`, mode Play, the session's seed and time scale, one `context_kind::play` context per world from **copies** of `world_descs` + `worlds_systems_list` (never the files; the copies live as long as the set; built under `context_set::current_scope`, so tasks the systems/spawners start belong to the set), hides the level (`set_active(false)`, `extract = false`), injects the editor camera into the play twin of the active world (an `active_world_changed` during Play moves it to the other twin), remounts `user://` to a fresh `<project>/.cache/play_profile` (`prj::project_context::play_profile_dir()`, deleted and recreated every start, `res::resource_system::remount`: every cached `user://` resource is signalled as changed, so nothing is served from the old roots; a handle held from before keeps its data; Stop mounts all the editor's roots back) and locks the document.
- **stop()** `destroy_set("play")`: the set cancels and waits for **its** tasks (`context_set::tasks()`: module tasks started while it was current, and their children; the level's tasks of the same layer go on) and drops their queued `then_main` continuations; `inp::input_router::forget_set("play")`, mounts the editor profile back, unlocks, reactivates the level and its `extract`, applies a level reload that came during Play (`context_manager::apply_pending_level_reload`: the level desc watch does not rebuild an inactive level), then brings back the active world, the editor camera and the selection (through `scene_hierarchy_panel::select_path`; a node that is gone is deselected). Play changes neither the document nor the files. State changes and is announced last; a `stop()` from a handler during Stop does nothing (`m_stopping`), `start()` is refused then. `camera_redirector` releases the `play` scope textures in its next frame.
- **pause/resume/step(n)/set_time_scale/set_seed** map to the play set (`step(0)` = 1). `before_module_swap`/`after_module_swap` are wired through `module_swap_gate::set_play_hooks`: a module reload stops Play while the old layer is alive and starts it again after the level is attached (`module_reloaded`; paused if it was paused); a plain module load/unload, a level load and New Level just stop it (reason `user`). `code.*` (files, not the scene) stays allowed during Play; with live mode on, a rebuild reloads the module through the same gate, so Play restarts with `module_reloaded`.
- **Edits are locked** while active (`scene_document::edits_locked()`, `document::edits_locked()`): `commit` logs and does nothing, `undo/redo/rollback_group` refuse, `edit.undo/redo` are disabled, `scene.*` and mutating `agent.session.*` return `busy` "stop play first" (any origin), `scene_editor` edits and `world_controller::create_world` refuse before touching a desc; the hierarchy (no create/rename/duplicate/delete/drag, selection and world tabs still work), the inspector (drawn disabled) and the viewport (no gizmo, no asset drop) show "Stop Play to edit"; adding an asset to the scene, importing a model and the auto-add after an export are refused with a message dialog ("Stop Play to import"). Saving stays allowed: it writes the document as edited (the hidden level's live transforms are those of before Start) and leaves the undo history as it is (`rebase_history` only rebuilds the diff index). Play only starts when no person's gesture is in progress (`person_is_editing`).
- **Views**: `edt::view_set(services)` / `view_registry(services, state)` (`edt_input_target.h`) = the set `"play"` while it exists, else `"level"`; the Scene viewport, the Game view, `viewport.capture` and `selection_service::entity()` read through them. `sync_ecs_transforms_to_desc` still reads only the level.
- **UI**: menu Play (`play.start` Play/Resume Ctrl+P, `yields_to_text_input`, `play.pause`, `play.step` (enabled only while paused), `play.stop`); `editor_system::draw_play_status` draws "Play: playing/paused" in the menu bar before the Live status, nothing while stopped.
- **Agent commands** (US-63-C #491, `controller/edt_play_commands.h`): the menu items are the commands (`register_play_commands`, wired by `editor_system::create_play_session` with `m_play` and `person_is_editing`), agent category `play` (default `allow`): `play.start` (paused: resumes, with no gesture check; a `start_refusal` is `failed` with its text; an agent's start from stopped during a person's gesture is `busy`), `play.pause`, `play.resume` (no menu item), `play.step{n?: 1..600}` (only while paused; while playing `failed` "pause first"), `play.stop`, `play.status` (read-only, no menu item). Each returns `{state: stopped|playing|paused, frame, worlds}`; `frame` = `context_set::frames_run()` of the set "play" (frames run in Play or Step since Start), `worlds` = its worlds (`play_session::frames_run/world_names`). An agent origin changes the state with `play_reason::agent`, any other with `user`. A person's menu item may be stricter than the command: `action_ui::enabled` (menu and shortcut only; Play greyed during a gesture, Step greyed while playing), so an agent gets the command's own refusal. `app.advance`/`app.resume`: `core_module` keeps its registrations as `app::frame_command_registrations` in the storage; the editor drops them and registers both again (`register_play_frame_commands` -> `app::register_frame_commands(..., frame_command_options{category, enabled})`, kept in `m_registrations`) with category `play`, enabled only while Play is active (playing or paused): outside Play `disabled`; every Stop (any path: it subscribes `play_state_changed`, `editor_system::m_play_hold_release`) calls `frame_control::release()`, since `app.resume` is disabled then. `frame` of `app.advance` is the application's frame counter, `frame` of `play.*` the play set's simulated frames. Pause, step, stop, resume and status have no gesture check. `tools/headless_mcp_smoke.py --play` drives start/step/status/stop over stdio in CI.
- Tests: `tests/edt_play_session_tests.cpp` (suite `edt_play_commands_tests`: the MCP scenario, `busy`, "pause first", `app.advance` outside Play; start/stop state, deferred level reload, pause/step, locks, module reload, layer tasks, `user://` profile, 10 cycles with in-cycle growth and return to baseline of sets, contexts, `attached_count`, channels, `live_resources`, router bindings/holds, redirector targets; 10 cycles over real null-backend frames for `ds::frame_allocator_usage()`).

## Game Mode (#294)

`editor --game[=res://<level>]` (cfg `editor/start_mode` = `editor` | `game`, default `editor`, anything else warns and is `editor`; `--game=<level>` sets `editor/game_level`, not `editor/startup_level`; `--game <level>` with a space takes the level too (boost takes the next token that is not an option as the implicit value's value); either form is checked at startup like any `editor/game_level`; `--set` wins). In game mode a set `editor/game_level` replaces the start level, but only as a `res://` tag with a portable path (`edt::game_level_problem`: `res::portable_path_problem`, no `\\`, no other scheme, no file path); anything else is an ERROR `editor` and **no** level is loaded at startup (it is never read as a file path, and no other level stands in). The config layer stores the value as written; the check is in `editor_system::init`, where `res` is a dependency (`cfg` does not depend on `res`). Once the start level has loaded (the `edt/load_level` implicit passes that load's own outcome to `editor_mode_controller::finish_startup(loaded, exiting)` through `poll_level_load(&loaded)`) the editor switches to game mode, which starts Play. No start level (nothing is loaded): WARN, editor mode, no loading screen; a failed load or one cancelled with Esc in its "Loading Level" modal: ERROR `editor`, editor mode; a refused start: WARN, editor mode; with `editor/exit_after_level_loaded` the loop is already stopping, so it stays in editor mode (INFO). With `--headless` the same switch happens (the mode reads `game`, Play runs), there is just no layout to draw.
- **Loading screen (#518)**: only when that load is scheduled, `editor_system::init` calls `editor_mode_controller::begin_startup(<the start level's res:// tag>)` (`startup_pending()`, `startup_level_label()`); `finish_startup` always clears it, whatever the outcome (each end of `poll_level_load`: loaded, error, Esc). `editor_layer::set_loading_screen(active, draw)` (active = `startup_pending()` and the `edt/load_level` implicit still registered, so the screen never outlives it): `edt::draw_layouts` (the layout pass of `on_update`) then draws `edt::draw_loading_screen(loading_screen_text(tag))` instead of either layout: one undecorated black `##loading_screen` window over the main viewport (`NoBringToFrontOnFocus`, so the implicit callbacks' modals stay over it) with "Loading res://<level>..." centred, no dockspace, no menu bar, no panels and **no shortcut** at all. The dockspace is not rendered (nor kept alive) during it, so its first `render()` afterwards still builds the default layout. Unset or false (no `--game`), `draw_layouts` makes the same ImGui calls as before. While pending, `file.open` and `file.new` answer `busy` "the start level is loading" to any caller (`file_menu_hooks::level_change_blocker`, wired by `editor_system`), so an agent cannot swap the level Play would start on. CI: "Smoke run (game mode)" in `editor-smoke` runs `--game=res://levels/smoke_level.desc` (`run_headless.sh --wait-for-log '\[editor\] game mode$'`), then checks `level loaded: .*smoke_level.desc`, `[editor] game mode` and no `[error]`/`[critical]` line.
- `editor_mode_controller` (`controller/edt_editor_mode.h`, no ImGui, owned by `editor_system`, `play_session&` injected): `mode()`, `set_mode(mode, play_reason)`, `toggle(reason)` -> nullopt or the refusal; raises `editor_events::editor_mode_changed(editor_mode)`. To the editor: a `playing` Play is paused and the controller notes that it paused it. To the game: a stopped Play is started (a `start_refusal` keeps the editor mode), a paused one is resumed only when the note is set (a pause someone else made stays). Every change of Play the controller did not make that is not a pause (any Stop: person, agent, module reload; a resume) drops the note; a Step keeps it; a resume that fails keeps it (WARN). Owner decision: with a UI (`has_ui`, false when the registry is headless) any Stop in game mode (person, agent, level load; not the stop and restart of a module reload, `stopped_for_reload`/`module_reloaded`) switches back to editor mode and raises `editor_mode_changed`; a module reload keeps game mode, but if `play_session::after_module_swap` cannot start Play again (a start blocker, the level gone), `editor_mode_controller::after_module_swap()` (called next by the swap gate's hook) logs WARN and switches to editor mode. `play_command_for(mode)` names the play.* command whose change a switch would make (`play.start`, `play.resume`, `play.pause`, or none).
- Layout: `editor_layer::set_game_layout(active, draw, shortcuts)`; in game mode `on_update` calls `dockspace::keep_alive()` (`DockSpace(id, {}, ImGuiDockNodeFlags_KeepAliveOnly)` with the id `render()` last used, so docked windows stay docked) and draws `game_view_panel::render_fullscreen()` (one undecorated `##game_mode_view` window over the main viewport, black, only the letterboxed image of the picked camera; shares camera pick, viewport sizing and letterbox with `on_render`) instead of `dockspace::render`, so no menu bar, no panels. The docked panel's open state is not touched (its `on_hidden` does not run in game mode). `render_target()` stays set, so `viewport.capture{viewport:"game"}` works in game mode. The Scene view's editor camera gets a zero viewport every game-mode frame (`viewport_panel::suspend_camera`; the extractor skips it, `rnd::effective_camera_viewport`), and its size back on `editor_mode_changed(editor)` (`resume_camera`). Input: after the frame's implicit callbacks (`editor_layer` calls `set_game_layout`'s `after_implicit` = `game_view_panel::bind_fullscreen_input()`, so a popup an implicit callback opens in the same frame counts) `bind_game_window_input` (`input/edt_input_binding.h`) binds the whole viewport rect to `active_play_input_target` every frame, hovered or not, unless `game_input_allowed(popup_open, dialog_open)` says no: any ImGui popup or modal (`IsPopupOpen(nullptr, AnyPopupId | AnyPopupLevel)`), a `dialog_service` request pending, or an agent question waiting (`agent_confirmations::pending()`, an ordinary window). Implicit callbacks (dialogs, progress windows) still draw over it.
- **Shortcut pass**: `fire_shortcuts(actions, allowed)` (`panels/edt_main_menu.h`) runs once per UI frame at the start of `editor_layer::on_update`, before either layout (it used to run inside the menu bar, which game mode has not). At most one action per frame; `yields_to_text_input` actions do not fire while `io.WantTextInput`. In game mode `allowed` = `edt::is_game_mode_shortcut` (`editor.mode.toggle`, `play.start/pause/step/stop`; `action_registry::dispatch(chord, text_input, allowed)`): every other key belongs to the game. Without `--game` the editor frame is drawn as before.
- `editor.mode.toggle{mode?: "editor"|"game"}` -> `{mode, play_state}` (`controller/edt_editor_mode_commands.h`): F11 (`yields_to_text_input`), View > Game Mode (checked in game mode), agent category `play`, `mutates`, `needs_display` (`unavailable_headless`). Absent `mode` toggles; the current mode is a no-op. **Policy**: an agent's switch (origin `agent`) asks `editor_mode_commands_deps::agent_mode_of` (wired to `agent_policy::effective` of that play.* command) and about `editor.mode.toggle` itself first: a play.* mode **stricter** than the toggle's own (deny > ask > allow) is `denied` before anything changes (`ask`: "<id> needs a person's approval; call it directly"), so the toggle opens nothing the play.* commands keep closed (nor `app.advance`, which needs Play); an `ask` both share was already put to the person for this very call, so an approved toggle runs; the person's hotkey and menu are not judged. A refused start is `failed` with its text; an agent's switch that would start Play during a person's gesture is `busy` (as `play.start`). Agent origin -> `play_reason::agent`, else `user`. Tests: `edt_editor_mode_tests` (incl. `begin_startup`/`finish_startup`), `edt_editor_mode_commands_tests` (`tests/edt_play_session_tests.cpp`), `EdtShortcutPassTests`, `EdtGameModeUiTests` (dock layout across game frames, input under a popup, `game_level_problem`, the loading screen through `draw_layouts`), `Cli_Game*`.

## Common Pitfalls

- **EnTT `registry::each()` does not exist** — use `registry.storage<entt::entity>()` to iterate all entities
- **EnTT forward declare** — use `#include <entt/fwd.hpp>`, not `namespace entt { class registry; }`
- **Input routing**: ECS input is routed by `inp::input_router`; a panel binds its hovered image every frame (`bind_item_input`), the context under the cursor gets the full `inp::input_state`, all others a neutral one. Never set `inp::input_focus` by hand
- **Edits go through `scene_document::commit()`**, which calls `serialize_and_push()` - destructive — tears down and rebuilds the entire ECS world; don't hold raw pointers to registry components across it
- **Camera state**: `scene_editor::on_save_camera` runs before the push and `on_inject_camera` after (state in `scene_document::camera`) — otherwise camera resets
- **Memory resources**: `memory://` protocol stores resources at runtime; `res://` resolves from filesystem via `resource.path`
- **`get_field_desc<T>` with inline objects** requires `__type` field present in the JSON object
- **`children` is a JSON array of named nodes (v2)** — iterate via `as_array()`; a v1 object is only valid before `migrate_tree`
- **No C functions** — prefer `std::format_to_n` over `snprintf`/`strncpy`, C++ alternatives over C stdlib
